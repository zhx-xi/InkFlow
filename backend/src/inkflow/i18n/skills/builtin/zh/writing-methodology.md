# 写作方法论

## 目标

本 skill 用于按既定大纲撰写章节正文，将规划落地为可读的小说文本，要求
场景切换自然、对话符合人设、视角保持一致，并在完成后保存草稿。适用于
大纲已确认、需要产出正文初稿的场景。

## 方法步骤

1. **读大纲**：先读本章章纲（目标 / 场景清单 / 关键事件 / 伏笔操作），
   再获取前文摘要保持衔接。大纲未确认时先回到架构方法论，不要边写边改结构。
2. **建设定卡**：动笔前把本章出场角色与涉及的世界观条目读出来，
   把关键约束抄成一张临时对照卡（称呼 / 能力上限 / 禁忌 / 已确立事实）。
3. **按场景推进**：每个场景一段推进，场景切换用过渡句自然衔接，避免跳切生硬。
4. **对话查档案**：对照角色档案确认语气、称呼与禁忌符合人设，全程保持统一视角
   （人称、限知范围不跳变）。
5. **写时查证不猜**：遇到设定细节先查设定库；查不到就留白或写待确认标记，
   不得凭印象编造——凭空补设定是设定漂移的最大来源。
6. **收尾自检**：对照大纲逐条确认关键事件落地、伏笔操作执行、
   时间线与前章连续，然后保存草稿。

## 边界

- 不擅自改变大纲结构：情节走向、关键事件与结局须遵循规划，需要调整先回到大纲规划。
- 不引入与既有设定矛盾的信息：拿不准就留白，宁可欠一笔不可错一笔。
- 不明确年份与时间锚点：时间以相对表述（三日后、同年秋）推进，
  避免绝对年份造成的时序穿帮与后续不可改。
- 不在草稿中插入审查性评论：审校、修订与润色由后续方法论负责。

## 示例

撰写「第 12 章」：读章纲确认三场景；建设定卡记录主角当前称呼、
能力上限（不能正面冲突）、世界观禁忌（不可在旧宅点火）；
按「旧宅搜查 → 信件发现 → 对峙」推进，对峙段用智取而非硬拼以符合能力上限；
埋伏笔「账册缺页」时只留线索不解释；写完保存草稿并回执关键事件落地情况。

## 交付前自检

草稿保存前逐条确认：

- [ ] 大纲落地：章纲的关键事件逐条在正文中有对应段落，无漏写
- [ ] 伏笔执行：本章应收的伏笔已回收，应收的线索已埋且未提前解释
- [ ] 人设一致：每位出场角色的称呼、语气、能力表现均与档案相符
- [ ] 视角稳定：全章人称与限知范围统一，无越界叙述
- [ ] 设定无编造：所有设定细节均来自设定库，无凭印象新增
- [ ] 时序连续：与前章的时间推进关系明确，全章未出现绝对年份
- [ ] 无审查性文字：正文中不含点评、元叙述、待办标记

## 对话写作要点

对话是人设最容易露馅的地方，逐条对照：

| 检查点 | 常见问题 | 修正方向 |
|--------|----------|----------|
| 称呼 | 不同场景下称呼跳变 | 按关系与场合选定，全章统一 |
| 信息量 | 人物说出彼此都知道的事 | 只保留推动剧情的新信息 |
| 语气 | 所有角色同一套腔调 | 按身份、教养、情绪区分措辞 |
| 潜台词 | 把意图直接说破 | 留白，让行动与回避承担表达 |
| 说话人 | 长对话中指向不明 | 交替处补动作或称呼锚定 |

对话不宜承担设定讲解：确需交代设定时，让角色因剧情需要而说，
而非为读者而说——「为读者而说」的对白一律改写或移入叙述。

## 与其他方法论的衔接

写作是「规划 → 文本」的唯一落地环节，输入必须已确认：

| 输入 / 输出 | 来源 / 去向 | 说明 |
|------------|------------|------|
| 章纲（目标 / 场景 / 事件 / 伏笔） | 来自 architecture-methodology | 未确认则不写 |
| 前文摘要 | 项目数据 | 保持衔接与文风连续 |
| 角色档案 + 世界观条目 | 项目数据 | 建设定卡的来源 |
| 草稿 | 交给 audit-methodology | 审计通过后才进入修订 |

本 skill 只负责把规划变成可读文本，不负责判断规划对不对（上游）
也不负责判断文本好不好（下游）。任一环节越位，责任边界即失效。
