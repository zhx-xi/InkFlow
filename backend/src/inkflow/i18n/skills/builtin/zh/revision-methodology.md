# 修订方法论

## 目标

本 skill 用于在保留原意的前提下修订打磨章节草稿，依据审校 findings 或用户
意见修改文本，控制改动幅度，修订后统计字数并保存草稿供用户确认。适用于
草稿已有明确问题、需要修改落地的场景。

## 方法步骤

1. **读清单定范围**：先获取前文摘要，再对照审校 findings 或用户要求，
   列出本次要处理的问题项与优先级，明确哪些段落本轮不动。
2. **先查设定再改字**：涉及角色或世界观的修订，先读对应档案确认正确表述，
   再落笔——禁止凭正文反推设定，那会把漂移固化进档案之外。
3. **逐条处理**：修正设定矛盾、补齐遗漏伏笔、理顺逻辑与衔接，保留作者原意。
4. **控幅单点改**：只改问题点对应的句子与段落，不重排场景结构，
   不顺手润色无关段落（文笔层面留给润色方法论）。
5. **改后复查**：统计新字数，并回查改动是否引入新的设定矛盾或时序断裂，
   必要时再走一次审计。
6. **存草稿 + 变更清单**：保存草稿并向用户说明每处改动对应的 finding。

## 边界

- 不超出指定范围：没有对应 finding 或用户要求的段落不主动大改，尤其不动情节走向。
- 不替审校下结论：findings 的判定由审计方法论负责，修订只按结论执行。
- 不越权改设定：发现设定本身有问题时报告给用户，
  不得通过改正文来「绕过」设定错误。
- 不一次改多项无关内容：改动范围越大越难回归验证，宁可分轮。

## 示例

按审校 findings 修订「第 12 章」：4 条 finding 全部纳入；先读角色档案确认
正确称呼与能力上限，修正称呼、把越权能力改为档案内的替代手段；补写缺失的
信物伏笔细节；时间线按上游第 10 章口径统一为「三日后」。其余段落保持原样；
完成后统计字数、复查无新矛盾，保存草稿并回复改动清单。

## 交付前自检

保存草稿前逐条确认：

- [ ] 逐条闭环：每条 finding 都有对应的修改，未处理的说明原因
- [ ] 改动克制：只改问题点所在句子或段落，无关段落零改动
- [ ] 设定有据：所有设定相关改动都查过档案，未凭正文反推
- [ ] 情节未动：事件结果、角色决策、场景顺序与原文一致
- [ ] 无新矛盾：改动后复查未引入新的设定冲突或时序断裂
- [ ] 字数已统计：向用户报告修订前后字数变化
- [ ] 变更清单可核对：每处改动列出「改前 → 改后 → 对应 finding」

## 常见误改

| 误改 | 后果 | 正确做法 |
|------|------|----------|
| 改成另一个未记载的能力 | 漂移依旧存在 | 改为档案内确有依据的手段 |
| 顺手重写无关段落 | 无法回归验证，且掩盖真实问题 | 只改 finding 指向处 |
| 按正文口径统一时间线 | 与上游时间轴脱节 | 以上游时间轴为准 |
| 把设定冲突通过改正文「绕过」 | 设定错误被永久掩盖 | 报给用户，等设定裁定 |

修订的风险不在于改得少，而在于改出新的不一致——
因此本 skill 把「复查」列为必经步骤，而非可选项。

## 改动幅度口径

| 问题类型 | 允许的改动幅度 | 不得触碰 |
|----------|---------------|----------|
| 称呼 / 术语不一致 | 仅替换该词及其指代 | 句子结构与情节 |
| 设定漂移（能力越界） | 改写该动作的实现方式 | 事件结果与胜负 |
| 伏笔漏收 | 增补线索段落 | 后续章节已写的走向 |
| 时序矛盾 | 统一时间表述 | 事件发生顺序 |
| 逻辑断裂 | 补过渡句或补一句因果 | 场景划分 |

改写幅度自我约束：单章改动段落数不超过 finding 数量。
若某条 finding 需要的改动超出上表口径，说明它不是修订问题，
而是结构或设定问题——应停下报告，而不是在正文里绕过去。
