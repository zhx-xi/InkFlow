# 架构方法论

## 目标

本 skill 用于在撰写正文之前规划章节结构与大纲，确保目标章节在全书弧线中
的位置清晰、起承转合完整，并与既有伏笔、角色设定和世界观设定保持一致。
适用于新建章节规划、章节拆分合并以及大纲调整场景。

## 方法步骤

1. **定位层级**：先判断本次规划对象是整本根 / 卷纲 / 章纲 / 情节点中的
   哪一层，再决定颗粒度。总纲缺位时先补最小可用骨架，不要跳过上游直接写章纲。
2. **确认位置**：读取前文摘要，判断本章处于全书弧线的开端、发展、高潮还是
   收束阶段，据此决定本章节奏与篇幅，避免出现连续三个同强度章节。
3. **核对伏笔账**：逐条检查既有伏笔的埋设章与计划回收章，确认本章是否有
   应收未收的伏笔；新埋的伏笔必须写明「计划在第几章回收」与「回收线索物」。
4. **核对设定边界**：本章新情节是否越出角色能力上限或世界观规则；
   与既有档案冲突时改规划而不是改设定（设定改动须回到设定流程）。
5. **校对时间线**：确认本章在项目时间轴上的位置与前章连续，
   跨场景时间跳跃须在规划里写明跨度，防止后文时序穿帮。
6. **规划章节骨架**：按起承转合组织，明确冲突推进与情绪转折，
   确定悬念埋设与伏笔回收计划，保证章节节奏张弛有度。
7. **输出结构化规划**：章节目标 / 场景清单 / 关键事件 / 伏笔操作 / 衔接要点。

## 边界

- 不直接撰写正文：本 skill 只产出章节规划，正文由写作方法论负责。
- 不落库：架构师只有大纲只读权限，规划以文本形式交付，落库由用户确认后执行。
- 不擅自新增角色或世界观设定：超出既有档案的内容标注为待确认项，交由用户决策。
- 避免规划过度具体：场景描写与对话台词留给正文阶段，此处只锁定结构、冲突与伏笔走向。
- 不制造「空转折」：每一处转折必须写明由什么事件触发、改变谁的处境，
  只写「气氛突变」而不给因果的规划视为未完成。

## 示例

规划「第 12 章」：先确认层级=章纲、本章位于发展段转折点；读取前文摘要与
时间轴确认紧接第 11 章当夜；核对伏笔账发现第 3 章埋设的信物计划在第 12 章
回收；核对角色设定确认主角当前能力上限不支持正面冲突，故规划为智取。
输出——章目标：回收信物伏笔并引出下一冲突；场景清单：旧宅搜查 → 信件发现
→ 对峙；伏笔操作：回收信物、新埋「账册缺页」；衔接：章末留下账册缺页线索。

## 交付前自检

规划交付前逐条确认，任一条不满足则补完再交：

- [ ] 层级明确：本次产出挂在哪一层（整本根 / 卷纲 / 章纲 / 情节点），父级是谁
- [ ] 位置明确：本章在全书弧线的哪个阶段，上一章与下一章的衔接点各是什么
- [ ] 因果闭合：每个关键事件都由前一事件触发，每处转折都写明触发者与被改变者
- [ ] 伏笔两清：本章要埋的（含计划回收章 + 线索物）与要收的（含埋设章）均已列出
- [ ] 设定无越界：新情节未越过角色能力上限与世界观规则，冲突项已标为待确认
- [ ] 时序连续：本章在项目时间轴上的位置明确，跨场景跳跃已写明跨度
- [ ] 无空转折：不存在只写「气氛突变」而无因果的段落

## 与其他方法论的衔接

| 阶段 | 负责 skill | 交接物 |
|------|-----------|--------|
| 结构规划（本 skill） | architecture-methodology | 章纲（目标/场景/事件/伏笔） |
| 正文落地 | writing-methodology | 按章纲产出草稿 |
| 质量把关 | audit-methodology | findings 清单 |
| 设定把关 | worldview-methodology | 世界观冲突建议 |
| 问题落地 | revision-methodology | 修订稿 |
| 文笔收尾 | polishing-methodology | 润色稿 |

本 skill 位于链路最上游：章纲未确认时，下游全部环节的结果都不可靠，
因此宁可多花时间在规划阶段，也不要带着结构问题进入写作。
