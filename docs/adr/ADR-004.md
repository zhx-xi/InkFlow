# ADR-004: Pydantic v2 作为统一数据契约

> **状态**: 已接受
> **日期**: 2026-07-30
> **来源**: docs/architecture-analysis-2026-07-30.md §三 ADR-004
> **依据**: Constitution 技术约束（数据验证：Pydantic v2）

## 背景

FastAPI 和 Typer 都原生使用 Pydantic；PRD 要求数据验证与类型安全。三种界面需要一份模型定义同时驱动校验、序列化和文档。

## 决策

Pydantic v2 模型贯穿全栈：
- **Domain Models**: 业务实体、值对象（Pydantic `BaseModel`）
- **Request/Response DTOs**: API 输入输出（FastAPI 自动校验/序列化）
- **CLI 参数**: Typer 自动从 Pydantic 字段生成 help/validation
- **配置**: `pydantic-settings` 管理环境配置

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| Pydantic v2（选定） | 一份模型三界面复用、Rust 内核高性能 | ORM 与 Pydantic 模型存在映射代码 |
| dataclasses | 零依赖 | 无校验、无序列化、无 OpenAPI 集成 |
| attrs | 灵活 | 生态集成不如 Pydantic |

## 影响

- ✅ 一份模型定义，三界面自动生成校验/文档/序列化
- ✅ Pydantic v2 性能大幅提升（Rust 内核）
- ❗ SQLAlchemy ORM 与 Pydantic 模型之间存在映射代码
