# ADR-009: 依赖注入策略

> **状态**: ✅ 已接受（不变）
> **日期**: 2026-07-30
> **来源**: docs/architecture-analysis-2026-07-30.md §三 ADR-009

## 背景

三界面（CLI / REST / MCP）共享 Service 层，需要统一的依赖组装方式，且测试需要注入 Mock 实现。

## 决策

采用轻量手动依赖注入（无 DI 框架）：`api/deps.py` 作为 FastAPI 的依赖中间层，将 Service 注入 Router；CLI 命令直接构造 Service（携带 Repository 实现）。所有依赖通过构造函数传入。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| 手动 DI（选定） | 零依赖、显式、测试友好 | 少量样板代码 |
| DI 框架（dependency-injector 等） | 自动装配 | 额外依赖、魔法过多、调试困难 |
| ServiceLocator 单例 | 调用简单 | 隐式依赖、测试污染 |

## 影响

- ✅ 测试可注入 MockRepository / MockLLMClient，无需真实依赖
- ✅ 依赖关系显式可见，新人易上手
- ❗ 新 Service 需要手动接线（单人项目成本可忽略）
