# ADR-001: 模块化单体 + 严格接口隔离

> **状态**: 已接受
> **日期**: 2026-07-30
> **来源**: docs/architecture-analysis-2026-07-30.md §一、§三 ADR-001
> **依据**: Constitution P6（模块化单体，接口隔离）

## 背景

单人开发，24 周时间线。PRD 要求三个界面（CLI / REST / MCP）共享同一业务逻辑，且为云端迁移预留接口。微服务的运维负担与单人开发不匹配（Conway 定律：架构复制沟通结构）。

## 决策

采用模块化单体（Modular Monolith），模块之间通过 `typing.Protocol`（Python 结构化子类型）定义接口边界，基础设施实现可替换。当某个模块需要独立扩展时（如 Phase 4 的 Auth），从模块演进为独立服务。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| 模块化单体（选定） | 开发效率高、单进程调试、数据库事务简单、可逐步拆分 | 单进程故障影响全局 |
| 微服务 | 独立部署、故障隔离 | 单人运维 3+ 服务不可行 |
| 纯单体（无模块边界） | 最快起步 | 无法演进，后期重构风险高 |

## 影响

- ✅ Service 层可实现 CLI/REST/MCP 三界面复用
- ✅ Protocol 定义清晰，云端迁移有据可依
- ❗ 需建立架构适应度函数，防止模块间循环依赖
- ❗ 需纪律性维护模块边界
