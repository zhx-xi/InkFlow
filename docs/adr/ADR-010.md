# ADR-010: 上下文管理 — 分层 Token 预算 → RAG 增强

> **状态**: ✅ 已接受（Phase 1 用 Token 预算，Phase 2 引入 RAG）
> **日期**: 2026-07-30（v2.0 更新：2026-07-31）
> **来源**: docs/architecture-analysis-2026-07-30.md §三 ADR-010

## 背景

长篇小说的上下文管理不能只靠 Token 预算——写第 50 章时需要第 3 章埋的伏笔，但早已被挤出上下文窗口。角色一致性、世界设定连贯性需要更精确的检索。

## 决策

**Phase 1**: 分层 Token 预算模型（Layered Token Budget）——按优先级（角色 > 世界设定 > 前文摘要 > 大纲）分配上下文窗口，超出部分摘要压缩（"Compressible" 层）。

**Phase 2**: 用 RAG 增强（[ADR-013](ADR-013.md)）替换"Compressible"层的摘要注入，实现精确语义检索。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| Token 预算 + RAG（选定） | Phase 1 快速可用，Phase 2 渐进增强 | 两阶段实现成本 |
| 纯 Token 预算 | 实现最快 | 长篇小说一致性无法保证 |
| 直接上 RAG | 一步到位 | Phase 1 复杂度超标，依赖 Embedding 模型 |

## 影响

- ✅ Phase 1 保证基础可用，不受 RAG 依赖阻塞
- ✅ Phase 2 语义检索精确（ADR-013）
- ❗ 预算分配策略需随使用反馈调参
