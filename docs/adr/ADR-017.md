# ADR-017：CI 代码质量检查 — Reviewdog + Ruff 统一门禁

> **状态**：✅ 已接受
> **日期**：2026-07-31
> **来源**：CI 体验改进 — 替代独立 `ruff check` 步骤，增加 PR 内联注解
> **依据**：Constitution §7.3（CI 门禁：lint → type check → test → build，全部通过方可合并）

## 背景

CI 当前独立运行 `ruff check src/ tests/`，仅有 pass/fail 输出，lint 问题需点进 CI log 才能看到具体位置。引入 Reviewdog 的动机是：

1. **反馈速度**：lint 问题直接标注在 PR diff 行上，无需跳转 CI log
2. **前后端统一**：未来 React/TypeScript 前端就绪后，用同一套 Reviewdog 框架覆盖 ESLint
3. **一次执行、双重用途**：避免 Reviewdog 和独立 `ruff check` 重复 lint 同一段代码

项目中 `backend/pyproject.toml` 已配置 Ruff（规则 E, F, I, N, W, UP），`.pre-commit-config.yaml` 含 Ruff + ruff-format hooks。flake8 被明确排除——Ruff 完全覆盖其规则集。

## 决策

**用 `reviewdog/action-setup@v1` 安装 reviewdog 二进制，ruff 以 `--output-format=concise` 输出单行格式，通过 `-efm` errorformat 解析后送入 reviewdog**，作为唯一的 Ruff 执行入口：

```yaml
- uses: reviewdog/action-setup@v1

- name: Lint + annotate (Ruff → Reviewdog)
  shell: pwsh
  env:
    REVIEWDOG_GITHUB_API_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  run: |
    $ruffOutput = ruff check src/ tests/ --output-format=concise
    $ruffExit = $LASTEXITCODE
    if ($ruffOutput) {
      $ruffOutput -replace '^(src/|tests/)', 'backend/$1' | reviewdog -efm='%f:%l:%c: %m' -reporter=github-pr-review -level=warning -name=ruff -tee
    }
    if ($ruffExit -ne 0) { exit $ruffExit }
```

**为什么是 errorformat 而非命名格式**：reviewdog 没有内置 `-f=ruff` 解析器（CI 实测报 `"ruff" is not supported`）；ruff 的 `--output-format=rdjson` 是包裹式 JSON 也无法直接使用。`-efm='%f:%l:%c: %m'` 是 Vim errorformat 标准语法，直接解析 ruff `--output-format=concise` 的 `file:line:col: rest` 格式。

**关键原则**：

1. **一次执行**：`ruff check` 只跑一次，输出捕获到变量 → pipe 给 reviewdog 发注解 → 用原始退出码决定 CI pass/fail
2. **`reporter: github-pr-review`**（而非 `github-pr-check`）：PR diff 行上直接显示 review 评论，反馈最直观；需要 `pull-requests: write` 权限
3. **退出码保留**：`$ruffExit` 捕获 ruff 原始退出码，确保 lint 失败能中断 CI（reviewdog 本身不控制门禁）
4. **前端扩展路径**：未来前端就绪后，按同样模式（`action-setup` + ESLint → reviewdog 管道）添加 step

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A: Reviewdog + flake8**（原始提案） | flake8 生态成熟 | flake8 完全被 Ruff 覆盖，零增量价值；引入冗余工具；性能比 Ruff 慢 10-100 倍 |
| **B: reviewdog/action-setup + ruff 管道**（选定） | 一次 lint、PR 注解、前端可扩展、官方 action | 多一个 Action 依赖；管道脚本比单行 run 稍长 |
| **C: ruff → JSON → pipe reviewdog** | 完全控制执行细节 | CI YAML 偏重（3 个 step），JSON 管道脆弱 |
| **D: ruff `--output-format=github`** | 零新工具、一行改动、即时可用 | 仅 GitHub 原生注解（非 PR 行内评论）；前端 ESLint 需另建注解方案 |
| **E: MegaLinter** | 全栈一体化、50+ linter | Docker ~2GB，重量级；与 Windows runner 不适配；单人项目过度设计 |
| **F: pre-commit.ci** | 零 CI 配置 | 第三方依赖；仅运行 pre-commit hooks，灵活度低 |

## 影响

- ✅ PR diff 上直接看到 lint 问题，反馈路径从"点 CI log"缩短为"看 PR Files Changed 标签"
- ✅ 一次 Ruff 执行，既发注解又做门禁——零冗余
- ✅ 前端就绪后加一个 `action-eslint` step 即可，前后端统一体验
- ❗ 引入 `reviewdog/action-setup@v1` 作为新 CI 依赖，版本通过 `@v1` 锁定大版本
- ❗ 使用 `-efm='%f:%l:%c: %m'` errorformat 解析 ruff `--output-format=concise` 输出——reviewdog 无内置 ruff 解析器
- ❗ PowerShell 管道中 `$LASTEXITCODE` 捕获是正确门禁的关键——不能依赖 reviewdog 的 `-fail-on-error`
- ❗ 当前仅覆盖后端（Python）；前端 CI 检查在前端代码库就绪后单独补充

### 2026-07-31 更新：拆分为独立 Job

将单一 `test` job 拆分为 `lint` / `test` / `build` 三个独立 job：
- **lint** — ruff check + reviewdog 注解 + mypy 类型检查
- **test** — pytest + coverage（与 lint 并行运行）
- **build** — wheel 构建（`needs: [lint, test]`，仅两者均绿才执行）

每个 job 可作为 required status check 独立勾选，失败定位无需点进 CI log。
