# ADR-003: Repository 模式封装 SQLAlchemy

> **状态**: 已接受
> **日期**: 2026-07-30
> **来源**: docs/architecture-analysis-2026-07-30.md §三 ADR-003
> **依据**: Constitution P3（TDD）、P4（依赖方向单向）

## 背景

SQLAlchemy 2.0 async + SQLite 作为本地持久化方案。PRD 要求测试覆盖率 ≥ 70%，数据库层需可 mock——测试不能依赖真实数据库。

## 决策

使用 Repository 模式封装 SQLAlchemy Session，Repository 实现 `ProjectRepositoryProtocol` 接口：

```
Service → ProjectRepositoryProtocol (Port) ← SQLAlchemyRepository (Adapter)
```

设计原则：
1. Repository 接收和返回领域模型（Pydantic models），而非 ORM 模型
2. SQLAlchemy ORM 模型作为 Repository 内部实现细节，不泄漏到 Service 层
3. CRUD + 自定义查询方法以 Protocol 定义类型签名

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| Repository 模式（选定） | 测试可注入 Mock、Domain 零 SQLAlchemy 依赖 | 简单 CRUD 场景多一层抽象 |
| Service 直接操作 Session | 代码少 | 测试需要真实数据库，Domain 依赖 ORM |
| ORM 模型直接当领域模型 | 最简 | 领域层被框架绑架，云端迁移困难 |

## 影响

- ✅ 测试时可注入 MockRepository，不依赖真实数据库
- ✅ Domain 层不依赖 SQLAlchemy，降低耦合
- ❗ ORM ↔ Domain Model 转换有性能开销（但 SQLite 场景可忽略）
- ❗ 对简单 CRUD 场景，多了一层抽象
