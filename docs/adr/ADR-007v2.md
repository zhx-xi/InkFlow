# ADR-007v2: 项目包结构（infrastructure 按技术分目录）

> **状态**: ✅ 已接受
> **日期**: 2026-07-31（v2.0 更新）
> **来源**: docs/architecture-analysis-2026-07-30.md §三 ADR-007v2

## 背景

v2.0 引入 LangChain 全家桶后，infrastructure 层需要承载 LLM、Agent 编排、RAG、Prompt 四类技术实现。原按业务模块平铺的结构无法表达技术边界。

## 决策

infrastructure 层新增 `llm/`、`agent/`、`rag/` 目录，domain/ports 新增 4 个 Protocol：

```
backend/src/inkflow/
├── api/                            # FastAPI 路由（Presentation）
├── cli/                            # Typer CLI（Presentation）
├── mcp/                            # MCP Server（Phase 3）
├── domain/                         # Domain 层（零框架依赖）
│   ├── models/                     # Pydantic 领域模型
│   ├── services/                   # 业务服务
│   ├── ports/                      # 出站接口（Protocol 定义）
│   │   ├── project_repository.py   # F1 (已实现)
│   │   ├── llm_client.py           # ADR-005v2
│   │   ├── agent_pipeline.py       # ADR-006v2
│   │   ├── vector_store.py         # ADR-013
│   │   └── prompt_template.py      # ADR-014
│   └── exceptions.py
├── infrastructure/                 # 基础设施（Adapter 实现）
│   ├── database/                   # SQLAlchemy + SQLite（Repository）
│   ├── llm/                        # LangChain LLM Client（ChatLiteLLM）
│   ├── agent/                      # LangGraph Agent Pipeline（StateGraph）
│   ├── rag/                        # RAG 检索（Chroma + BGE）
│   ├── prompt/                     # Prompt 模板管理（ChatPromptTemplate + YAML）
│   ├── auth/local_trust.py
│   └── storage/local_file_storage.py
├── core/                           # 共享基础设施
│   ├── config.py                   # Pydantic Settings
│   ├── database.py / log.py
└── prompts/                        # Agent Prompt 模板（YAML）
```

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| 按技术分目录（选定） | infrastructure 子模块可独立替换（如换 RAG 方案只改 rag/） | 文件数量增加（~70+ 文件） |
| 按业务分目录（v1.0） | 业务聚合直观 | 技术实现交错，替换成本高 |

## 影响

- ✅ infrastructure 层按技术实现分目录，业务模块在 domain 层
- ✅ 每个 infrastructure 子模块可独立替换
- ❗ 文件数量增加（~70+ 文件）
