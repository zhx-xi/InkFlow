# ADR-022: skills 包形态 — 源码单一真相 + 三通道分发

> **状态**: ✅ 已接受
> **日期**: 2026-08-02
> **风险等级**: 🟢 低
> **依据**: Issue #65（决策 1：AI agent 通过随程序/源码的 skills 包使用；MCP 从 Phase 3 关键路径降级为远期增强）+ design/product-positioning-analysis-2026-08-02.md 旅程 C（AI agent 辅助写作旅程）

## 背景

1. Issue #65 决策 1：单机形态中，其他 AI agent（如 Hermes / Claude Code）通过**随程序/源码的 skills 包**使用 InkFlow；MCP 后移为远期增强
2. 旅程 C：agent 通过 skills 发现项目结构（`project list --json`）→ 读取设定（结构化 JSON）→ 调用 write 生成章节 → 触发审计 → 结果写回 —— **全程走 CLI 命令 + `--json` 输出**，零常驻服务
3. 既有资产：CLI（Typer）与 `--json` 输出契约已实现并有 tests/cli/ 覆盖；`inkflow` 命令即 agent 的执行通道
4. 约束：skills 包 = Markdown 使用说明 + CLI 命令封装，**零后端代码、零依赖、零常驻进程**，比 MCP 更早落地

## 决策

- **单一真相**：源码仓库 `skills/inkflow/` 目录是唯一维护源；结构 = `SKILL.md`（**YAML frontmatter**：name / description / 触发条件 / 版本）+ `references/` 子目录（命令参考、JSON 契约示例、使用指南）
- **三通道分发**：
  1. **GitHub 源码 tap / URL**（主通道）：agent 直接 fetch 安装，永远最新
  2. **随安装包内置**（辅通道）：离线/无网络环境可用
  3. **`inkflow skills install` 命令**：列出 / 安装 / 更新 / 校验，统一管理入口
- **执行契约**：CLI `--json` 输出是 agent 与内核之间的**稳定执行契约**；skills 文档只描述命令语义与 JSON 结构，不重复实现逻辑
- **版本对齐**：skills 包版本与 InkFlow 版本对齐（沿用 ADR-019 SemVer），随版本发布更新
- **演进预留**：MCP Server 发布（ADR-023）后，在 skills 包内补充 `mcp-setup.md`，引导 agent 平滑切换到 MCP 结构化调用

## 备选方案

| 选项 | 优点 | 缺点 |
|------|------|------|
| **源码单一真相 + 三通道分发（选定）** | 单一维护源无双份漂移；在线/离线场景全覆盖；零后端代码 | 需维护 `inkflow skills install` 命令与版本对齐规则 |
| 仅随安装包分发 | 实现最简单、单份拷贝 | 与源码仓库**双份维护**、更新滞后、agent 拿不到最新版、无法热更新 |
| 仅 GitHub 分发 | 单一真相、永远最新 | 离线/无网络环境不可用，覆盖面不足 |

## 影响

- ✅ **零后端代码**：纯文档 + 现有 CLI 能力，可立即交付（不阻塞 0.5.0 之前任何里程碑）
- ✅ 三通道覆盖在线/离线、自动/手动全部安装场景
- ✅ 版本与 InkFlow 对齐（ADR-019），发布节奏清晰
- ❗ 必须保证 CLI `--json` 输出稳定性：1.0.0 契约冻结（ADR-019）后字段不得随意变更，否则破坏 agent 生态
- ❗ skills 文档与 CLI 命令语义需同步演进：变更评审时对照 tests/cli/ 契约测试
