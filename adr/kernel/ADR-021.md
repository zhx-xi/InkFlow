# ADR-021: 本地内核进程化 — 独立进程 + localhost REST + SSE 通信

> **状态**: ✅ 已接受
> **日期**: 2026-08-02
> **风险等级**: 🟢 低
> **依据**: Issue #65（产品形态决策 1/2：单机 = GUI + CLI + skills 包，web 页面归云）+ design/product-positioning-analysis-2026-08-02.md §1（形态① 与 ② 共享同一本地后端进程）
> **替代**: 产品定位分析 §1 隐含的「GUI 直连进程内服务」思路（进程内调用否决，理由见备选方案）

## 背景

1. 单机形态存在**多客户端并发**访问同一份数据：GUI 主界面 + CLI + skills 包（AI agent）+ MCP Server（远期），任何客户端都不能独占内核
2. 云端 = 单机的远程形态：GUI/CLI 需支持「远程模式」（配置 api_base + token 后读写云端而非本地），与本地访问必须共享同一契约（产品定位分析 §5 #10）
3. 既有资产：FastAPI REST API + SSE 流式（F23）+ `inkflow serve` 命令已实现，且有 tests/api/ 集成测试保障
4. 约束：**零新增通信抽象** —— 不得为 GUI 发明独立协议，不得破坏与云端同一 OpenAPI 契约

## 决策

**单机 GUI 连接本地 FastAPI 内核进程，通信走 localhost HTTP REST + SSE**：

- **内核 = 独立进程**，由 GUI 壳管理生命周期（启动 / 健康检查 / 异常退出拉起 / 关闭）
- **动态端口**：绑定端口 0（系统分配），实际端口经 **stdout / 端口文件** 交付给 GUI 壳，避免端口冲突
- **多进程并发**：SQLite 启用 **WAL 模式 + busy_timeout**（基于 ADR-003），支撑 GUI/CLI/agent 同时读写
- **本地安全基线**：仅监听 **127.0.0.1** + 启动时生成**随机 token**（请求头校验）；CORS 白名单仅放行本地来源 —— 防 CSRF / DNS rebinding
- **远程模式**：同一 API client 换 **base URL + JWT** 即连云端，架构零新增
- **交付口径**：现有 `inkflow serve` 的强化版（`--port 0` + token + WAL），不引入新命令、不新增抽象

## 备选方案

| 选项 | 优点 | 缺点 |
|------|------|------|
| **独立内核进程 + REST/SSE（选定）** | 多客户端并发共享；与云端同一 OpenAPI 契约（远程 = 换 base URL + JWT）；SSE 流式一条代码路径两用 | 需管理内核生命周期与本地安全基线 |
| 进程内调用（in-process，GUI 直接 import 服务） | 无网络层、实现最简单 | 内核被 GUI 进程**独占**，CLI/agent/MCP 无法并发访问；本地/远程契约分离（进程内没有 HTTP 契约） |
| 命名管道 / IPC | 性能好、无端口暴露 | 与云端 REST 契约不统一，agent（skills/MCP）无法复用；前端 TS 客户端接入成本高 |

## 影响

- ✅ 多客户端（GUI / CLI / MCP / agent）并发访问同一内核，SQLite WAL 支撑读写并发
- ✅ GUI 远程连云端 = 换 base URL + JWT，OpenAPI 契约单一（ADR-004 Pydantic 契约全栈复用）
- ✅ SSE 流式（F23）在 GUI 与云端走同一条代码路径
- ✅ 零新增抽象：交付物 = 现有 `inkflow serve` 强化版，REST/SSE 测试资产（tests/api/）直接复用
- ❗ 新增 GUI 壳侧的内核进程生命周期管理（端口交付、健康检查、崩溃拉起）
- ❗ 本地安全基线必须守住：127.0.0.1 + 随机 token 校验，防止浏览器页面滥用本地端口
