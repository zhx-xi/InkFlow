# ADR-065: 多纪元正式化 — `timeline_events` 三列（`era` / `era_value` / `era_scale`）+ `time_value` 全局标量语义

## 状态

✅ 已接受（2026-10-06 拍板）——由 issue #1410（0.17.0 W2 轨 b，Part of #1328 子任务 T1/3）驱动。

> **本 ADR 改写两项既有判定**：
> 1. `specs/f12-timeline/spec.md` **§2.2** 原「纪元 + 序号复合键 ❌ 否决」——v1.3 已改为「分期处置」，本 ADR 完成「第二期」并给出接受理由；
> 2. `specs/f12-timeline/spec.md` **§2.8 E7「零 DDL」**——0.16.0 的硬边界在本里程碑**到期解除**（新增三列 + 迁移）。
>
> 决策来源：issue #1410 正文（范围四条 / 依赖 / 验收四条）+ 评论区「承接登记（2026-10-03）」（前端列切换并入本单验收）。

## 背景

### 需求侧事实

作者的世界里同时存在多套纪年（某王朝年号、某修真界的界历、上界的历法），而世界序只能按「±N 日」这类相对标量显示，无法**按纪元分轴显示与选择**。
用户 2026-10-01 拍板：最终做**完整历法换算引擎**（正式列 + 流速换算 + 跨轴一致性判定），整体量大 → 拆两个里程碑：

| 里程碑 | 内容 | 状态 |
|---|---|---|
| **0.16.0**（#1353，PR #1435） | 多轴共存 + 可选择性显示：`extra.era` / `extra.era_value` 承载，**零 DDL**、可逆 | ✅ 已交付 |
| **0.17.0**（#1328） | 完整历法换算引擎：T1 正式化（本 ADR）/ T2 换算（#1411）/ T3 前端（已并入） | 本轨 = T1 |

### 0.16.0 承载方式的已知短板（实测）

- **弱约束**：`extra` 是 JSON 列 —— 轴名/轴内值**无类型、无长度上限（DB 层）、无索引**；分轴统计只能全表扫描后在应用层分桶。
- **第二真源风险**：纪元语义与 `time_value` 混在同一个 JSON blob 里，DDL 层不可见 → 无法写「schema 级」的漂移门禁。
- **T2 无落点**：流速比（`era_scale`）没有承载位；跨纪元换算需要它作为一等数据。

### 原「❌ 否决」的真实理由与当时的处置

§2.2 原否决理由有两条，**两条都仍然成立**，只是当时的结论是「因此 0.16.0 不做」，而非「永远不做」：

| 原否决理由 | 0.16.0 处置 | 0.17.0（本 ADR）处置 |
|---|---|---|
| 「跨纪元比较需要额外换算规则」 | **成立 → 不做换算**（不设跨纪元验收项） | **仍然不做**：换算/分桶归 **T2（#1411）**；本轨**不引入**换算 |
| 「两个字段参与排序逻辑复杂」 | **成立 → 不引入双排序字段**（全局排序键仍是单一 `time_value`） | **仍然成立 → 排序键不变**：`era_value` 只在**轴内**使用，**不进**全局排序、**不进**一致性检查 |

即：**推翻的不是理由，是「因此不做正式列」这个推论**。三条边界（单时基不变 / 纪元只作轴标签 / 不跨纪元比较）在 0.17.0 依然逐条保持（见「决策」§2）。

## 决策

### 1. 数据面：`timeline_events` 新增三列

| 列 | 类型 | 约束 | 语义 |
|---|---|---|---|
| `era` | `VARCHAR(50)` | `NOT NULL DEFAULT ''` | **轴名**（如「本纪年号 / 修真界纪年 / 仙界纪年」）；`''` = 该事件属于**默认轴**（= 旧的单标量时间线，R6-4） |
| `era_value` | `FLOAT` | `NULL` | **轴内值**（如某纪元轴内的 `317.5`）；`NULL` = 轴内值未知。**仅在该事件 `era` 非空时有意义** |
| `era_scale` | `FLOAT` | `NOT NULL DEFAULT 1.0` | **流速比**（该纪元相对项目时基的时间流速）；`1.0` = 与项目时基同速。本轨只落列 + 默认值，读写面与换算归 T2（#1411） |

### 2. 语义定死（跨层契约，不得各造一套）

- **`time_value` = 换算后的全局标量**（跨轴**唯一**排序键，§2.7 S1/S3 完全不变）。
  `time_unit` 仍是它的物理尺度（§2.7 S2，参与归一排序）。**本轨不改 `time_value` / `time_unit` 的任何语义。**
- **`era` = 轴名**；**`era_value` = 轴内值**；**`era_scale` = 流速比（默认 1.0）**。
- **跨纪元比较必须经换算**——换算规则（`time_value_global = f(era, era_value, era_scale)`）归 **T2（#1411）实现**。
  本轨**不做**换算、**不按 `era` 分桶**、`check_consistency` 的相邻对扫描**维持原样**（只在归一日尺度上比较 `time_value`）。
- **三条边界逐条保持**：① 单时基不变（不引入第二套时基）；② 纪元只作轴标签（轴族派生 / 轴选择 / 轴内排序与标签）；③ 不跨纪元比较（硬验收：同一批事件加不加纪元，`check` 结论**逐字段一致**）。

### 3. 唯一真源与旧承载处置

- **正式列为唯一真源**：写入面只写 `era` / `era_value`；读取面（repo / API 响应 / 前端 / CLI 回显）只读三列。
- **`extra.era` / `extra.era_value` 降级为 v1.3 遗留快照**：迁移时**一次性投影**进正式列，此后**不再读写**。
  - **不删除** `extra` 里的旧键 —— 满足「迁移不得删改既有数据」约束，并保住**可逆性**（回退到 0.16.0 时纪元信息仍在）。
  - 旧键若与正式列分歧，**以正式列为准**（旧键是历史快照，无任何读取面消费它）。
- **请求面 `era` / `era_value` 的成对语义（§2.8 E4）完全不变**，仅落点由 `extra` 改为正式列：
  ① `era` 未传（`None`）⇒ 不动（`era_value` 一并忽略）；② `era = ""` ⇒ 清空轴名与轴内值；③ `era` 非空 ⇒ 写轴名，`era_value` 数值写入 / `""` 清除 / 未传保留。

### 4. 迁移（沿用 ADR-054 惯例：`create_all` 管新库 + `ensure_*` 修旧库）

新增 `ensure_timeline_era_columns(conn)`（幂等）：

1. **表不存在 → no-op**（全新环境等 `create_all` 建表，ORM 已含三列）。
2. **缺列才 `ALTER TABLE ... ADD COLUMN`**（`PRAGMA table_info` 探测；空表 / 有表缺列 / 有表有列三形态均幂等）。
3. **存量回填**：把 `extra.era` / `extra.era_value` 投影进正式列（仅当正式列 `era = ''` 且 `extra` 中确有轴名）。
   以 `migration_markers` 表（#1323 引入）的标记键保证**只跑一次**；`era_scale` 由 `ADD COLUMN ... DEFAULT 1.0` 对既有行**自动填充**。
4. **不阻塞启动**（本仓既有约定）。

`core/database.py` 已顶 900 行护栏，故本 helper 落在 sibling 模块 `core/migrations_timeline_era.py`，
**不 re-export**（镜像 ADR-063 对 `ensure_project_id_fk_children` 的处置）；`api/app.py` 的 `lifespan` 直接从 sibling 导入并接线，
接线守护落在本轨契约测试（AST 提取，禁 substring）。

### 5. 消费面同 PR 切换（消除中间态漂移）

前端读取来源（`timeline-era-axes.ts` 的 `eraNameOf` / `eraValueOf`、`LibraryCreateDialog` 的编辑预填）
**必须与本轨同 PR** 从 `extra.era` / `extra.era_value` 切到正式列 —— 不得留「后端已换列、前端仍读 `extra`」的窗口
（本仓已有该类漂移先例）。

## 备选方案

| 方案 | 说明 | 结论 |
|---|---|---|
| **三列 + `time_value` 全局标量（采用）** | `era` / `era_value` / `era_scale` 落正式列，`time_value` 保持跨轴唯一排序键 | ✅ 类型/索引/长度可约束；T2 有 `era_scale` 落点；改动面可控（1 表 + 读写路径） |
| 维持 `extra` 承载（0.16.0 现状） | 零 DDL、完全可逆 | ❌ 弱约束、无法索引、无法写 schema 级漂移门禁；T2 的流速比无承载位 → 正式化无可避免，只是推迟 |
| `era` + `era_value` 作**复合业务键**（唯一约束 / 复合主键） | 「纪元 + 序号」复合键 | ❌ §2.2 原否决理由**仍成立**：全局排序仍靠 `time_value`，复合键只是多一套键 + 一个本该允许重复的约束（同刻多事件是常态） |
| 新增独立 `timeline_eras` 轴表（轴名 → 流速比） | 轴成为一等实体 | ❌ **过度设计**：本期轴只是**事件属性标签**，无独立生命周期/属性集；跨表 join 换取零收益。若 T2 需要轴级配置，届时再评估（记入 T2） |
| 迁移时**删除** `extra` 旧键（move 语义） | 唯一真源更干净、无历史快照 | ❌ 违反「迁移不得删改既有数据」；且降低可逆性（回退 0.16.0 丢纪元）。代价（旧快照与正式列可能分歧）由「正式列为准 + 旧键无消费面」覆盖 |
| `era` 列直接承载**换算后**的全局时间（而非轴内值） | 省一次换算 | ❌ 与 §2.7 直接冲突：全局标量的唯一承载位是 `time_value`；且换算无 `era_scale` 时不可能正确 |
| Alembic 迁移（ADR-054 骨架） | 用版本权威取代 `ensure_*` | ⏸ ADR-054 已接受但**实施挂下期**；本轨沿用现行 `ensure_*` 形态（与其它 32 个 helper 一致），不混用两套 schema 所有权 |

## 影响

### 更容易

- 纪元数据从「JSON blob 里的约定」升为 **DDL 可约束**的一等列：类型、长度、默认值由 DB 保证。
- **T2（#1411）有落点**：`era_scale` 就位，换算只差算法；跨轴分桶/换算无需再动 schema。
- 读取面统一（repo → API → 前端 → CLI 一条链），消除「同一语义两种承载」的认知负担。
- schema 级漂移门禁（ORM ↔ 迁移）从此可覆盖这三列。

### 更难 / 成本

- **改动面**：1 个 ORM 模型 + 1 个领域实体 + 2 个 DTO + 1 个 service 写入路径 + 1 个 repo 映射 + 1 个迁移模块 + `lifespan` 接线
  + **前端 3 处读取来源** + `ci_cd/openapi_snapshot.json` / `openapi.d.ts` 重刷 + 既有 `#1353` 契约测试族按新契约升级。
- **迁移风险**：`ADD COLUMN` 本身安全（非破坏性），但**回填必须幂等**（marker 表）；失败**不得阻塞启动**。
- **`extra` 旧键成为历史快照**：与正式列可能分歧 —— 由「正式列为唯一真源、旧键无消费面」显式声明覆盖，属**有意接受**的代价（换取可逆性）。
- **900 行护栏**：`core/database.py` 恰在 900 行边界 → helper 落 sibling 且**不 re-export**，接线守护改由契约测试承担（同 ADR-063）。

### 风险

- ⚠️ 若遗漏某个写入点仍写 `extra.era`，会出现「正式列空、extra 有值」的分歧 → 由「写入面单点（service）+ 前端同 PR 切换 + 契约测试断言响应 `era` 字段」共同封锁。
- ⚠️ 回填若对**已由正式列写过**的行重复执行，会用旧快照覆盖新值 → marker 表 + 「仅当 `era = ''`」双重护栏；契约测试显式覆盖「回填不覆盖已有正式列值」。

### 可逆性

- 代码层：`git revert`。
- 数据层：三列均为 `ADD COLUMN`（可 `DROP COLUMN`，无 FK / 无 UNIQUE 约束）→ **schema 回退成本低**；
  `extra` 旧键保留，回退到 0.16.0 后行为与 v1.3 一致。**属高可逆性变更**，故不构成「不可撤」决策。
