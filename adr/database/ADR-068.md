# ADR-068: 历法换算显示 — 声明式历法 spec（项目级）+「累计日数 → 年/月/日」口径

## 状态

✅ 已接受（2026-10-12 拍板 D1–D6）——由 issue #1589（0.18.0 时间线显示轨 B）驱动。

> **与既有 ADR 的关系（不改写任何既有结论）**：
>
> 1. [ADR-065](../database/ADR-065.md)（`era` / `era_value` / `era_scale` 三列 + `to_global = era_value / era_scale`）
>    与 [ADR-067](../database/ADR-067.md)（正式表零未定事件 + 后置时间归一）的语义**逐条保持**；
> 2. 本 ADR 只新增**显示层换算**：`time_value` 仍存「相对项目时基的累计日数」（f12 §2.7 S1/S3），
>    `era` / `era_value` / `era_scale` 语义不变，**换算结果不回写库**（D6）；
> 3. 换算**只管标签文本**，跨轴纵向定位仍由 `to_global` 决定 —— 两者**不合并**（D6 反例见验收 N7）。

## 背景

### 需求侧（用户 2026-10-12 rc6 产物实测）

刻度带标签 = `time_value` + `time_unit` 原样输出 → 实测印出 **`0.79 日 / 0.84 日 / 3.27 日 / 2920 日 …`**；
页脚「共 214 刻度」；轴头只有「未分纪元 222」、**没有任何轴选择器**。

用户原话：**「没有显示我想要的比如：天平 xx 年这种，还是 xx 日，也不能选择主轴和其他纪元轴」**。
→ 缺两件：① **日数 → 年/月/日 的展示换算**（按轴各自的历法）；② **轴族 = 1 时的「主轴命名 / 绑定历法」入口**
（否则用户造不出第二条轴，D5「复用 `tl-axis-picker`」**没有起点**）。

补充实测事实：补时间后的 `time_value` 是**小数**（按章锚区间均匀铺开）→ 未配历法时若原样打印会出现
`0.79 日` 这类**无意义的亚日小数**（同一「日」下的多个刻度本应同标签）。

### 技术侧事实

| 事实 | 出处 |
|---|---|
| 纵向定位已用 `to_global = era_value / era_scale` | ADR-065 E11（本 ADR **不动**） |
| 刻度标签回退链 = `era_value` + `time_unit` → `time_value` + `time_unit` → 「未知」 | f19-gui/timeline.md N14 |
| `time_value` 语义 = 累计时基（单位由 `time_unit` 声明；`日` = 1） | f12 §2.7 S1–S3 |
| 轴族派生（`era` 值去重）与轴选择器已存在 | #1353 / f19 §2 |

### 为什么不引入现成库（2026-10-12 实查，★ = GitHub API 实测）

| 仓库 | ★ | 形态 | 结论 |
|---|---|---|---|
| javalent/calendarium | 154 | Obsidian 插件 | 插件形态，非可复用库 |
| vigoren/foundryvtt-simple-calendar | 70 | FoundryVTT 模块 | 同上（`monthDays` / `leapYear{rule,interval,offset}` 形状可借） |
| rayners/fvtt-seasons-and-stars | 13 | FoundryVTT 模块 | 借数据形状（`intercalary` / `eraCycle`），**不引依赖** |
| steamedcotton/rpg-calendar | 3 | npm 包 | 内置固定历（Harptos），覆盖不了「不等月长 + 纪元周期」 |

结论：本需求只要「累计日数 → 年月日」的**格式化**（不做日期运算 / 星期 / 月相），**该领域没有通用库**
（最大 154★ 且为插件形态）→ **自建纯函数**，零新增依赖（ADR-025 依赖锁定不受影响）。

### 为什么存储形态是「表达式字符串」

| 形态 | 可序列化进项目配置 | 无 `eval` | 覆盖「不等月长 + 4 年一闰 + N 年一纪元」 |
|---|---|---|---|
| 枚举预设（`none` / `gregorian` / `custom(interval,offset)`） | ✅ | ✅ | ❌ 表达力不足（自定义间隔 + 偏移无法表达「百年不闰、四百年再闰」） |
| **表达式字符串（`#` = 年序号）** | ✅ | ✅（受限词法求值） | ✅ |
| 真函数 / 闭包 | ❌ | ❌（需沙箱） | ✅ |

→ 取**表达式**（与 `bevy_ingame_clock` 的 `leap_years: String` 同形）；枚举预设保留为 **UI 快捷项**
（点一下填出等价表达式），**唯一存储形态 = 表达式**。

## 决策

### 1. 承载：项目级 `ProjectConfig.calendars`（零 DDL）

历法 spec 挂在**项目配置**上（`projects.config` JSON 列内，`ProjectConfig` 新增类型化字段 `calendars`），
**不新增表、不新增列** → 零迁移、可 JSON 导入导出、agent 可经项目配置 API 写入（D3）。

```jsonc
{
  "calendars": [
    {
      "axis": "武侠界",                       // = 事件的 `era` 值（D1：每主轴一套）；"" = 默认轴
      "epoch_label": "开元",                  // 第 1 年年号（可空 → 只显示数字）
      "month_names": ["正月", "二月", "…"],     // 可空；非空时长度必须 == month_days.length
      "month_days": [30, 29, 30, 30, 30, 29, 30, 30, 29, 30, 30, 29],  // 不等月长（D2）
      "leap": { "rule": "# % 4 == 0 && (# % 100 != 0 || # % 400 == 0)", "add_days": 1, "month": 2 },
      "intercalary": [],                      // **保留字段，0.18.0 不参与换算**（无名日/独立节日）
      "era_cycle": { "years": 100, "label": "劫" }   // 可空；「N 年一纪元」
    }
  ]
}
```

> **字段命名 = `snake_case`**（与 `ProjectConfig` 既有字段 `agent_architect` / `chapter_title_format` 一致，
> 不引入 camelCase 别名）；社区调研里的 camelCase 形状**只作灵感**，落库名以本节为准。

**轴身份 = `era` 值**（D1：换算公式每主轴一套）。**无该轴的条目 ⇒ 该轴不换算**（D3：不给默认值、不猜）。

### 2. 换算口径：纯函数，唯一实现点

**唯一实现点 = `domain/services/calendar.py`**（纪律同 ADR-065 E11「不得各写一份」）。

```text
day_count_to_date(day_count: float, spec: CalendarSpec) -> CalendarDate{year, month, day, cycle}
```

| # | 规则 |
|---|---|
| C1 | **同日归整**：输入先取 `floor(day_count)` → 亚日小数**一律向下归整到「第 N 日」**（同一日内的多个刻度显示同一「N 日」，消掉 `0.79 日`）。0 基：第 1 天 = `day_count ∈ [0,1)` |
| C2 | **年长**：`sum(month_days) + (leap.rule 命中年序号 ? leap.add_days : 0)`；闰日加在 `leap.month`（1 基月序） |
| C3 | **逐级累加**：从第 1 年起累计各年年长定位年（`#` 代入年序号）；年内逐月累加定位月/日。历法年数 < 10⁴ 足够；更大时改前缀和 / 闭式（**不做投机优化**） |
| C4 | **纪元周期**：`era_cycle = {years, label}` ⇒ `cycle = floor((year - 1) / years) + 1`；标签前插「{cycle} {label}」。无 `era_cycle` ⇒ 无前插 |
| C5 | **确定性与幂等**：纯函数（同输入同输出）；不读时钟、不读全局态 |
| C6 | **越界防御**：`month_days` 非正 / 长度与 `month_names` 不匹配 / `leap.month` 越界 / 表达式解析失败 ⇒ **spec 非法 ⇒ 写入 422**，且该轴**不换算**（回归「N 日」） |

### 2.1 分层与输入口径（实现前定稿，2026-10-12）

| # | 规则 | 理由 |
|---|---|---|
| S1 | **日历数学只在后端**：spec 模型 + 表达式求值 + `day_count_to_date` 全在 `domain/services/calendar.py`（**唯一实现点**）；**API 随事件下发计算结果三元组** `calendar_date: {year, month, day, cycle} \| null`（**纯数据、不含文案**）；**前端只做「选粒度 + 拼文案」**（无任何日历数学） | 避免 Python（CLI/API）与 TS（GUI）**双实现漂移** —— 同 ADR-065 E11「不得各写一份」纪律 |
| S2 | **换算输入 = 现行标签的取值来源**（f19 `bandLocal` 口径：**纪元轴 = `era_value`；默认轴 = `time_value`**），再按 f12 §2.7 **S2 归一到「日」**（`日/天`=1、`月`=30、`年`=365、`周`=7）；`时/时辰` 按 **S4** 归到当天锚点的日数后再取整 | 与既有「标签取哪个值」口径保持一致（不改显示语义），且复用既有归一表，不新造第二套 |
| S3 | **`era_value` 无单位列** ⇒ 视为**该历法自己的「日」尺度**（历法 spec 的解释权在该轴手上） | D1：每主轴一套公式 |
| S4 | **未配历法的轴** ⇒ `calendar_date = null` ⇒ 前端回落「N 日」（整数，C1 归整后） | D3：不给默认值（零回归） |
| S5 | **粒度（D4）在前端决定**（前端掌握分页 / 相邻刻度），后端只给三元组 —— 同一次换算在不同页可能显示不同粒度，**数字本身不变** | 粒度是「版面」问题，不是「历法」问题 |

### 3. 表达式求值器：受限词法，**永不 `eval`**

| # | 规则 |
|---|---|
| X1 | 白名单词法（**仅此**）：整数常量、`#`（年序号）、`+ - * / %`、`== != < <= > >=`、`&& \|\| !`、括号 |
| X2 | 实现 = 手写 tokenizer + 递归下降求值器，**仅用于布尔判定**；**禁止** `eval` / `exec` / `compile` / 属性访问 / 名字查找 / 函数调用 |
| X3 | 长度上限（≤ 200 字符）；非法 token / 括号不匹配 / 空表达式 ⇒ 解析失败 ⇒ spec 非法（C6） |
| X4 | 求值失败（除零等）⇒ 不命中闰年（**不抛异常**，不阻断渲染） |

### 4. 显示粒度：按刻度间距自适应（D4）

| # | 规则 |
|---|---|
| G1 | 粒度判据 = **本页相邻刻度的日数差**（取中位数，落在该轴的刻度序上）与该历法自身长度比较：`< 1 月` → `X 年 Y 月 Z 日`；`< 1 年` → `X 年 Y 月`；`≥ 1 年` → `X 年` |
| G2 | 阈值**由 spec 自身导出**（「1 月 / 1 年」= 该历法 `monthDays` 均值 / 年长），不硬编码 365/30 |
| G3 | `eraCycle` 生效 ⇒ 标签前插「{cycle} {label}」（如「3 劫 12 年」） |
| G4 | **未配历法 ⇒ 回落「N 日」**（整数，C1 归整后）——零回归（验收 N1/N8） |
| G5 | `epochLabel` 非空 ⇒ 年份显示为 `{epochLabel} {year} 年`，否则 `{year} 年` |

### 5. 主轴命名 / 绑定历法入口（rc6 复验补充）

| # | 规则 |
|---|---|
| P1 | 轴族 ≥ 2 ⇒ 复用既有 `tl-axis-picker`（D5），选中轴决定哪些历法生效 |
| P2 | **轴族 = 1 也必须有入口**：项目设置页「历法」块显式列出「默认轴（未分纪元）」一行可编辑（= 给该轴命名 + 绑定历法）。否则验收 N6（双主轴各按自己历法显示）**没有起点** |
| P3 | 编辑面 = 项目设置页「历法」块（每轴一个 spec；留空 = 不换算）；spec 走项目配置 API 写入 |

### 6. 明确不改的东西（边界）

- `time_value` / `time_unit` / `era_value` / `era_scale` / `to_global` / 一致性检查 / 审计判定 —— **全部不动**（D6）；
- 换算**只产标签文本**，不写库、不进排序、不参与判定；
- **不引入第二套时基**（ADR-065 边界① 保持）：历法只**解释** `time_value`，不替代它。

## 备选方案（未选项，供复议）

| 案 | 内容 | 否决 / 保留理由 |
|---|---|---|
| A | 引入现成日历库（`@internationalized/date` / `rpg-calendar`） | **否决**：本需求只要格式化（无日期运算 / 星期 / 月相）；社区最大 154★ 且为插件形态，绑定成本 > 自建 ~200 行 |
| B | 允许用户写任意 JS/Python 函数（用户原话「自定义函数等」） | **保留为将来例外**：需 `eval` + 沙箱 + 序列化/迁移问题；表达式已覆盖「不等月长 + 4 年一闰 + N 年一纪元」全部诉求 |
| C | 固定两个数「N 日 = 1 月 / M 日 = 1 年」 | **否决**：覆盖不了不等月长 / 闰年 / 纪元周期 |
| D | 枚举预设 `none` / `gregorian` / `custom(interval,offset)` | **保留为 UI 快捷项**（点一下填出等价表达式）；存储形态仍是表达式 |

## 影响

### 更容易

- 多「界」各按自己历法显示（验收 N6），女主/主角所在界可作主轴切换（D5）；
- 亚日小数消失（C1 同日归整），刻度标签首次可读；
- spec 在项目配置里 ⇒ **agent 可自主确认历法**（D3 的「必须显式确认」由项目配置 API 落地，无需新增专用端点）；
- 零新增依赖、零 DDL ⇒ 可逆（删掉 `calendars` 即回到「N 日」）。

### 更难 / 代价（诚实记录）

- 自建**受限 DSL**（表达式）是长期维护成本：白名单外的输入必须**被拒且可测**（X2/X3 需专项测试）；
- 本版 `intercalary`（无名日 / 闰月）**只作保留字段、不参与换算** —— 将来要支持需扩展语法与算法（届时另开 ADR）；
- 「换算结果不是数据」这一点必须写死在 spec 里（CLI / 审计 / API 仍是日数），否则各界面会各造一套显示口径。

### 边界

- 时基唯一性保持（ADR-065 边界①）：历法**不**引入第二套时基，也不改变 `time_value` 的物理尺度；
- 未配历法 = **零回归**（验收 N1/N8：无 spec 不报错、不静默套默认历法）。
