# ADR-039: Skills 文件系统真源（DB 退役 + deepagents 原生目录引用）

> **状态**: ✅ 已接受
> **日期**: 2026-08-20
> **风险等级**: 🟡 中（存储架构变更，涉及 API/装配/seed 语义；0.10.1 补充批 #522 落地）
> **依据**: Issue #522（GUI 复验三个技能管理缺陷：无滚动/不可编辑/仅粘贴上传）+ 用户拍板（2026-08-20 D3a=B / D3b=A / D3c=A）

## 背景

0.10.1 rc3 GUI 复验暴露 Skills 管理三个问题（#522）：内置 skill 详情无滚动条、复制的 user_upload skill 无查看/编辑入口、上传只能 textarea 粘贴无法上传本地文件/文件夹/zip/URL。深入分析后定位根因：**F39 Skill 实体以 DB 表（`skills`）单列 `content` 存储**，与 deepagents 生态的 skill 分发型（文件系统 `data_dir/skills/<name>/SKILL.md`，ADR-022）结构割裂，导致：

1. **结构不支持多文件**：DB 单字段 content 无法表达 references/scripts 关联；社区 skills 包多为目录/zip 形态，导入即失败
2. **复制后可编辑语义残缺**：duplicate 产出的 user_upload 行无 PATCH 编辑入口（前端 + 后端双向缺）
3. **双真源漂移风险**：F19-skills CLI（`inkflow skills install`）已写 `data_dir/skills/`，F39 却存 DB——同名同域两套存储，迟早漂移
4. **deepagents 原生引用无法对齐**：Agent.skill_ids 存 DB 主键字符串化（`"3"`），而 deepagents SkillsMiddleware 的文件系统扫描要求 name=目录名

## 决策

### ① 完全去表（D3a=B）：skills 表删除，文件系统为唯一真源

- **删除**：`skills` 表 + `SkillORM` + `SQLiteSkillRepository` + `SkillRepositoryProtocol`（DB 路径全部移除）
- **新真源**：`data_dir/skills/<name>/SKILL.md`（`<name>` = frontmatter name = **目录名**，必须满足 deepagents N2 规则：小写字母数字+单连字符 `^[a-z0-9]+(-[a-z0-9]+)*$`）
- **Skill 领域模型**：删除 `id` 字段（无 DB 主键），保留 name/description/content/source/时间戳；API 响应层 `id` 字段值=name（兼容前端现有类型，P2 前端再对齐）
- **Agent.skill_ids 语义切换**：从 `str(int)` 主键字符串化 → **skill 目录名列表**（deepagents 原生 name 引用）；装配消费方（`_validate_skill_ids`、`list_agents_by_skill`、agentic_writer `skill_lookup`）全部按目录名解析
- **内置 6 Skill 英文 slug 化**：原中文名（架构/写作/审校/修订/世界观/润色方法论）**不满足 N2 规则**，落地文件系统时统一改为英文 slug：`architecture-methodology` / `writing-methodology` / `audit-methodology` / `revision-methodology` / `worldview-methodology` / `polishing-methodology`（description/content 中文保留；spec §5.3 明示 seed 内容非契约字段，可合法规范化）
- **与 F19-skills 同根**：本决策使 F39 内部白名单 skill 与 F19 分发型 skills CLI **共用同一目录**（`data_dir/skills/`），解析统一复用 `cli/skills_parser.py::parse_skill_metadata`（N2 校验）；F39 spec §1.3 原先「互不消费」边界**废止**（spec 同步修订）

### ② 启动初始化（D3b=A）：每次启动检查，内置缺失即回补

- `app.py` lifespan 调用 `ensure_builtin_skills(skills_root: Path)`：目录不存在或内置缺失 → 从代码内嵌常量 `BUILTIN_SKILL_SPECS` 写出 6 个 SKILL.md；已存在跳过（**删了回补**，镜像 seed 幂等语义改为文件复制）

### ③ 一次性迁移（D3c=A）：旧表 user_upload → 写出文件后清表

- `migrate_skills_from_db(session, skills_root) -> int`：旧 `skills` 表存在且有 `source="user_upload"` 行 → 逐行写出 `data_dir/skills/<name>/SKILL.md`（content 原样）→ 清空表（DELETE + DROP）；返回迁移条数；表不存在 → 0
- 迁移放在 P1（存储层 PR）内含实现 + 测试

### ④ 上传扩展（P2 落地，本 ADR 记录方向）

- SkillUploadDialog 增加「文件/文件夹/zip/URL」四种入口；后端上传端点（multipart / zip 解压 / URL 下载）→ frontmatter 解析（name=目录名称校验）→ 写 `data/skills/<name>/`；references/scripts 按目录保留
- SkillList 详情滚动容器 + user_upload 编辑入口（弹窗预填 → PATCH 文件写回）

## 备选方案

| 方案 | 内容 | 否决理由 |
|------|------|----------|
| A 维持 DB 单字段 content，只加滚动/编辑/文本上传 | 最小改动支撑 #522 表面三缺陷 | 无法解决多文件 skill 包导入（用户明确需求）；延续双真源漂移风险；skill 无法对接 deepagents 文件系统生态 |
| B 文件系统真源 + DB 软删/表保留 | 保留表留后路 | 双真源仍可能漂移（#211 真删先例：语义变更必须彻底）；迁移一次性完成，无需回退路径 |
| C 文件系统真源但内置保留中文目录名 | 少改内置名 | 中文名违反 deepagents N2 name 规则，deepagents FilesystemBackend 扫描会跳过加载——「deepagents 原生 name 引用」拍板语义失效 |

## 影响

**变容易**：
- skill 多文件结构（references/scripts）天然支持，社区技能包零改造导入
- F39 白名单 skill 与 F19 分发型 skills 同一目录同一解析器，生态收敛
- PATCH 编辑/删除/复制 = 文件操作，语义直观、无 DB 迁移负担
- Agent 白名单引用与 deepagents 原生 name 引用对齐，未来 SkillsMiddleware 接入零改造（deepagents-skills-middleware 研究已确认字节级兼容）

**变困难**：
- 内置 skill 显示名从中文变英文 slug（产品可见变化；description 中文保留，P2 前端展示可强化德文案可读性）
- API id 语义从 int 变 name 字符串，前端类型需同步（P2 UI PR 一并处理）
- 删除内置 skill 文件会被启动回补（只读语义 409 保留，杜绝「改坏了恢复」二次负担）
- skill 名即目录名：重命名 = 目录移动 + Agent.skill_ids 级联更新（本期 PATCH 不支持改名，改名走 删+建）
