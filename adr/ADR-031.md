# ADR-031: Agent 化双模式开关 — deterministic（默认）+ agentic（显式开启）

> **状态**: ✅ 已接受
> **日期**: 2026-08-03（拍板）；2026-08-12（落盘）
> **风险等级**: 🟡 中（新增 agentic 执行路径，deterministic 为默认不变）
> **依据**: Agent 化升级路径 v1.1 §1 判据 A-E + 用户拍板（2026-08-03，核心原则「双模式并存」）
> **原编号**: ADR-A（design/agent-upgrade-path-2026-08-03.md §5 架构决策点）

## 背景

Agent 化升级对照四条判据（自主控制流 A / 工具调用循环 B / 自主终止 C / 跨步状态恢复 D）+ 补充判据 E（越用越智能，F28 记忆系统）。但 agentic 模式引入 LLM 自主决策，token 消耗 3-8 倍、行为不可完全预知——不能无差别替换既有确定性写作链。

**核心原则**：双模式并存——`deterministic`（现有静态链，默认）与 `agentic`（显式开启）。符合项目「AI 自动化默认关闭、显式开启」既有设定（F13 timeline_auto_extract 先例）。

## 决策

- **模式字段**：`pipeline.mode: deterministic | agentic`，项目级配置 + CLI/请求覆盖（F13 同构：extra 键 + 请求体/CLI 显式覆盖）。
- **默认值**：`deterministic`——既有 `/api/v1/writing/generate` 等端点**零改动**，默认路径行为不变。
- **路径隔离**：agentic 用独立 API 前缀 `/writing/agentic/` 隔离语义，避免误用既有端点。
- **失败语义**：agentic 失败可回退 deterministic（用户显式决定，不自动回退——避免掩盖 agentic 缺陷）。
- 用户可见入口：`inkflow write next --mode agentic`。

## 备选方案

| 选项 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **双模式开关（选定）** | deterministic 零风险保留；agentic 增量隔离；复杂度可控 | 需要维护两条路径 | ✅ 用户拍板 |
| 独立配置表 | 语义清晰 | 过重；extra 键已有 F13 先例 | ❌ 否决（F27 spec §5.6 决策表） |
| 仅 CLI 开关 | 实现最简单 | 无项目级持久化，GUI 无法感知 | ❌ 否决 |
| 全量替换为 agentic | 单一路径 | 用户失去确定性路径；违背「显式开启」原则 | ❌ 否决 |

## 影响

- ✅ deterministic 默认路径行为零变化，既有测试零回归
- ✅ agentic 路径隔离在独立前缀，前后端契约清晰
- ✅ 双模式与 F13/F28 开关语义统一（extra 键 + 覆盖优先级）
- ❗ 复杂度上升（双模式并存）：deterministic 仍为默认；agentic 增量隔离；Supervisor（F29）远期
- ❗ CLI/API 需暴露模式选择；GUI 侧后续提供模式切换 UI
