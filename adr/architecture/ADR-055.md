# ADR-055: 时间存储与显示口径 — 存储/传输一律 UTC，面向用户显示一律本地时区

## 状态

已接受（2026-09-10，用户拍板 issue #1000）

## 背景

InkFlow 的时间字段（`created_at` / `updated_at` / `resolved_at` / `started_at` /
`confirmed_at` / 日志 `timestamp` 等）此前在三个界面上的显示口径不一致：

- **GUI 日志页**：`formatTimestamp` / `formatClock` 用 `toISOString()` UTC 口径显示
  （f496 spec 甚至写了 `toLocaleString()`，实现与 spec 均与「用户看到自己的时间」相悖）；
  详情面板原始 ISO 串直出（含 `Z` / `+08:00` 偏移，普通作者难以心算）。
- **CLI 人类输出**：`project/character/outline/foreshadowing/timeline/world/session/
  audit chapter` 的 get / confirm / history 视图把 HTTP JSON 里的时间串**原样透传**
  （如 `创建时间: 2026-01-01T00:00:00`），用户无法直观读出本地时刻。
- **API/MCP 数据层**：返回 ISO 原始值（SQLite `DateTime` 列剥 tzinfo，实际为
  naive UTC——探针实证 `tzinfo=None`）。

用户在 #1000 拍板：**所有面向用户的地方（GUI、CLI）时间一律显示本地时区；
保存/存储一律 UTC**。这是跨端惯例（邮件客户端、IDE、操作系统日志皆如此），
**不是可配置开关**——不新增 config 时区字段，规则为硬约束。

### 关键实证（决定实现形态）

1. **生产 API 返回 naive UTC**：SQLite `DateTime`（非 `timezone=True`）列存取会剥掉
   tzinfo，Pydantic 序列化为不带偏移的 ISO 串（值=UTC）。因此
   `datetime.fromisoformat(iso).astimezone()` 直转是**陷阱**：naive 输入会被 Python
   当作**本地时间**不做任何换算（漏掉整个时区偏移）。正确形态 = naive 先补
   `tzinfo=UTC` 再 `astimezone()`。
2. **Windows 测试环境时区注入不可靠**：Python 无 `time.tzset()`；`TZ` 环境变量被
   msvcrt 误解析（实测 `TZ=Asia/Shanghai` 下 `astimezone()` 输出 +1 而非 +8），且
   进程中途改 env 无效 → CLI 侧确定性测试必须走**函数参数注入目标时区**
   （依赖注入优于 monkeypatch，AGENTS.md §10.5），不依赖 runner 系统时区。
3. **Node ≥ 13 运行时 `process.env.TZ` 即时生效**（实测 v24：改后立即反映到
   `Date#getHours()` / `Intl`）→ 前端测试在 vitest setupFiles 钉
   `TZ='Asia/Shanghai'` 即可让「本地时间」断言与 CI（windows-latest，UTC）解耦。

## 决策

**全局硬约束（三层分工）：**

| 层 | 口径 | 说明 |
|----|------|------|
| 存储层（SQLite / 未来 PostgreSQL） | **UTC** | 既有 `_utcnow()` = `datetime.now(UTC)` 惯例不变；ADR-054 Alembic 迁移不动 |
| 数据层（REST API / MCP / `--json` 信封） | **UTC ISO 原始值** | API/MCP 是机器接口，客户端负责显示转换；`--json` 输出同属数据层，**不转换** |
| 显示层（GUI 组件 / CLI 人类输出） | **系统本地时区** | `YYYY-MM-DD HH:mm:ss`（秒粒度），无 UTC/本地切换开关、不加时区标注后缀 |

**实现收敛点（唯一真相）：**

- GUI：`frontend/packages/renderer/src/lib/log-format.ts` 的 `formatTimestamp` /
  `formatClock` 改用**本地访问器手拼**（`getFullYear/getMonth/getDate/getHours/
  getMinutes/getSeconds` + 手工补零）。**不用 `toLocaleString()`**——12/24 小时制、
  月份名、分隔符随 locale/浏览器差异漂移，契约不可测。`LogDetail` 详情时间戳从
  「原始 ISO 直出」改为复用 `formatTimestamp`（本地化）。
- CLI：新增 `backend/src/inkflow/cli/_time.py` 提供
  `format_local(iso: str | None, tz: tzinfo | None = None) -> str`：
  - naive 输入先 `replace(tzinfo=UTC)`（存储口径=UTC），再 `astimezone(tz)`
    （`tz=None` → 系统本地时区）；
  - 输出 `strftime("%Y-%m-%d %H:%M:%S")`；
  - 空串/`None`/解析失败 → 原样直出（显示层防御，CLI 不炸）；
  - `tz` 参数 = 测试确定性注入通道（实证 2）。
  各命令模块（project / character / outline / foreshadowing / timeline / world /
  session / audit_chapter）的人类输出分支接入 `format_local`；`--json` 分支不动。
- **例外（语义时间不转换）**：timeline 的「世界内时间 / 时间单位 / 原始时间表达」
  （`time_value` / `time_unit` / `time_display`）是**小说世界的语义时间**，不是
  现实时刻，保持原样；foreshadowing 列表标签 `回收于 <日期>` 属现实时间显示 →
  转本地日期。

**测试基准：**

- 前端：`src/test/setup.ts` 钉 `process.env.TZ = 'Asia/Shanghai'`（+08:00 确定基准）。
- 后端：单元测试用 `timezone(timedelta(hours=±N))` 注入断言；CLI 集成测试用
  `tests/cli/conftest.py::local_display()`（测试侧平行实现，不 import 被测函数，
  防自引用弱断言）计算期望值——在任意 runner 时区下均成立。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A. 本决策：显示层各自转本地，数据层恒 UTC | 单一存储口径；离线/云端（2.0.0 异地写作）天然正确；无配置面 | 每个显示点都要记得接入（靠统一 formatter + 契约测试收敛） | ✅ 采纳 |
| B. 可配置时区开关（config 加 tz 字段） | 用户可强制 UTC 视图 | 用户明确拍板「不是可配置开关」；配置面膨胀；三端同步成本高 | ❌ 否决（#1000） |
| C. 存储本地时间 + 偏移列 | 显示零转换 | 跨时区/夏令时数据损坏；云同步（2.0.0 PostgreSQL 多端）不可行；违背行业惯例 | ❌ 否决 |
| D. 前端 `toLocaleString()` | 一行搞定 | 输出随 locale 漂移（12/24 小时制、日期序），契约测试不可写 | ❌ 否决（任务书明示） |
| E. `--json` 也转本地 | CLI 全口径统一 | `--json` 是脚本/机器消费面，属数据层；破坏 API 一致性（实证：JSON 信封=透传 HTTP 响应） | ❌ 否决 |

## 影响

**变容易：**
- 用户在 GUI/CLI 看到的时间 = 墙上时钟，无需心算时区；
- 2.0.0 云端里程碑（异地写作/云存档）多端时间显示天然一致（存储 UTC 恒真）；
- 新显示点接入有唯一收敛口（`formatTimestamp` / `format_local`），契约测试钉死口径。

**变难 / 代价：**
- 既有「原样透传」断言（如 audit `confirmed_at` 原样输出契约）被本 ADR 显式废止，
  相关测试翻转为本地化期望值；
- GUI 详情面板不再显示原始 ISO 偏移串（需要原始值时用 `--json` / API / 日志
  `params`）；
- 每个新增人类输出点必须记得接入 formatter——由 ADR + spec 注记 + 契约测试
  三重防线兜底（漏接 = 测试红）。

**关联：**
- issue #1000（本决策触发）；F57 日志/i18n spec（日志时间戳显示口径注记）；
  f496 日志页 spec（`toLocaleString()` 旧注废止 → 本地访问器手拼）；
- ADR-016（loguru 结构化日志：日志**存储** timestamp 仍为 UTC，不变）；
- ADR-024 / 2.0.0 云架构（多端一致性前提 = 存储 UTC）；ADR-054（Alembic：
  无 schema 变更，不涉及）。
