# ADR-061: 知识图谱 drawio 互通 — mxGraph XML 一次性格式转换（不内嵌编辑器）

## 状态

✅ 已接受（2026-10-02 拍板：方案 A）

> 决策来源：issue #1360（由 #1325 实施会话产出；#1325 已把画布修好——连线可见 / 可拖拽 / 可拉线建关系 / `scope=related|all`）。
> 实施粒度：**单 PR**；本 ADR 只记录「形态选型」，具体交换格式与端点契约见
> `specs/f48-knowledge-graph/spec.md` §3.1/§5.7。
> 关联：ADR-020（本地/离线优先）、ADR-030（单一真相源）。

## 背景

F48 知识图谱的数据面是 `knowledge_relations`（六元组 + 描述），**#495 后它是关系数据唯一表**
（原 F9 `character_relations` 已反向并入）。同表被三处消费：

- AI 关系提取（#479）写入 `source=ai` 行
- 章节审计 / 伏笔联动按实体读取该表
- GUI 画布（`@xyflow/react` v12）渲染 nodes + edges

用户诉求（#1360）：知识图谱目前只能在 InkFlow 的画布上排布，缺少**在别的工具里精修排版**的手段——
希望「把画布上的关系导出成 `.drawio`，在 drawio 桌面版继续排版」，并能「把 drawio 里画好的关系图导回 InkFlow 落库」。

三个候选形态：

| 方案 | 形态 | 判定 |
|---|---|---|
| **A（本 ADR 采纳）** | **mxGraph XML 导入/导出**：一次性格式转换，不提供编辑器交互 | ✅ 采纳 |
| B | drawio `iframe` 内嵌（drawio 官方 embed） | ❌ 否决 |
| C | drawio 桌面版整包内嵌（随 InkFlow 分发 drawio 运行时） | ❌ 否决 |

## 决策

### D1：只做一次性格式转换，不内嵌编辑器

InkFlow 只提供**导出**（DB → 文件）与**导入**（文件 → DB）两个单向动作；
不在应用内提供 drawio 的编辑界面、不用 drawio 渲染画布、不引入任何 drawio 运行时。

### D2：`.drawio` 不落盘入库、不作为可编辑真相源

`.drawio` 文件是**用户自己保管的中间产物**，InkFlow 侧不保存、不索引、不追踪其内容版本。
导入是**幂等的校验-写入**动作，导出是**只读计算**——不存在「InkFlow 里的图谱」与「文件里的图谱」
两个需要保持一致的可写副本。

### D3：导入复用既有校验链 + 冲突跳过语义

导入不新增一条校验路径：解析后的每一行关系都走既有的
`KnowledgeGraphService.create_relation`（项目存在 → 自环 → 六元组字段 → 实体存在且同项目 → 同键唯一）。
- 同键已存在（无论是库内既有还是文件内重复）→ 按既有幂等语义**跳过并计数回报**
- 自环 / 实体不存在或跨项目 / 字段非法 / 端点无法解析 → **拒绝该行并计数回报**（不中断整批）
整批**不因单行非法而 500**；非法 XML 在解析阶段直接 422。

### D4：不做内嵌（离线 / 体积 / 双真相源三重冲突）

| 冲突 | 说明 |
|---|---|
| **离线** | 方案 B 的 drawio embed 依赖 `embed.diagrams.net` 在线资源 → 违背 ADR-020（本地优先/离线可用）与 ADR-021（本地内核） |
| **体积** | 方案 C 需随包分发 drawio 运行时（体积上百 MB 量级）→ 与本项目单文件便携分发的定位冲突（ADR-044 打包口径） |
| **双真相源** | 方案 C 会让 `.drawio` 成为**可编辑的第二个真相源**：用户在 drawio 改了图，InkFlow 不知道；InkFlow 的 AI 提取写了关系，drawio 不知道 → 违背 ADR-030。而 `knowledge_relations` 是 AI 提取 / 审计 / 伏笔联动的**消费源**，一旦分叉，下游（提取质量、审计报告、伏笔联动）全部失真 |

**结论**：drawio 只能作为「视图层的可替换外挂」，不能作为数据层的第二副本。

## 备选方案

| 备选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. mxGraph XML 一次性转换**（选定） | 可离线；零新增依赖（标准库 XML）；不引入第二真相源；不改变渲染栈（与 `@xyflow/react` 无关——导出/导入是纯数据转换） | 文件与库内容可能漂移（用户手工在两处改动）——但**漂移是一次性导入动作的责任**，不是持续双写 | ✅ 采纳 |
| B. drawio `iframe` 内嵌 | 交互完整、零格式转换 | 需外网；违背 ADR-020/ADR-021；且仍需解决双真相源 | ❌ 否决 |
| C. drawio 桌面包内嵌 | 完全离线、交互完整 | 体积上百 MB；`.drawio` 成第二真相源（违 ADR-030）；打包与升级成本高 | ❌ 否决 |
| D. 自研私有 JSON 交换格式 | 完全可控 | 生态为零——用户要的是「能在 drawio 里排版」，私有格式拿不到任何外部编辑器支持 | ❌ 否决（用户诉求落空） |

## 影响

**变得更容易**

- 用户可在 drawio 桌面版完成排版 / 拼图 / 打印，InkFlow 侧零改动、零依赖、零体积增长
- 「导出 → 外部整理 → 导入」链路可离线全流程走通
- 后续若要做其它图编辑器（yEd / diagrams.net 网页版）互通，同一 mxGraph XML 格式可复用

**变得更难 / 需注意**

- **导入不是全保真**：实体（角色/世界观/…）本身不由 drawio 文件创建——文件里只能在**已存在**的实体之间建立关系；
  手工在 drawio 里新画、未携带 InkFlow 实体标识的节点会在导入时被**跳过并回报**。
- **`.drawio` 里的排版（坐标）不回流**：节点位置是 GUI 视图态（`localStorage`），不是关系数据，导出只是给出一个确定性初始排版。
- **导入的 `replace` 模式具破坏性**：会先清空项目内既有关系再写入文件内容（GUI 侧需二次确认）。属用户显式选择，非默认。
- **格式细节属实现契约**：节点/边到 mxGraph cell 的映射、往返幂等判据写入 `specs/f48-knowledge-graph/spec.md` §5.7，
  后续若要改格式，须同步该 spec（本 ADR 不复制格式细节，避免漂移）。
- **XML 解析安全**：本工具为本地单用户、输入为用户主动选择的本地文件；使用标准库 `xml.etree.ElementTree`
  （不解析外部实体）。若未来把该端点暴露给远程调用方，需先引入 `defusedxml`（届时另开 ADR）。
- **后续（未承诺）**：drawio「导出为 XML + Compressed」产出的 base64+deflate 压缩体本 v1 不解析——
  返回 422 且在错误信息中点明「压缩」（`.drawio` 的默认保存形态是**未压缩** XML，主流程不受影响）。
  若日后需要，可用标准库 `zlib` + `base64` 解压后再走同一解析路径（无新依赖）。
