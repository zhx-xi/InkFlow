# ADR-011: 异步无阻塞架构

> **状态**: ✅ 已接受（不变）
> **日期**: 2026-07-30
> **来源**: design/architecture-analysis-2026-07-30.md §三 ADR-011
> **依据**: Constitution 技术约束（FastAPI async、SQLAlchemy 2.0 async）

## 背景

LLM API 调用延迟 5-30s，RAG 检索、流式输出（SSE）都需要非阻塞 IO。同步阻塞会让 API 并发能力趋近于 1。

## 决策

全链路异步：FastAPI async 路由 + SQLAlchemy 2.0 async（aiosqlite）+ 异步 LLM 客户端 + 异步流式生成（SSE）。CLI 层通过 `asyncio.run()` 复用同一套异步 Service。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| 全链路 async（选定） | LLM 长调用不阻塞、SSE 流式、并发高 | async/await 学习成本 |
| 同步 + 线程池 | 代码简单 | 线程切换开销、SSE 实现复杂 |
| 同步（单用户场景） | 最简单 | 一次 LLM 调用阻塞一切 |

## 影响

- ✅ LLM 调用期间服务器保持响应（健康检查、其他请求）
- ✅ SSE 流式输出实现自然（async generator）
- ❗ 所有 IO 操作必须 async，禁止在 async 函数中调用阻塞库（需 CI 纪律）
