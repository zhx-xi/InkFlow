# ADR-012: 错误处理策略

> **状态**: ✅ 已接受（v2.0 扩展 LLM/RAG 异常类型）
> **日期**: 2026-07-30（v2.0 更新：2026-07-31）
> **来源**: design/architecture-analysis-2026-07-30.md §三 ADR-012

## 背景

领域错误（资源不存在、业务规则违反）与基础设施错误（网络、LLM API、数据库）需要区分处理：前者返回明确的 404/422，后者应可重试并避免泄漏内部细节。

## 决策

- 领域异常（`NotFoundError` 等）→ API 层映射为 404/422 响应
- 基础设施异常 → 包装为领域可见错误，记录日志，API 返回 500（不泄漏堆栈）
- 统一异常层级：`inkflow.domain.exceptions` 定义领域异常基类

**v2.0 新增异常类型**：
- `LLMRequestError`: LLM API 调用失败（网络/超时/Provider 错误）
- `ContextBudgetExceededError`: Token 预算超限
- `AgentPipelineError`: Agent 管线执行失败
- `VectorStoreError`: 向量库操作失败
- `PromptRenderError`: Prompt 模板渲染失败

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| 领域异常层级（选定） | 语义清晰、API 映射明确 | 异常类数量增长 |
| 裸异常透传 | 零代码 | 内部细节泄漏、无重试语义 |
| 返回码/Result 类型 | 显式 | Python 生态不自然，样板多 |

## 影响

- ✅ 错误语义跨三界面一致（CLI 打印友好消息，API 返回标准状态码）
- ✅ 可针对不同异常类型配置重试策略
- ❗ 新模块需遵守异常定义规范（Constitution §4）
