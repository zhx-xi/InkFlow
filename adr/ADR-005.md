# ADR-005: LLM Provider — LiteLLM 统一对接（v1.0，已弃用）

> **状态**: ⛔ 已弃用 · 被 [ADR-005v2](ADR-005v2.md) 取代
> **日期**: 2026-07-30（弃用于 2026-07-31）
> **风险等级**: 🟡 低（未实现，无迁移成本）
> **来源**: design/architecture-analysis-2026-07-30.md §三 ADR-005

## 背景

PRD 要求 ≥ 3 个 Provider（OpenAI、DeepSeek、Ollama），不同任务路由不同模型。需要统一抽象层避免每 Provider 一套代码。

## 决策（v1.0）

薄 Protocol 包装 LiteLLM，约 50 行代码覆盖 100+ Provider：

```
domain/ports/llm_client.py  ← LLMClientProtocol
infrastructure/llm/litellm_client.py  ← LiteLLMClient（内部直接调用 litellm）
```

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| 薄包装 LiteLLM（v1.0 选定） | 最轻量、Provider 覆盖广 | 无 callback 体系、无 LangSmith 追踪、无 LCEL 组合能力 |
| LangChain ChatLiteLLM（最终选定） | 生态完整、可观测性 | 多一层依赖（见 ADR-005v2） |
| 每 Provider 一个类 | 原生集成 | 切换模型需改代码 |

## 弃用原因

LiteLLM 裸调方案虽然轻量，但缺乏 LangChain 生态的 callback 体系、LCEL 管道组合能力和 LangSmith 调试追踪，限制了复杂 Agent 管线的可观测性和可组合性。被 ADR-005v2（LangChain ChatLiteLLM）取代。

## 影响

- ⛔ 本决策未实现，无迁移成本
- ✅ 保留价值：记录了"为什么不用最轻方案"的完整上下文
