# ADR-006: Agent 编排 — 管道链模式（v1.0，已弃用）

> **状态**: ⛔ 已弃用 · 被 [ADR-006v2](ADR-006v2.md) 取代
> **日期**: 2026-07-30（弃用于 2026-07-31）
> **风险等级**: 🟡 低（未实现，无迁移成本）
> **来源**: design/architecture-analysis-2026-07-30.md §三 ADR-006

## 背景

PRD 要求 Architect → Writer → Auditor → Reviser 链式执行（F4），且后续规划用户自定义 Agent 管线（DAG + 条件分支）。

## 决策（v1.0）

自定义 Pipeline 链模式：手写阶段类 + 顺序执行器 + 自建拓扑排序/并行调度/日志追踪。

## 弃用原因

Phase 2 的 DAG 升级需要重写拓扑排序与并行调度；可观测性、Checkpointing、错误处理全部需要自建。LangGraph StateGraph 从顺序链到 DAG 的渐进式升级成本远低（改 `add_edge` → `add_conditional_edges`）。被 ADR-006v2 取代。

## 影响

- ⛔ 本决策未实现，无迁移成本
- ✅ 保留价值：记录"为什么不自研管线"的对比依据（见 ADR-006v2 对比表）
