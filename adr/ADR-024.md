# ADR-024: 云架构拓扑 — 双前缀单体 + owner_id 隔离 + 拆分预留

> **状态**: ✅ 已接受
> **日期**: 2026-08-02
> **风险等级**: 🟡 中（云端 1.0 Gate 项明确，前置工程投入已列）
> **来源**: design/security-analysis-cloud-2026-08-02.md（D1-D6 安全裁决）、design/product-positioning-analysis-2026-08-02.md（§3 裁剪评估 / §4 MVP / §5 协作后移）
> **依据**: Issue #65（2026-08-02 产品形态批量拍板，云端端 12 项）+ ADR-001（模块化单体）+ ADR-013（本地 RAG = Chroma）+ ADR-019（版本里程碑）

## 背景

云端 = **云存档 + 异地写作**（单机的远程形态，不是协作平台，更不是另一款产品）。单人开发、成本敏感：任何「多一套部署/多一项常驻成本」的方案都直接与约束冲突。

2026-08-02 Issue #65 对产品形态一次性批量拍板（安全视角裁决见 `security-analysis-cloud-2026-08-02.md`，产品视角裁剪见 `product-positioning-analysis-2026-08-02.md`）。本 ADR 固化云端端的架构拓扑与安全边界，作为云端实现（版本 2.0.0 云端里程碑）的架构依据。

## 决策

### ① 同一 FastAPI 应用双路由前缀 + 拆分预留

- 单进程双前缀：`/api/v1/*`（用户端）+ `/admin/*`（管理后台），**共享 domain/infrastructure**，差异仅在认证与路由。
- 管理后台与用户端同应用（同进程、同 compose 部署），但**认证完全隔离**：admin token 与用户 token 不同 issuer/audience、不可互认（以认证隔离 + 独立 DI 达成安全分析 §4.1「管理面与用户面隔离」的意图，不引入第二套部署）。
- **预留拆分后路**：user/admin 路由各自独立模块包（`api/user/*` 与 `api/admin/*`）+ **独立 DI 装配** + **独立认证依赖**——未来流量/复杂度增长时可拆为两个进程或两个应用，**domain 零改动**。
- **拆分触发器**（满足任一即评估拆分；写死触发条件，避免事后凭感觉决策）：
  1. **管理功能复杂度**：管理端出现独立发布/回滚需求，或管理路由与用户路由的耦合使单应用修改互相阻塞；
  2. **独立扩容需求**：用户面流量增长需单独扩/缩容，或管理面需独立部署环境（如内网隔离）。
  - 拆分只动装配层与进程边界（FastAPI app 实例 / uvicorn 进程），domain/service/repository 零改动。

### ② 多用户数据隔离：聚合根 owner_id + Repository 层强制过滤

- 所有聚合根（Project/Chapter/Volume/Character/World/Outline/TimelineEvent/Foreshadowing/…）加 **`owner_id`**（= user_id 级归属；无租户/组织概念，单租户多用户）。
- **数据作用域下沉仓储**：Repository 层强制按 owner 过滤（仓储基类统一注入 `WHERE owner_id = ?`，禁止逐处手写）——**防水平越权**；越权一律 404（防枚举探测，安全分析 §3.2）。
- **云端 1.0 Gate 项**：owner_id 强制过滤落地 + 越权测试矩阵（用户 A token 访问用户 B 全部资源端点 → 全部 404/403，与业务测试同等 CI 强制）为云上线前置门槛。
- 本地单机模式无 owner 概念：owner_id 固定为本地默认值（LocalTrust 身份），本地路径零改动。

### ③ 功能安全边界（云端 1.0 = 版本 2.0.0 云端里程碑）

| 类别 | 云端 1.0 形态 | 级别 |
|------|--------------|------|
| 数据与配置类全部功能（项目/章节/角色/世界观/大纲/时间线/伏笔/会话/搜索/导出/回收站·修订历史） | ✅ 上云 | — |
| AI 写作管道 + 内置 Agent 编排 | ✅ 上云（BYOK 计费 = 成本闸门） | — |
| **自定义 skill 任意代码** | ❌ **本地专属，云端永不执行**（可执行体在同步层拒收） | **P0 红线** |
| **LLM API Key** | ❌ **云端零存储、不经手 Key 流量**——BYOK 客户端直连：写作 LLM 调用在本机发起，云端只做任务编排与结果存档 | **P0 红线** |
| daemon 定时写作 | ❌ 云端不提供执行调度（常驻定时任务 = 滥用面 + 计费失控风险）→ **daemon 本地跑 + 云存档** | 后移（改形态） |
| 平台托管 Key（云端代理） | 后移 P2（仅未来「纯 Web 免安装」需求出现时再评估，须 KMS + 全量审计 + 可吊销） | P2 |

### ④ 自定义 skill：白名单上云 + 内容审核

- 云端 skill = **Prompt 模板 + 自定义 Agent 角色 + 内置工具白名单 + 参数化 DAG**（纯 Prompt 白名单，结构上消灭 RCE 面）；**可执行体云端拒收**（SyncProtocol payload 白名单，安全分析 §3.3 S4）。
- **内容审核**：云端 skill 内容（含 AI 生成内容）经 **AI 自动审查 + 人工抽检**；**审核队列进管理后台（P1）**，拦截涉黄/违规内容，违规即下架/拒发布。

### ⑤ 云端 RAG：PostgreSQL + pgvector

- 云端 RAG 向量库 = **PostgreSQL + pgvector**（与业务同库，**零额外部署、零额外运维成本**）；独立向量库拆分（专用实例/托管服务）**留到有收入后评估**。
- 本地单机保持 **Chroma**（ADR-013 不变，本地路径零改动）。

### ⑥ 部署形态：Docker Compose 单机 VPS

- 单机 VPS + Docker Compose 编排：**nginx + API（FastAPI）+ 前端静态 + PostgreSQL（+pgvector）+ MinIO**（S3 兼容对象存储）；**管理后台同机**（同 compose、同进程，双前缀路由）。
- 不做微服务、不做 Kubernetes（与 ADR-001 模块化单体一致）；加密备份 + 恢复演练纳入上线 checklist。

### ⑦ SyncProtocol 语义修订：云存档 / 远程在线模式

- 云端语义 = **云存档 + 远程在线**：用户经 web/GUI 远程**直接操作**云端数据（在线读写，非离线副本合并）；冲突模型 = **LWW（最后写入胜出）+ 修订历史**（误操作可回滚），**无需 CRDT/OT**。
- **双向离线同步（断网本地缓冲、恢复后补同步）降级为可选**（后续评估，MVP 不做）。
- 接口签名不变（`push/pull/rev`）；云端实现补充安全要点：rev 服务端签发（防伪造/重放）、归属校验、payload 白名单（拒收 skill 可执行体）、限流、审计（安全分析 §3.3 S1-S8）。

### ⑧ UserProtocol 修订：多用户数据隔离优先，协作后移

- 云端语义 = **多用户数据隔离（user_id 级）**（无组织/共享/邀请模型——**多人协作独立立项、后移**）。
- 接口签名不变（`UserProfile.tenant_id` 字段保留默认值，云端实现固定该值、不使用租户概念）。

## 备选方案

| 方案 | 优点 | 缺点 | 裁决 |
|------|------|------|------|
| **双前缀单体（选定）** | 单人运维一套部署；共享 domain；拆分后路保留 | 单进程故障影响全局（单机部署本就如此，可接受） | ✅ 选定 |
| user/admin 独立服务 | 故障隔离、独立发布 | **单人运维翻倍**（两套部署/监控/升级/备份） | ❌ 否决 |
| 容器沙箱上云 skill | 保留完整自定义能力 | **单人运维成本高**（镜像构建链/CVE 跟踪/版本升级）+ **RCE 面仍在** | ❌ 否决 |
| 平台托管 Key（云端代理） | 云端全自动写作体验 | Key 集中 = 单点蜜罐；泄露面 = 云服务器+DB+日志 | ⏸️ 后移 P2 |
| 独立向量库（专用实例/托管服务） | 与业务库隔离 | 额外部署 + 持续成本（成本敏感直接冲突） | ⏸️ 有收入后评估 |

## 影响

- ✅ 与 ADR-001 模块化单体一致：同进程双前缀起步，演进路径清晰（按拆分触发器拆进程，domain 零改动）
- ✅ p0-11 六协议**全部保留签名不变**（UserProtocol/SyncProtocol 仅语义修订，接口投资不浪费）
- ✅ 本地路径零改动（本地 = Chroma RAG / 单用户 / 免认证 / daemon 本地跑，与现状一致）
- ❗ **云端 1.0 Gate 项**（上线前置门槛）：① owner_id 仓储强制过滤 + 越权测试矩阵；② 管理后台最小 RBAC + 审计 + MFA；③ skill 白名单执行 + prompt 静态扫描 + 内容审核队列（P1）；④ SyncProtocol 安全化（rev 签发/限流/审计）
- ❗ 拆分预留要求路由层纪律：user/admin 独立模块包 + 独立 DI 装配 + 独立认证依赖，禁止相互 import
- ❗ 前端一套代码两用：云 Web 部署 + GUI 内嵌（Electron GUI 壳 + 本地 REST 内核）
- ❗ 云端上线前本地先行整改：废除 APIKey 明文模式、本地端口防 CSRF（安全分析 §2.2/§5 C6）
