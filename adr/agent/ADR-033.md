# ADR-033: 预算护栏数值 — max_steps=12 / token 32K / 同工具连续调用上限 3（F27 实现实测定稿）

> **状态**: ✅ 已接受
> **日期**: 2026-08-03（待定稿）；2026-08-10（F27 实现实测定稿）；2026-08-12（落盘）
> **风险等级**: 🟡 中（数值直接影响 agentic 成本与行为上限）
> **依据**: Agent 化升级路径 v1.1 §4 Stage 1（token 消耗 3-8 倍 → 预算护栏）+ F27 spec §5.4（Q2 拍板：选项 A + 设置可改，2026-08-10）+ F27 实现实测
> **原编号**: ADR-C（design/agent-upgrade-path-2026-08-03.md §5 架构决策点）

## 背景

agent 循环（ReAct）token 消耗为 deterministic 的 3-8 倍，弱模型可能空转/重复调用；无上限则单次 run 成本失控。升级路径 v1.1 将预算护栏数值标记为 🔲 待定（「待 Spike 0 实测后定稿」），F27 spec Q2 拍板确认数值且允许全局设置覆盖。

## 决策

**默认值（F27 实现实测定稿）**：

| 护栏 | 默认值 | 语义 |
|------|--------|------|
| `max_steps` | **12** | agent 循环最大步数（LLM 调用 + 工具执行轮次） |
| `token_budget` | **32K** | 单次 run token 预算上限 |
| 同工具连续调用上限 | **3** | 同一工具连续调用次数上限（防振荡/空转） |

- **可配置**：全局设置可更改（F32 app_settings 扩展键：`agent_max_steps` / `agent_token_budget` / `agent_max_consecutive_tool`，用户拍板 2026-08-10）。
- **读取优先级**：请求体显式字段（`--max-steps` / `--token-budget`）> 全局设置 > 默认值。
- 触达任一护栏 → 强制终止并标记 `terminated_by_guardrail`（语义见 ADR-034），产物保留。

## 备选方案

| 选项 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **12 / 32K / 3（选定）** | 与 F27 实现/测试一致；覆盖典型写作 run 场景 | 极端长章可能触达上限 | ✅ Q2 拍板（选项 A + 设置可改） |
| 更高上限（如 24 / 64K） | 长任务更宽松 | 成本失控风险高；弱模型空转窗口大 | ❌ 否决 |
| 无护栏 | 零限制 | 成本失控；无强制终止路径 | ❌ 否决（token 3-8 倍风险） |
| 固定不可改 | 实现最简单 | 用户无法适配自身模型/场景 | ❌ 否决（2026-08-10 用户拍板设置可改） |

## 影响

- ✅ 单次 agentic run 成本有硬顶（32K token）
- ✅ 数值实现可测：`test_settings_models.py` / `test_settings_service.py` 实证设置键默认值 12/32K/3
- ✅ 用户可通过全局设置适配（弱模型需更小步数、强模型可放宽）
- ❗ 数值属于产品参数，后续随实测修改走 ADR 修订流程（同日可多次升版）
- ❗ F29 Supervisor 步数上限 30 为独立数值（路由振荡护栏），与本 ADR 的 max_steps 语义不同
