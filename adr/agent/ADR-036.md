# ADR-036: 写工具形态 — 内部自定义工具 save_draft（草稿机制 + 用户确认后生效 + 三条工程约束）

> **状态**: ✅ 已接受
> **日期**: 2026-08-03（拍板）；2026-08-12（落盘）
> **风险等级**: 🟢 低（进程内函数，无跨进程复杂度）
> **依据**: Agent 化升级路径 v1.1 §4 Stage 1（写工具形态用户拍板）+ 架构不变式（内部工具 = 进程内函数调 service，非 MCP）+ F27 spec §5.2/§5.3
> **原编号**: ADR-F（design/agent-upgrade-path-2026-08-03.md §5 架构决策点）

## 背景

agent 需要写能力，但**不能让 agent 直接写正式章节**——用户会失去控制感；且用户确认/修改动作是 F28 记忆系统（判据 E「越用越智能」）的事件源，直接写正式章节则无事件可捕。同时架构不变式要求：内部 agent 工具 = 进程内函数调 service 层（自定义工具，非 MCP——MCP 是跨进程协议，为外部 agent 设计；内部用 MCP 纯增开销）。

## 决策

- **形态**：写工具 = **内部自定义工具 `save_draft`**（进程内函数调 service 层），非 MCP；F20 时同一批 service 薄适配暴露 MCP（工具同源）。
- **草稿机制**：agent 只写草稿（`draft` 状态），**用户确认后才转正式章节状态**（draft → confirm → 正式章节）——控制感在用户手里，同时用户确认/修改动作成为 F28 记忆系统的数据源。
- **三条工程约束（用户拍板补充）**：
  - ① 调 service 层**不碰 ORM**（字数统计/状态流转等领域规则不破坏）；
  - ② **单工具单事务**（agent run 是长任务，不跨工具事务）；
  - ③ 写操作**落审计日志**（谁/何时/改了什么）。
- 落库点：`infrastructure/agent/tools/save_draft_tool.py`，经 draft_service + chapter_service + audit_log_service。

## 备选方案

| 选项 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **save_draft 自定义工具 + 草稿机制（选定）** | 用户控制感；F28 事件源；service 层规则不破 | agent 产出需确认步骤 | ✅ 用户拍板 |
| MCP 写工具 | 跨进程协议一致 | 内部使用纯增开销；F20 才需要外部面 | ❌ 否决（F20 再做，工具同源） |
| agent 直接写正式章节 | 少一步确认 | 用户失控；F28 无事件源 | ❌ 否决 |
| agent run 级大事务 | 原子性最强 | 长任务持锁风险 | ❌ 否决（单工具单事务） |

## 影响

- ✅ 用户控制感：agent 产出草稿 → 用户确认/修改 → 正式生效
- ✅ F28 事件源就绪：草稿确认/修改/拒绝动作天然产生 diff 事件
- ✅ 领域规则（字数/状态流转）在 service 层保持（约束①）
- ✅ 审计可追踪（约束③）+ 事务隔离（约束②）
- ❗ CLI/API 需暴露草稿管理面（list/confirm/reject）；GUI 侧草稿 UI 后续迭代
- ❗ F20 MCP 工具同源：MCP 复用 save_draft 工具定义
