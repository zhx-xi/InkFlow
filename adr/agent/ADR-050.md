# ADR-050: Chat Agent 工具面分层演进 — 层级化工具矩阵 + 域×CRUD Scope（分阶段方案 D）

## 状态

✅ 已接受（2026-09-06 用户拍板，Phase 1 归 0.13.0；Phase 2 预备案不排期）

## 背景

Chat agent 工具面现状（26 可勾选 + 9 核心）存在三个结构性问题：

1. **大纲层级压参**：`create_outline(level, parent_id)` 要求 LLM 持有父级 UUID，但工具面无大纲读工具 → 层级写入（卷纲/章纲）实际不可达；`level` 默认 `"overall"` 是误操作陷阱。
2. **情节点空白**：plot points 有 API/CLI，无任何 agent 工具。
3. **授权表达落后**：`tool_ids` 按工具名平铺勾选，无法表达"按功能域授权操作类型"；工具面扩到 40+ 后不可维护。

曾评估的候选（2026-09-06 架构讨论）：

- **A1 元工具 + 通用 dispatcher**（渐进式加载，`invoke_tool(name, args)`）
- **A2 发现式动态重绑定**（域元工具发现后，下一轮注入该域真实 schema；镜像 MCP 面 `tool_search` 形态 / Anthropic Tool Search Tool）
- **B 全量静态列出 + 前后缀命名约定**
- **C action 聚合门面**（镜像 MCP `manage_outline`）

关键认知修正：**"按命名规则让 agent 自动获取工具"不成立**——LLM 可调用面 = 请求 `tools` 字段声明的 schema 集合，未声明即运行时不可发现。命名约定只服务于人（GUI 分组）与映射表，不服务于模型。

## 决策

采用 **方案 D：分阶段混合**。

### 1. Phase 1（0.13.0）：静态工具矩阵 + grants scope

- 大纲域按层级拆为具体工具（`create_overall/volume/chapter_outline` 等，父级**按名解析**取代持 UUID），补 `list_outlines`/情节点 CRUD（工具清单见 F58 spec §2.3）。
- 其他域**只补真实读缺口**（get/list），不机械对齐全矩阵（角色/时间线/伏笔/记忆是平面实体）。
- 授权模型 `grants: {domain × [read|write|delete]}` 替代 `tool_ids`（GRANT_TOOL_MAP 为唯一真相源），GUI 改 GitHub API-key 式勾选矩阵。
- **双闸保留**：delete scope 只控暴露，运行时 ask_once 会话确认（ADR-043）叠加不变。

### 2. Phase 2（预备案，触发条件见 F58 spec §7）：A2 动态重绑定

同样这批工具，装配方式从"scope 全量静态注入"改为"域元工具发现后按需注入真实 schema"。工具形态在 Phase 1 固化后，Phase 2 零返工。

### 3. 明确否决

- **A1**：dispatcher 的 `args` 自由 JSON 丢失 per-tool input_schema 校验与 F57 按工具名归因埋点，对以设置库写入为核心的 InkFlow 得不偿失。
- **B（全量+命名自动获取）**：自动获取是幻觉，全量 = token 全付 + 选错率随面增大而下降。
- **C（action 聚合门面）**：层级 × action × parent 参数组合爆炸，条件校验复杂度高于拆工具。
- **根工具（通用 `create_outline`）继续暴露**：Phase 1 后从 agent 面下线（保留服务层实现），杜绝 level 陷阱。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A1 dispatcher | 初始 prompt 极小 | 丢 schema 校验/归因；文档依赖模型纪律 | ❌ 否决 |
| A2 动态重绑定 | token 省 + 校验保 | 改 harness 装配环，风险最高 | ✅ Phase 2 终态 |
| B 全量静态 | 实现最简 | token 痛、选择准确率差 | ❌ 否决 |
| C 聚合门面 | 工具数少 | 参数组合爆炸 | ❌ 否决 |
| D 分阶段（本决策） | 形态/机制解耦、分期摊风险、scope 独立可交付 | 两阶段周期拉长 | ✅ 采纳 |

## 影响

**变容易**：
- LLM 无需持有 UUID 即可写层级（父级名解析）；情节点进入 agent 可操作面。
- scope 矩阵与工具形态解耦：未来加工具 = GRANT_TOOL_MAP 登记一行。
- 存量 `tool_ids` 借迁移窗口一次性换算为 grants。

**变困难 / 风险**：
- 工具目录 26 → ~40，内置 agent 模板、GUI 勾选、审计 i18n 词条、契约测试数量断言全量跟改（拆 5 个 issue 分批）。
- 反查迁移规则（`create_outline` → 三个层级工具）本质是**授权扩权**（旧 1 工具 → 新 3 工具），需在 spec 明示并经用户侧知悉。
- Phase 2 启动时需回归全部 Phase 1 工具装配测试（harness 装配环改动）。

**关联**：取代 ADR-043 中"自定义 agent 按 tool_ids 逐个勾选"的授权交互形态（其 ask_once 删除授权模型继续有效）；依赖 ADR-035 deepagents harness（Phase 2 改动集中处）；实现 F58 spec。
