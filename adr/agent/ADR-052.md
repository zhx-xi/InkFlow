# ADR-052: Agent 工具 DB 锁 per-loop 发放 + writer adapter async 优先（#953 死锁修复）

## 状态

已接受（2026-09-06，随 PR #<n> 落地；关联 #837 / #929(PR #935) / #953）

## 背景

0.13.0 两个已合入机制相撞导致 `book run` P0 死锁（#953）：

1. **#837**：agent 工具共享请求级 `AsyncSession`，deepagents Send API 并行分发 tool_calls 会交错破坏事务状态机 → 引入**模块级 `asyncio.Lock` 单例**（`infrastructure/agent/tools/_tool_db_lock.py`），前提是「所有工具协程在同一事件循环交错执行」。
2. **#935**：`_make_sync_wrapper`（harness.py）在 ToolNode sync 路径（检测到运行中循环）用 **worker 线程 + `asyncio.new_event_loop()`** 跑工具协程，规避打包版 `asyncio.run` 嵌套崩溃。

`asyncio.Lock` 惰性绑定首个 acquire 它的循环。book run 派发链 `DeepAgentInvokeAdapter.invoke`（agentic_writer.py）在 **async 上下文内同步调 `graph.invoke`** → 内层图跌入 sync 路径 → 工具协程落入新循环 → acquire 宿主循环已持有的模块锁 → `RuntimeError: bound to a different event loop`，协程永久悬挂，run 无终态。锁报错只是表层：Lock/AsyncSession/aiosqlite 连接全部绑循环，**跨循环共享请求级 session 本身就是数据竞争**。

实证探针（langchain 1.3.14 / deepagents 0.7.5 / langgraph 现版，Python 3.13）：

- coroutine-only 工具在 sync `graph.invoke` 下抛 `NotImplementedError: StructuredTool does not support sync invocation` —— harness 中「M5 实测缺陷」注释**仍然成立**，`_map_tools` 的 func 双通道不能删（排除纯「消灭双通道」方案 C）。
- `await graph.ainvoke` 下工具协程**全程宿主循环**执行，func 不触发 —— async 路径可行。

## 决策

1. **adapter async 优先（主收敛）**：`DeepAgentInvokeAdapter.invoke` 探测 inner 具备真协程 `ainvoke`（`inspect.iscoroutinefunction`）时 `await ainvoke(...)`，使 book run 卷轨/agentic 轨工具协程回到宿主单循环，恢复 #837 前提；无 async 能力的鸭子（MagicMock/旧替身）回退既有同步分支，行为零破坏。
2. **锁发放改 per-event-loop（组合项）**：`_tool_db_lock.py` 提供 `get_tool_db_lock()`，按当前 running loop（`WeakKeyDictionary`）发放锁；同循环内仍一把锁（#837 串行语义不变），跨循环各自持锁不再抛绑定错。无 running loop（CLI/MCP 同步线程）→ 回退模块属性 `_tool_db_lock` 兜底锁（兼容既有测试重置形态）。24 锁点消费方机械替换为 `async with _tool_db_lock_mod.get_tool_db_lock():`，保持模块属性引用形态。
3. **启动 reconcile**：内核 lifespan 启动钩子将遗留 `writing_plans.status='running'` 归位 `failed` + `progress_reason`（#456 running 落库的反向对账），重启即自愈。
4. **sync 桥保留为兜底**：仅供真实无循环线程（CLI 直跑工具）使用；「async 上下文同步调图」的暴露入口已由决策 1 从根上封死。**禁止**新增在运行中循环内同步调图的代码路径。
5. 明确**否决**：仅 per-loop 锁不收敛循环（=单独方案 A，跨循环并发读写同一 session 是不报错的数据损坏）；thread-per-run 为桥工具新建 session（=方案 B，需重排全部工具装配闭包，复杂度不成立，且被决策 1 取代后无必要）。

## 备选方案

| 方案 | 优点 | 缺点 | 裁决 |
|------|------|------|------|
| A. 仅 per-loop 锁 | 改动最小 | 跨循环共享 session 数据竞争仍在（静默损坏） | ❌ 单独否决，作组合项采纳 |
| B. 桥内独立 session（thread-per-run） | 保留桥 | 装配闭包全重排；锁语义复杂化 | ❌ 否决 |
| C. 消灭双通道（删 func） | 理想最干净 | coroutine-only 在 sync 图调用必抛 NotImplementedError（探针实锤上游未变）；且 deepagents 中间件层可能仍探测 func | ❌ 否决，取其内核：adapter async 优先（=C1） |
| C1 + A + reconcile（本决策） | 主链回宿主循环根治；锁面纵深防御；遗留态自愈 | 双机制并存需契约钉死（本 ADR） | ✅ 采纳 |

## 影响

- ✅ book run stage6 崩溃面根除（RED-2 集成契约钉死：桥路径草稿必落库 + session 事后无污染）。
- ✅ 既有 #837 五契约测试（同循环串行、模块单例语义）零改动保持——`get_tool_db_lock()` 在同循环仍返回同一把锁。
- ✅ run 卡死黑洞三层封堵：C1 灭挂起源 / 异常链既有映射【G】固化 / 重启 reconcile 自愈。
- ⚠️ 新约定：**工具协程不得在跨循环环境触碰请求级共享对象**（session/engine）；adapter 层探测式 async 化对「inner 提供假 ainvoke（MagicMock 自动属性）」安全（`iscoroutinefunction` 判假）。
- ⚠️ 未来 langchain 若支持 coroutine-only sync 兜底，可重评删 func 双通道（届时本 ADR 修订）。
- 后续验收（rc4）：全新内核 `book run` 10/10 章 done + tokens>0（issue 拍板评论终判据），属打包波次，不在本 PR 内。
