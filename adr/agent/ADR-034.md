# ADR-034: 护栏触发语义 — 产物保留 + terminated_by_guardrail 映射 FAILED + 可回退 deterministic

> **状态**: ✅ 已接受
> **日期**: 2026-08-03（拍板）；2026-08-12（落盘）
> **风险等级**: 🟢 低（纯语义约定，无行为歧义）
> **依据**: Agent 化升级路径 v1.1 §4 Stage 1（自主终止双保险）+ F27 spec §5.3/§5.4（guardrail 语义表）+ F27 实现（四重护栏）
> **原编号**: ADR-D（design/agent-upgrade-path-2026-08-03.md §5 架构决策点）

## 背景

agent 循环是长任务，guardrail 触发时**产物不能丢**——若按普通失败处理丢弃半成品，用户损失大（一次 run 数分钟 + token 成本）。需要明确的触发语义：guardrail 不是 HTTP 错误，是受控终止。

## 决策

- **产物保留**：guardrail 触发时已完成内容/草稿**全部保留**（`agent_run` 轨迹快照 + 草稿落库），不视为失败丢弃。
- **状态标记**：`terminated_by_guardrail`，映射现有 FAILED 语义（run 状态记录），客户端按 status 字段分支处理。
- **HTTP 语义**：guardrail 双形态（max_steps / 重复工具 / 空 content / token）均返回 **200** + status=`terminated_by_guardrail`——不视为 HTTP 错误。
- **兜底保存**：LLM 未调 save_draft 就自然终止 → 服务层兜底保存草稿（审计标注 `auto_saved`）。
- **回退路径**：agentic 失败可回退 deterministic——**用户显式决定，不自动回退**（避免掩盖 agentic 缺陷；用户自行选择确定性路径重跑）。
- 空 content 自动重试（附工具结果重申「请输出正文」）→ 仍空则触发护栏。

## 备选方案

| 选项 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **产物保留 + 200 + status 字段（选定）** | 用户零损失；客户端分支清晰；与现有 API 信封一致 | 调用方需处理 status 分支 | ✅ 用户拍板 |
| 硬失败丢弃产物 | 语义简单 | 用户损失（分钟级 run + token 成本）；与「产物保留」原则冲突 | ❌ 否决（F27 spec §5.3） |
| guardrail 映射 HTTP 4xx/5xx | 符合「失败即错误」直觉 | 客户端需按错误处理；与 guardrail 受控终止本质不符 | ❌ 否决 |

## 影响

- ✅ F27 四重护栏（repeat_tool / max_steps / empty_content / token_budget）统一语义
- ✅ API 契约稳定：`/writing/agentic/` 恒 200 + status 字段（guardrail 双形态）
- ✅ 产物保留使 F28 记忆系统有完整事件源（草稿确认/修改/拒绝）
- ❗ 客户端（GUI/CLI）必须识别 `terminated_by_guardrail` 状态展示给用户
- ❗ 自动回退被明确否决——deterministic 兜底由用户显式触发
