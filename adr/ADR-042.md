# ADR-042: LangSmith 可观测性追踪接入

## 状态

已接受（2026-08-24，用户拍板方案 C）

## 背景

InkFlow 的 LLM/Agent 栈为 LangChain 1.3.14 + LangGraph 1.2.10 + deepagents 0.7.5，deepagents 构建于 LangGraph。调试 agent 行为（工具调用、模型交互、决策点、子 agent）时，缺乏端到端可视化执行视图。LangSmith 提供纯 env 驱动的 trace 捕获（`LANGSMITH_TRACING=true` + `LANGSMITH_API_KEY` 即启用，零业务代码），与现有栈天然契合。

源码核实（2026-08-24）：`config.py` 中 `langsmith_api_key` / `langsmith_project` / `langsmith_enabled` 三字段为**纯空壳声明**，从未被任何代码消费；全程无 `LANGSMITH_*` env 设置；`langsmith` 包已传递安装（0.10.15，经 langchain-anthropic 硬依赖）。

## 决策

1. **默认关闭**：`langsmith_enabled=False` 保留现状；仅显式开启才注入 `LANGSMITH_*` env。
2. **注入点**：内核 FastAPI `lifespan()` 启动顶段调用 `apply_langsmith_tracing()`——内核单进程承载 REST API / CLI / MCP 全部 LLM 入口，单一注入点全覆盖，且早于首次 `ChatOpenAI` 实例化。
3. **云 vs 自托管**：先 SaaS（`smith.langchain.com`，免费 key）；新增 `langsmith_endpoint` 字段预留自托管配置位，后续可切。
4. **key 来源**：config 字段（env `INKFLOW_LANGSMITH_API_KEY` 注入），不走 LLM provider 加密 key 库（LangSmith key 非 LLM provider key）；v1 最小化。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **A. 默认关 + SaaS 优先**（采纳） | 内容不上云（按需开）；零部署成本；key 免费 | 需手动开才能追 | ✅ |
| **B. 默认开 + SaaS** | 一装即追 | 小说内容默认上云，隐私风险高 | ❌ |
| **C. 直接自托管 OSS（docker）** | 数据本地 | 要起+维护 docker，个人自用偏重 | ⏸ 后续可切（endpoint 已留） |
| **D. 走 APIKeyManager 加密库存 key** | 符合 LLM key 策略 | LangSmith 非 provider；v1 增加装配复杂度 | ⏸ 范围外（spec §2） |

## 影响

- **使更容易**：调试 deepagents 完整执行链路；观察 token/延迟/工具调用；为后续 evaluation 打基础。
- **使更复杂**：测试须保证 `langsmith_enabled=False` 时 `LANGSMITH_*` 不残留（幂等注入）；启动多一次 env 处理。
- **隐私**：开启时小说内容（prompt/output）上云——已通过「默认关 + 按需开」控制。
- **后续**：自托管切换（`langsmith_endpoint`）、APIKeyManager 加密存 key、evaluation/feedback 均挂后续。
