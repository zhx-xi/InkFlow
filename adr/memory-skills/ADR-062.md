# ADR-062: 内置 Skill 版本化与项目级覆盖

> **状态**: ✅ 已接受
> **日期**: 2026-10-02
> **风险等级**: 🟡 中（播种语义变更；涉及启动路径，但仅文件系统操作、零 DDL）
> **依据**: Issue #1331（v0.15.0-rc4 旅程验证衍生，「明显更好但工作量较大」方案挂 0.16.0）
> **关联**: ADR-039（skills 文件系统真源）· F39 spec（§2.2/§5.3/§12/§13）

## 背景

`ensure_builtin_skills(skills_root)`（`domain/services/skill_service.py`）自 ADR-039 起在
lifespan 播种 6 个内置方法论 skill，规则为「文件存在即跳过」。取证确认（#1331）：

- 用户改过的副本**不会被覆盖** → 不是数据丢失缺陷；
- 但**未改过的副本也永远拿不到升级** → 升级路径完全缺失（同一枚硬币的反面）。

同时暴露两项结构缺陷：

1. 内置内容硬编码为 Python 字符串（`BUILTIN_SKILL_SPECS`），非独立文件 → 无版本标识、
   无法算差异、维护差；
2. 无「项目级同名 skill 优先」的表达（F39 §1.3 原把项目差异留待阶段 2）。

## 决策

### ① 抽离：内置内容 → md 文件（带版本号 frontmatter）

- 落点 `backend/src/inkflow/i18n/skills/builtin/{zh,en}/<slug>.md`（6 份）。
  - **独立子树**，与 `i18n/skills/{zh,en}/`（F19 操作类分发镜像，24 份）**不同域**——
    后者的内容会被同步进随包分发目录 `skills/inkflow/references/`，混入方法论会污染
    外部 agent 的分发面。
- 每份 frontmatter 增 `version` 字段；正文（closing `---` 之后）与原字符串实现**逐字一致**
  （以正文 sha256 黄金基线锚定，独立于实现的数值守护）。
- `BUILTIN_SKILL_SPECS` 保留为模块级符号（形态不变），改为由 loader 从 md 读取；
  Python 内嵌字符串**删除**（杜绝双真相源）。
- en 槽位本期为空、加载回退 zh；英译另开 issue（现状本就无英文方法论，非本决策引入的缺口）。

### ② 播种三态 + 基线文件

- 基线载体 `<skills_root>/.builtin_state.json`：
  `{"<slug>": {"version", "origin_sha256", "user_modified"}}`。
  指纹口径 = `read_text(encoding="utf-8")` 全文的 sha256（文本行尾归一化，跨平台稳定）。
- `ensure_builtin_skills(skills_root) -> int` 三态（返回值语义仍为「本次写入/更新数」，
  既有幂等契约：首次 6 / 重复 0 / 删 1 回补 1）：

  | 情形 | 行为 |
  |------|------|
  | 文件缺失 | 写出最新出厂内容 + 记基线 |
  | 存在且指纹 == 基线（未改） | 出厂内容已变 → **升级**；未变 → 不动 |
  | 存在且指纹 != 基线（**用户改过**） | **保留用户版，不写** |
  | 无基线条目且内容 == 当期出厂 | 记基线，不重写文件 |
  | 无基线条目且内容 != 当期出厂 | 记基线并标 `user_modified=True`（保守冻结，永不自动覆盖） |

### ③ 项目级覆盖（本期落解析面）

- 载体 `data_dir/projects/<project_id>/skills/<name>/SKILL.md`（项目 overlay）。
- `resolve_skill_md_path(name, *, project_skills_root, global_skills_root)`：项目级优先 → 全局。
- `is_project_override(...)`：两端同名并存 → True（冲突可判）。
- **本期不接装配链**：`AgenticWriterDeps.skill_lookup` 现签名为 `(name) -> Skill`，无
  project_id；接线需改 agentic_writer / books.py / _chat_auth.py 三处装配点，回归面大，
  另开 issue 评估。

### ④ 升级可见面

- 服务层 `builtin_skill_status(skills_root)`（name / latest_version / installed /
  installed_version / user_modified / has_update）+ `builtin_skill_diff(name, skills_root)`
  （unified diff，stdlib `difflib`）。
- API `GET /api/v1/skills/builtin/status`、`GET /api/v1/skills/builtin/{name}/diff`
  （两段静态路径，不被 `/{skill_name}` 吞）。
- CLI `inkflow skill status` / `inkflow skill diff <name>`（HTTP 薄层，镜像既有 `skill list`）。
- **未做**（明确下期）：交互式「查看差异 / 接受升级 / 保留自定义」GUI。

## 备选方案

| 方案 | 内容 | 否决理由 |
|------|------|----------|
| A 维持「存在即跳过」 | 零改动 | 升级路径永久缺失：未改副本（绝大多数）永远拿不到新版；#1331 的根本诉求 |
| B 无条件覆盖出厂版 | 简单 | 数据丢失：抹掉用户自定义的方法论（#1331 明令禁止） |
| C 基线落 DB 表/列 | 复用 app_settings | 违背 ADR-039「文件系统为唯一真源」；且引入 DDL 与迁移三形态负担 |
| D 基线内嵌 md frontmatter（自指纹） | 少一个文件 | 用户编辑文件即破坏自指字段（含整段重写/复制场景），判定不可靠；且工厂版与用户版无法区分 |
| E 落 i18n/skills/{zh,en}/ 与操作类同目录 | 少一个目录 | 会被同步进随包分发面 `skills/inkflow/references/`，向外部 agent 泄露无关方法论 → 双真相源 |

## 影响

**变容易**：

- 内置方法论升级可安全传播到「未定制」安装；定制副本有显式 `user_modified` 保护与可见提示。
- 内置内容成为可 diff 的文件资产（版本号进 frontmatter），不再埋在 Python 字符串里。
- `skill_service.py` 体量显著下降（抽离约 11k 字符硬编码 → md）。
- 项目级覆盖具备可测的解析原语，装配接线可增量落地。

**变困难**：

- 播种语义从「纯幂等写」变为「读基线 + 判定 + 可能覆盖」——新增一个状态文件，需在
  备份/同步/迁移场景中一并考虑（该文件非 skill，不应被列表/计数逻辑纳入）。
- 用户「改了又完全改回出厂版」会被永久标记 `user_modified`（保守代价，接受）。
- 基线文件丢失（如用户手工清理）→ 已存在的定制副本会被判为 `user_modified`（保守），
  但纯未改副本也退化为保守保留，需等下一次基线建立后才恢复升级能力。
