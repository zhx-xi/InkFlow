# ADR-037: 记忆提取方式 — 规则化统计（N≥2 阈值）先行，LLM 提取为第二阶段；结构化偏好表（非向量）

> **状态**: ✅ 已接受
> **日期**: 2026-08-03（拍板）；2026-08-12（落盘）
> **风险等级**: 🟢 低（纯规则算法，可解释可测试）
> **依据**: Agent 化升级路径 v1.1 §4 Stage 2（用户拍板建议：先规则化统计）+ 判据 E（越用越智能）+ F28 spec §5.2
> **原编号**: ADR-G（design/agent-upgrade-path-2026-08-03.md §5 架构决策点）

## 背景

判据 E（用户拍板新增）：从用户修改/确认/重新生成行为中学习项目偏好并注入后续生成。但**一次修改可能是试错**——过度泛化会把一次性修改当偏好，污染后续生成。需可解释、可测试、用户可控的提取方式。

## 决策

- **提取方式**：先**规则化统计**（difflib 文本片段比对 + **N≥2 阈值**——同一模式修改出现 ≥2 次才提取为偏好，防过度泛化）；**LLM 提取为第二阶段**（远期，F14 extraction 模式）。
- **存储**：结构化偏好表 `project_preferences`（category/pattern/value/confidence/count/source_events + 时间戳）——**非向量**，用户可查看/删除（可控性）。
- **写入边界**：偏好提取/落库/删除只经 memory_service（调 repo 不碰 ORM，ADR-036 约束①同构）。
- **冲突语义**：偏好与显式设定冲突 → **显式设定（角色档案等）优先级高于学习偏好**。
- **透明性**：`inkflow memory list/remove/stats` +「AI 已记住：称呼主角为 X」式透明提示。
- **事务**：事件记录与内容更新同事务（原子）。

## 备选方案

| 选项 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **规则化统计 + N≥2（选定）** | 可解释、可测试、防过度泛化 | 语义级偏好需 LLM 提取兜底 | ✅ 用户拍板建议 |
| LLM 提取（语义级） | 理解深层偏好 | 不可解释、不可测试；F14 extraction 模式远期才就绪 | ❌ 第二阶段远期（本 ADR 明示） |
| 向量化检索/语义相似偏好 | 检索灵活 | 未排期；偏好是精确规则非相似检索 | ❌ 未排期（非向量结构化表） |

## 影响

- ✅ 一次修改不学、两次学（阈值可测：count==2 落库）
- ✅ 用户可查看/删除已学偏好（可控性，防止过度学习）
- ✅ 显式设定优先于学习偏好（冲突消解确定性）
- ✅ 可解释 AI：规则化提取可单测（preference_learner 纯函数模块）
- ❗ 语义级偏好（「风格偏冷峻」）需等 LLM 提取阶段
- ❗ 修改率/重新生成率下降为 F28 生效证据（对比 F27 基线）
