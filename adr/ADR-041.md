# ADR-041: chat 会话可重放——复用 agent_runs 落 run 决策

## 状态

已接受

## 背景

`#599`（统一执行视图）已把链式（agent_executions）+ agentic（agent_runs）统一到同一面板，但 `#599` §4 明确将「chat 流式会话持久化 run id」列为**范围外（挂后续）**。当前 `chat_agent_service.stream_events`（/chat/agent/stream，走 deepagents ReAct）只把事件转成 SSE 帧、**不持久化**——对话后无法回看 agent 内部步骤/工具调用。本 ADR 决定补齐该缺口。

## 决策

复用 F27 `agent_runs` 表 + `AgentRun/AgentStep/AgentToolCall` 模型，落 chat run（`mode="chat"`）：

- **D1**：每次 `/chat/agent/stream`（一次 prompt → 一次 agent 执行）落一个 `AgentRun(mode="chat")`，复用 `SQLiteAgentRunRepository.create/save`，零迁移。
- **D2**：steps 从 `astream_events v2` 收集——`on_chat_model_end`（完整 AIMessage：content/tool_calls/usage）+ `on_tool_end`（ToolMessage：tool_call_id/name/content）→ 组装 `AgentStep`（每条 AIMessage 一个 step，tool_call 按 tool_call_id 回填 result），镜像 F27 `_build_steps`。
- **D3**：管线 trace **不补 tool_calls**（已核实 `pipeline_nodes._call_llm_node` 是单次 LLM 调用、无工具，`tool_calls=[]` 是正确反映——非缺陷）；管线「reasoning 记 prompt」增强列为后续增值项。
- run_id 经 SSE done 帧回传（`{"type":"done","done":true,"run_id":<id>}`），供前端 #599 渲染。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **复用 agent_runs（D1，选定）** | 零迁移；GET `/agent/runs/{id}` 复用；mode 区分 | chat 与 agentic 同表，mode 需约定 | ✅ 采用 |
| 新建 ChatRun 表 | 语义隔离 | 第二次造执行实体 + 迁移 + 新区块 | ❌ 拒绝（避免重复造轮子）|
| 管线补 tool_calls | 若管线有工具则有益 | **管线无工具**（单次 LLM）→ 伪缺口 | ❌ 拒绝（已核实）|
| 管线 reasoning 记 prompt | 增强可重放 | 需改 pipeline_nodes 透传 LLM 输入 | 🔶 后续增值项 |

## 影响

- **可重放**：chat 对话后经 `GET /api/v1/agent/runs/{id}` 可回看 agent 步骤 + 工具调用 args/result。
- **零破坏**：不建表/不迁移；SSE 帧协议不变（done 帧可加 run_id 字段）；前端 #599 已支持 runId。
- **局限**：steps 收集依赖 `astream_events v2` 事件完整性（on_chat_model_end / on_tool_end）；若 langchain 事件形态变化需同步。
- **可逆**：复用既有结构，可随时停用（不影响 agentic run）。

## 关联
