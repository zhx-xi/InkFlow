# ADR-047: 确定性 LLM 测试服务器 — fake OpenAI（backend/tests/fake_llm）

> **状态**: ✅ 已接受
> **日期**: 2026-09-01
> **风险等级**: 🟢 低
> **依据**: Issue #869（测试三层架构设计缺口 ②）；ADR-005v2（LangChain ChatOpenAI + base_url）、ADR-026（真实 AI CI 开关）、ADR-018（测试分层）
> **替代**: 无（新增决策）

## 背景

InkFlow 的 AI 依赖测试（LLM 调用）目前只有两条路：① 单元层 `dependency_overrides` + Mock（进程内 FakeLLM，ADR-026 背景所述）；② 真实 AI（ADR-026 `run-ai-tests` label + secrets，慢/成本/flaky，默认关）。**缺一条「确定性、黑盒可挂、可复现」的路**——让黑盒 CLI/MCP/GUI（真实内核进程经 HTTP 调 LLM）也能确定性测试，不依赖真实模型。

## 决策

新增**独立性 fake LLM 服务器**：一个 OpenAI 兼容 HTTP 服务，供真实内核的 `LangChainLLMClient`（经 `INKFLOW_LLM_BASE_URL`）调用，按 fixture 回放**正确**与**错误**响应。

### 实际落位（与草案「tests/fake_llm/」差异说明）

最终落位 **`backend/tests/fake_llm/`**，理由：
1. `uv run pytest tests/fake_llm/ -q` 从 `backend/` 执行（`testpaths=["tests"]`）→ 相对解析为 `backend/tests/fake_llm/`。
2. `[tool.coverage.run] omit=["*/tests/*"]` 仅对 `backend/tests/` 生效，fake_llm 服务器代码**不进 coverage-backend 源码口径**（符合测试基础建设定位）。
3. 黑盒 CLI/MCP/GUI 测试（S1+）从 `backend/` 经 `working-directory: backend` 跑，可引用 `../tests/...`；fake server 经 conftest fixture 或 `INKFLOW_LLM_BASE_URL` 注入。

### 结构

```
backend/tests/fake_llm/
├── __init__.py
├── server.py        # FastAPI：POST /v1/chat/completions（JSON + SSE 流式）；app.state.error_counts
├── routing.py       # 按 (model + 请求签名) 选 fixture；select_fixture(model, payload) -> Fixture
├── fixtures/
│   ├── correct/*.json   # 正常 ChatResponse / 流式 chunk / tool_calls
│   └── error/*.json     # 401 / 429 / 500 / 超时 / 空 content / 格式错
└── conftest.py      # fake_llm fixture（threading+uvicorn 起真监听端口，yield base_url）——S1+ 黑盒接入用
```

### 注入点/开关（复用既有，不造新）

- `config.py`（`InkFlowConfig`，env_prefix `INKFLOW_`）加两个字段：
  - `llm_base_url: str = ""` ← `INKFLOW_LLM_BASE_URL`（测试指向 fake server）
  - `e2e_llm_mode: Literal["fake", "real"] = "fake"` ← `INKFLOW_E2E_LLM_MODE`（黑盒测试 fake/真实切换）
- `provider_config.py`：`get_provider_config("fake")` 在**函数体最顶部**短接——`config.llm_base_url` 非空时返回 `LLMProviderConfig(provider="fake", api_key="placeholder-fake-key", base_url=config.llm_base_url, default_model="fake-model")`，**不查注册表、不抛 ValueError（fake 无真实 key）**。
  - ⚠️ **`"fake"` 故意不加入 `_BUILTIN_PROVIDERS`**：`seed_builtin_providers` 遍历 `_BUILTIN_PROVIDERS` 把 fake 当 GUI 内建 provider 持久化（污染 provider_configs 表，实测使 5 个 seed 契约测试 n==4 断言失败）。fake 解析走短接即可，无需注册。
- `LangChainLLMClient._get_chat_model`：base_url = `self._openai_api_base or provider_cfg.base_url`（既有逻辑，无需改）——fake provider_cfg.base_url 即指向 fake server。

### Routing / Fixture 契约

`routing.py` 的 `select_fixture(model, payload) -> Fixture`：
- **签名覆盖优先**：payload 任一 message content 含哨兵 `[[fake-scenario:<scene>]]` → 取 scene（覆盖 model 路由，错误注入用）。
- **主路由按 model**：`fake/correct` / `fake/error-401` / `fake/error-429` / `fake/error-500` / `fake/error-timeout` / `fake/empty` / `fake/malformed` → 对应场景。
- **未知 model** → 默认 correct fixture（不崩）。

`server.py`：
- `app`（module-level）+ `create_app()`；POST `/v1/chat/completions`，支持非流式 JSON + SSE 流式（`data: [DONE]` 结尾）。
- `app.state.error_counts: dict[str, int]`：错误场景计数（key = 场景名，如 `"error-429"`），供重试/退避测试。
- 错误非流式 → 对应 HTTP 状态 + OpenAI error body；错误流式 → SSE error 帧。

### 黑盒三面接入（S1+，不属 S0）

黑盒 CLI/MCP/GUI 测试**本地跑**：`ensure_kernel()`（真实内核）+ `INKFLOW_LLM_BASE_URL` 指向 fake server → 确定性；切 `INNKFLOW_E2E_LLM_MODE=real` 走真实模型（ADR-026）。`fake_llm` uvicorn fixture（conftest.py）在 S1+ 落地。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **独立 fake server（选定）** | 黑盒子进程真 HTTP 可挂；正确/错误 scripted；开关 fake↔real | 新增一个服务 + fixture | ✅ |
| 仅进程内 Mock/FakeLLM（现状） | 零新增 | 黑盒（CLI/MCP/GUI 真内核）挂不上；非端到端 | ❌ 沿用单元层 |
| 一直用真实 LLM（ADR-026） | 保真 | 慢/成本/flaky，默认关 | ❌ 仅真实验证 |

## 影响

- **更易**：AI 依赖测试（agent 链路 / writer 生成 / 流式）在 CI 与本地**确定性**；黑盒三面无需真实模型即可跑。
- **注意**：`config.py` 加 2 字段（源码变更）；`provider_config.py` 加 fake 短接分支（源码变更，须由 `tests/unit/test_fake_llm_config.py` 覆盖，否则 coverage-backend 掉线）；`tests/fake_llm/` 为净新增测试基础设施（不进 coverage-backend，自身覆盖 100%）。
- **S0 契约测试归属**：①-④ 服务器/路由契约 → `backend/tests/fake_llm/`；⑤ config/provider_config fake 分支契约 → `backend/tests/unit/test_fake_llm_config.py`（生产源码单元测试，供 coverage-backend 覆盖）。
- **fake_llm 测试未注册进 CI**（S0 只做服务器 + config 注入点；`backend/tests/fake_llm/` 不在 CI 的 `src/ ../tests/` ruff 路径与 `tests/unit/` pytest 路径内）——S1 黑盒三面接入时随 ci.yml 一起登记。

## S3a 非功能补测：安全 C5 + 超时重试 C4（2026-09-02，PR #873）

> 本文档并入 ADR-047 口径。S3a 给「已具备但未测」的非功能语义补测试契约，并修复
> 测试暴露的 2 处真实缺陷。E2E 不计覆盖（不触及 coverage 门禁）；fake_llm 黑盒经
> `fake_llm` fixture（conftest.py，`backend/tests/fake_llm/`）起真 uvicorn 端口。

### C5 安全

- **C5① 日志/落盘不泄 token**：
  - **真实缺陷**：`AgentRun.steps` 决策轨迹（message_content + tool_calls[].arguments/result）
    会回显工具参数链——若工具参数/结果含密钥形态，steps 落库即泄漏磁盘。`chat_stream/agent`
    端点在发 prompt 给 LLM 前已脱敏（`redact_secrets`），但**未覆盖 steps 回显**。
    决策：新增 `redact_secrets.redact_step(AgentStep) -> AgentStep` 纯函数，在
    `chat_agent_service` 构造每条 AgentStep 时全量脱敏（message_content / tool_calls[].arguments
    递归 dict / tool_calls[].result / reasoning）。
  - **契约锁（已正确，补测试）**：`INKFLOW_READY` 交付行携带的是**内核本地鉴权 token**
    （`INKFLOW_SERVER_TOKEN`，每次启动随机），**不是 provider API key**；且它必须放在
    `INKFLOW_READY`/端口文件里供 Electron 壳解析（`kernel.json` 消费方，spec §2.1），
    **不能掩码/省略**（否则破坏壳鉴权）。故「不泄 token」的落地语义 = **不泄 API key 形态
    （sk-…）+ X-InkFlow-Token 值不入 access log**；明文鉴权 token 作为合法握手保留，
    凭测试断言其不含 `sk-` 形态即契约锚定。⚠️ 反模式风险：把 INKFLOW_READY 的 token
    掩码会破坏 `tests/cli/test_cli_serve.py::test_serve_ready_line_format`（四键）
    与 `tests/cli/test_cli_project.py::test_serve_smoke`（解析 token 鉴权 /health）。
- **C5② F53 脱敏黑盒闭环**：`/api/v1/chat/stream` 端点在发 prompt 前 `redact_secrets`，
  fake LLM（`received_prompts` 记录 wire 收到的 messages）收到的 prompt 无 key —— 已正确
  （contract lock，black-box 实证）。`redact_secrets` 纯函数矩阵补 4 类防御边界，其中
  **3 类真实缺陷**：JSON unicode 转义 key（`sk-\u0041…`）、大小写变体（`SK-`）、
  key 拆词（换行/空格打断连续串）→ Codex 修复 `redact_secrets` 正则。
- **C5③ CORS 来源矩阵**：非法 Origin 无 ACAO / 白名单回显 / 预检白名单 200+ACAO /
  预检非法非 2xx 无 ACAO / `null` 允许 —— 已正确（contract lock，empirically verified）。

### C4 超时重试

- `config.llm_request_timeout=300` / `llm_max_retries=3` 已存在；`provider_config`
  `get_provider_config` 把二者透传给 provider（`max_retries`/`timeout`），LangChainLLMClient
  `${_get_chat_model}` 传入 `ChatOpenAI(max_retries, request_timeout)`。
- **契约锁（已正确，补测试）**：fake server `error-500` 场景 wire 请求数 = `max_retries+1`
  （首 + N 重试）；LLM 失败 → `/stream` SSE error 终帧（HTTP 200，不泄内部细节）。
- **待拍板**：`save_draft`「重试恰一次」幂等语义（LLM 500 后重试成功，save_draft 不写两遍）
  ——涉及 agent 重试编排层行为定义，**本批未实现**，留独立小节决策（见 PR body 待拍板）。

## S3f 非功能收尾批（2026-09-03，#869，T1-T4）

### fake_llm 扩面：/v1/embeddings（T3）

- 端点：`POST /v1/embeddings`（OpenAI 兼容：`object=list`，`data[].embedding`，
  `index` 顺序）；向量 = sha256(model+"\n"+canonical(input)) 循环取 8 字节 → float∈[0,1]，
  确定性幂等；`create_app(dim=8)` 维度可配；`app.state.embedding_requests` 请求记录。
- **🔴 token 形态教训（黑盒 probe 实锤）**：input 必须支持 OpenAI 全三形态
  `str | list[int] | list[list[int]]`——langchain `OpenAIEmbeddings` 默认 len-safe 路径
  发 token 数组而非原文；只收 str 列表 → 真实内核 reindex 400→500（TestClient 直测 fixture
  形态漏检）。确定性向量服务一律补黑盒驱动复验（真实客户端 → 200 + 请求计数>0）。
- 消费面：`e2e-rag-fake.spec.ts`（RAG reindex 成功闭环 → UI fresh + stale=false，
  ADR-048 §S3f）；CI fake 轨默认 8 维零破坏既有 5 端点。
