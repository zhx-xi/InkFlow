# ADR-027: 测试覆盖率门禁 — 三层全覆盖（#104，0.3.1）

> **状态**: ✅ 已接受
> **日期**: 2026-08-06
> **来源**: Issue #104「测试覆盖率补全」（0.3.1 质量加固，milestone #9 最后一个）
> **依据**: 用户拍板验收口径（2026-08-05）——单元行 99%/分支 90%（前后端）、API 端点 100% 有测试、E2E 三页；红线 = 禁止无断言 smoke 测试凑覆盖率
> **替代**: 旧约定「覆盖率 ≥ 70%（AGENTS.md 测试行）」「仅 unit-test job 上报 coverage（ADR-018）」

## 背景

1. 0.2.0 时期覆盖率基线约 91%（实测），但 CI 无覆盖率门禁——coverage 只是上传 codecov 展示，不阻塞合并
2. 用户要求建立**可执行的三层覆盖率护栏**：单元（前后端）、集成（API 端点）、E2E（页面流程），每层有明确验收口径
3. 后端测试规模大（1970+ 用例），单 job 全量跑覆盖率慢；RAG 文件（chromadb）与 coverage 同进程冲突（F14 先例）；Protocol 接口文件方法体（`...`）物理不可执行
4. 前端 vitest 已有 coverage 能力但未配置 thresholds；electron 包此前完全未纳入覆盖率统计

### 统计口径（C 方案，用户拍板）

1. **后端权威口径 = `coverage.xml`**（CI coverage-backend job：unit + 顶层 tests 合并 `--cov-append`，XML 由 `ci_cd/check_coverage.py` 断言行/分支双阈值）
2. **RAG 文件覆盖**：`tests/unit/test_langchain_vector_store.py` 原按 F14 先例 `--ignore`（chromadb C 扩展与 coverage 同进程冲突）——**#273 已取代**：冲突实证修复（#276 hnsw:sync_threshold=3 + chromadb 1.5.9），该测试进 cov 口径，langchain_vector_store 真实覆盖 99%（ci_cd/api-coverage.md 登记更新）
3. **Protocol 接口方法体排除**：`[tool.coverage.report] exclude_lines` 增加 `^\\s*\\.\\.\\.\\s*$`——`domain/ports/` 抽象方法体（`...`）物理不可执行（129 行接口签名永远 0 命中），排除后「行 99%」在数学上可达；errors/模型类（可执行逻辑）不受影响
4. **chromadb 落盘竞态**：`LangChainVectorStore._get_collection` 设置 `hnsw:sync_threshold=3`（写入即落盘，validator 要求 >2）+ RAG 测试 `--reruns 2` 兜底（pytest-rerunfailures 新增 dev dep）
5. **红线**：所有补测带真实断言（状态码/字段/await 调用/输出文案），禁止无断言 smoke 凑覆盖率

### 门禁形态

- **后端**：`coverage-backend` job（needs changes，core/tests/ci 任一变化触发）→ unit + 顶层合并 → `check_coverage.py 98.5 95.0 coverage.xml` 失败即红；coverage.xml 上传 artifact
- **前端**：renderer + electron 包 vitest.config.ts 内嵌 thresholds（行/分支/函数/语句），`coverage-frontend` job 失败即红
- **测试文件行数护栏**：`ci_cd/check_file_length.py 900`（monster-file 禁）防止测试文件无限膨胀（拆分先例：character/timeline/extraction）

### 函数覆盖维度（标准定义，2026-09-01 修订，Issue #869 缺口①）

> **补充定义**：ADR-027 原只到「行 / 分支」。本维度补充**后端函数覆盖**，采用**标准定义「每个函数至少被调用 ≥1 次」**。

**动机**：coverage.py 7.x 的 JSON/HTML `functions` 字段是「函数体语句覆盖率」（一个函数差一行就 <100%），**不是**「该函数被调用过」；表达「每函数被调用≥1次」coverage.py 原生无法报告，需自定义工具。

**机制**（pytest 会话级 trace 插件 + ast diff）：
1. pytest 会话级 `sys.settrace` 收集 `'call'` 事件 → 记录 `(src/inkflow 相对路径, code.co_qualname)`（Python 3.11 `co_qualname` 天然对得上嵌套/类方法名，如 `Class.m.<locals>.inner`）。
2. `ast` 解析 `src/inkflow` 取**全部** `def/async def` 函数（含嵌套/类方法/控制流块内），按与 `co_qualname` 完全一致的算法生成同形键（`FunctionDef/AsyncFunctionDef` 引入 `.<locals>` 作用域、`ClassDef` 引入类前缀、其余控制流节点不改变作用域）→ 与 trace 集合做差集。
3. 输出「未调用函数清单 + 百分比」报告。

**豁免清单**（显式 `ci_cd/func_coverage_exempt.json`；否则 3004 函数硬 100% 数学上不可达——同本 ADR 排 Protocol `...` 先例）：
- `body_is_ellipsis`：body 仅 `...` 的 Protocol 抽象方法体（不计数，AST 层排除）——与本 ADR 排除 Protocol 接口文件 `...` 的 exclude_lines 同理。
- lambda：lambda 表达式不是 `FunctionDef`，天然不在 AST 清单。
- 模式豁免：`__init__` / `__repr__`（魔术方法，测试未必触发）。
- 装饰器 `functools.wraps` 别名（包装函数 co_qualname 指向 wrapper 而非原函数）。
- PyInstaller 打包钩子（仅打包期运行）。
- 仅真实 LLM 触达的编排函数（mock 测试不触发）。

**门禁形态（A 方案，不设硬 100%）**：
- 独立 `function-coverage` CI job（**不 `--cov`**——trace 插件用 `sys.settrace` 与 coverage 的 C tracer 同进程互斥；独立 job 跑全量测试收集 called-set）→ `ci_cd/check_func_coverage.py` 门禁。
- 门禁规则 = **`≥基线−Δ` 且 `0 新增未调用`（豁免清单内除外）**。基线（基线百分比 + 基线未调用集合）固化于 `ci_cd/func_coverage_baseline.json`（S1 首跑建立）；Δ 为容差（默认 1.0%，可配置）。`0 新增未调用` = 当前未调用集合须 ⊆（基线未调用 ∪ 豁免）——新增死函数即红。
- 落地顺序：S1 一次到位交付「报告 + 门禁 + 基线 + 豁免清单」（Phase A 报告 → Phase B 门禁，不拆分）。

**影响**：
- ✅ 函数级「死代码/未用函数」可查（报告 + 门禁）。
- ✅ 新增功能函数若未挂测试 → 门禁红（0 新增未调用）。
- ❗ 新增 `ci_cd/check_func_coverage.py`（gate 脚本）+ `ci_cd/func_cov_plugin.py`（pytest 插件）+ `func_coverage_exempt.json` / `func_coverage_baseline.json` 两个数据文件；独立 `function-coverage` job 不 `--cov` 跑全量，不干扰既有 98.5/95 门禁。
- ❗ trace 插件与 gate 逻辑放 `ci_cd/`（**不进 `src/inkflow`**）——避免其自身成为 `source=["inkflow"]` 覆盖率的被测对象，把既有 98.5% 行门禁拖红。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A: 三层全覆盖 + CI 双 job 门禁（选定）** | 每层可验证、防回归、口径清晰（ADR-027 登记） | 补测工作量 2-3 人天；需拆分超长测试文件 |
| B: 仅上传 codecov 不设门禁 | 零成本 | 覆盖率是展示不是护栏，回归无感知（旧状态） |
| C: 用 `[tool.coverage] fail_under` 内嵌 pyproject | 配置集中 | unit job 只跑 tests/unit/ 会误红——覆盖率必须 unit+顶层合并后判定（CI job 断言更准） |
| D: 不排除 Protocol 接口文件统计 | 口径「全量」 | 行 99% 数学上不可能（129 行 `...` 永 0 命中），目标无法达成 |

## 影响

- ✅ CI 覆盖率门禁常态化：后端 98.5/95.0、前端 99.11/92.51，回归即红
- ✅ API 端点覆盖清单 `ci_cd/api-coverage.md`（97/97）成为 API 层护栏证据
- ✅ E2E 三页流程（项目/写作/Agent 6 用例）覆盖 GUI 关键路径
- ✅ RAG 测试稳定性修复（sync_threshold=3）同时改善生产持久化安全性（崩溃恢复更快）
- ❗ 新增 dev dep pytest-rerunfailures（uv.lock 更新）
- ❗ `AGENTS.md` 测试行由「覆盖率 ≥ 70%」更新为「CI 门槛 98.5/95.0（ADR-027）」
- ❗ 补测后测试文件总数增长约 300 用例，CI 全量时间增加（unit ~2m、顶层 ~1.5m，仍并行）
