# ADR-040: 对话输入机密脱敏（A+B 双兜底）

## 状态

已接受

## 背景

用户可能在 AI 对话（`/api/v1/chat/stream`、`/api/v1/chat/agent/stream`）中粘贴 API 密钥等机密（例：让 AI 帮忙设置模型/密钥时直接贴 key）。当前链路 `chat_stream.py` 把 `prompt` 原样传给 `svc.stream/stream_events` → `HumanMessage` → LLM，**无任何脱敏**。项目现有保护（key_manager 加密落盘、provider_configs 不回显 key、CLI mask_key）都不覆盖「prompt 内明文密钥」这一敞口。本 ADR 决定在发送到 LLM 前做脱敏。

## 决策

采用 **A+B 双兜底**，在 chat 两条流式端点入口对 `prompt` 脱敏后再发 LLM：

- **A（正则兜底）**：识别常见密钥形态（`sk-`、`Authorization: Bearer`、长 token 串）→ `****`。
- **B（已存密钥精确替换）**：与 `APIKeyManager` 联动，把 `keys/` 目录已存密钥明文在 prompt 内做子串替换 → `****`。

落点：`chat_stream.py` 两条端点（`/stream`、`/agent/stream`）。新增 `redact.py` 提供 `redact_secrets(prompt, known_keys)` + `load_known_keys()`。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **A+B（选定）** | 正则兜底未存 key；已存 key 精确命中最可靠 | 需读已存 key 明文入内存（本地单机可接受） | ✅ 采用 |
| 仅 A（正则） | 不需读 key | 未覆盖项目特有/已存 key 形态，漏网 | ❌ 拒绝 |
| 仅 B（已知 key） | 精确 | 漏掉未存的独立密钥（如用户临时贴的非本项目 key） | ❌ 拒绝 |
| 禁止用户输入密钥（强拦截） | 不泄露 | 违背「用户可向 AI 描述密钥」的自主性，体验差 | ❌ 拒绝 |

## 影响

- **更安全**：用户 prompt 内已存/常见密钥不会原样发给模型提供方。
- **透明**：替换为 `****`，用户可感知。
- **不破坏**：不改消息持久化（chat_messages 保留原文本）、不改 SSE 协议、不涉前端。
- **局限**：A 正则无法覆盖所有未知密钥格式（依赖形态识别）；B 仅覆盖「本项目 keys/ 目录已存」的密钥。未来若支持 BYOK/多密钥仍需扩展。
- **可逆**：若未来引入 server-side 加密代理，可移除本层；脱敏函数独立可测。
