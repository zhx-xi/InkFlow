# ADR-023: MCP Server 设计 — 官方 SDK + stdio + 直连领域服务

> **状态**: ✅ 已接受
> **日期**: 2026-08-02
> **风险等级**: 🟡 中
> **依据**: Issue #65（MCP 降级为远期增强，但本地 stdio 版保留）+ specs/p0-11-cloud-protocols/spec.md §3.6（MCPTransport：本地 stdio / 云端 Streamable HTTP）+ design/product-positioning-analysis-2026-08-02.md 旅程 C、§3 #19
> **替代**: 产品定位分析 §1 的「skills 包先行」中隐含的 CLI 封装思路（MCP 工具包装 CLI 子进程的方案否决，理由见备选方案）

## 背景

1. AGENTS.md 三界面规划：CLI（Typer）+ REST API（FastAPI）+ **MCP Server** —— MCP 是第三表现层，从立项即预留
2. F20（1.0.0，ADR-019 v4）：MCP Server **≥15 工具**，供 agent 结构化调用
3. p0-11 spec §3.6 已定义 `MCPTransport` Protocol：本地 = **stdio**，云端 = Streamable HTTP（**后移 P2 评估**，产品定位分析 §3 #19）
4. 约束：遵循 Clean Architecture（ADR-002）—— 表现层直接调 domain services 经 DI（ADR-009），**不经过 REST 层、不包装 CLI 子进程**

## 决策

- **协议与实现**：MCP 行业标准 + **stdio 本地传输** + 官方 Python SDK（`mcp` 包）；工具入参/出参 schema 用 **Pydantic**（ADR-004），与全栈契约同源
- **代码位置**：新增 `src/inkflow/mcp/` 表现层，与 `api/`、`cli/` 同级；工具实现**直接调用 domain services**（DI 注入，ADR-009），不包装 CLI 子进程、不经 REST 层
- **与 CLI 的关系**：与 CLI **共享 service 层，不共享命令树代码**；工具名与 CLI 命令语义**一一对应**（如 `project_create` ↔ `inkflow project create`），保证 agent 心智一致
- **冷启动**：重组件（LLM client / RAG 等）**懒加载**，保证 stdio 会话快速就绪
- **演进**：云端 Streamable HTTP 传输后移（P2 评估）；MCP 发布后为 skills 包（ADR-022）补充 `mcp-setup.md`

## 备选方案

| 选项 | 优点 | 缺点 |
|------|------|------|
| **官方 SDK + 直连领域服务（选定）** | 零多余进程/网络开销；与 CLI 同一 service 层，行为一致性可测；遵循 MCP 标准演进 | 新增 `mcp` 依赖 + 表现层测试（tests/mcp/） |
| 包装 CLI 子进程（subprocess 调 `inkflow ... --json`） | 实现最快、零新代码 | 每次工具调用一次**进程启动**（数百 ms 开销）+ stdout JSON 解析脆弱、错误/流式信息丢失、无法结构化 |
| 经 REST 层转发（MCP → HTTP → API） | 复用 API 契约 | 多一跳网络 + 端口/鉴权依赖；与 CLI 同源却不同路径，行为漂移风险 |

## 影响

- ✅ **≥15 工具**（F20，1.0.0 交付），agent 获得结构化调用与流式输出
- ✅ 与 CLI 共享 service 层：行为一致性有保障，现有 tests/integration、tests/cli/ 资产可复用
- ✅ 官方 SDK 跟随 MCP 标准演进，未来云端 Streamable HTTP（P2）只需换传输层
- ✅ 重组件懒加载保证冷启动体验
- ❗ 新增 `mcp` 依赖与 tests/mcp/ 表现层测试（沿用 ADR-018 测试分层）
- ❗ 工具名与 CLI 命令语义一一对应需长期维护（变更评审时对照 CLI 契约）
