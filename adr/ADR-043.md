# ADR-043: AI 工具面全量注册 + 删除交互授权模型

## 状态

✅ 已接受（阶段① 已实现合入 main；阶段②/③ 待实现，D5 结论：agent 链改删不给 AI）

## 背景

InkFlow 的 AI Agent（chat 系统级 Agent / agentic writer）当前只注册了 **9 个工具**（2026-08-29 源码核实）：

- **只读**（reader_tools.py `_TOOL_SPECS`）：`search_characters` / `check_foreshadowing` / `get_prior_summary` / `audit_chapter` / `count_words`
- **草稿保存**（save_draft_tool.py）：`save_draft`
- **设定库写**（setting_write_tools.py）：`create_character` / `create_world_setting` / `create_outline`

用户要求（#766）把**设定库、记忆、写作、agent 链**相关函数全部注册到 AI 工具，其中**删除默认无权限**，删除需 AI **向用户交互式获取授权**（一次性 / 持久化），持久化 = 现有「全自动」闪电按钮改**分段控件**。

`Tool` / `ToolSpec` 统一模型 + 动态 deps 工厂（`build_reader_tools` / `build_setting_write_tools` / `build_save_draft_tool`）已具备，扩展是**新增工具 spec + 权限守卫**，非新架构。

## 决策

### 1. 工具面分级授权矩阵
所有 AI 工具按「读 / 写 / 删」三态授权。静态注册表为**唯一真相源**；删除类工具默认**不注册**，由授权守卫决定是否挂载。

| 域 | 工具 | 授权 | 状态 |
|---|---|---|---|
| 设定库·角色 | search_characters | 读 | 已有 |
| 设定库·角色 | create_character | 写 | 已有 |
| 设定库·角色 | update_character / delete_character | 写 / 🔒删 | 新增 |
| 设定库·世界观 | create_world_setting / create_outline | 写 | 已有 |
| 设定库·世界观/大纲 | update_* / delete_* | 写 / 🔒删 | 新增 |
| 设定库·地图/时间线/伏笔 | read / create / update / delete | 读/写/🔒删 | 新增 |
| 记忆 | list / add / update | 读/写 | 新增 |
| 记忆 | remove | 🔒删 | 新增 |
| 写作 | generate / continue / revise | 写 | 新增 |
| agent 链 | run / call | 执行 | 新增 |
| agent 链 | 修改 / 删除配置 | — | **❌ 不给**（D5） |

> 🔒 = 默认不注册，需授权守卫放行。

### 2. 删除权限模型（HITL 交互授权）
- **默认无删除权限**：删除类工具初始不注册，AI 无法调用。
- **一次性授权**：AI 发起删除 → 命中守卫 → 触发 HITL 中断（deepagents `__interrupt__`，与书级卷边界 HITL 同机制，复用 #456）→ 暂停等待用户批准/拒绝**本次** → 结果回灌继续。
- **持久化授权**：用户授予「全自动」→ 权限状态域记录 `allow_delete=true`（per-conversation）→ AI 删除不再询问。
- **分段控件**：现有「全自动」闪电按钮改 **手动 / 一次确认 / 全自动** 三态（UI 层，映射到授权状态域）。

### 3. 权限状态域
新增授权状态（per-conversation）：`delete_permission: manual | ask_once | auto`（默认 manual）。工具守卫读该状态决定是否挂载删除工具 / 是否触发 HITL。

### 4. 分阶段
- **阶段①**：读 + 写工具全量注册（设定库/记忆/写作/agent链调用）——低风险，先交付。
- **阶段②**：删除 HITL 授权（一次性 + 分段控件 + 权限状态域）。
- **阶段③**：agent 链调用细调。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 分级授权 + HITL（采纳）** | 安全的删除路径；AI 能做全量；手动权威兜底 | 阶段②实现复杂度（HITL + 状态域） | ✅ |
| **B. 删除全量给 AI（无守卫）** | 实现最简 | 误删设定/记忆风险高 | ❌ |
| **C. AI 完全无删除** | 最安全 | AI 能力残缺，删要人手动 | ⏸ 阶段①过渡 |
| **D. 删除全走持久化（无一次性）** | 状态简单 | 初次授权决策重；无单次释放 | ⏸ 阶段②可扩展 |

## 影响

- **使更容易**：AI 全量操作设定库/记忆/写作；删除通过 HITL 安全放行；分段控件表达授权粒度。
- **使更复杂**：工具注册表 + 权限守卫 + HITL 中断链路；测试需覆盖授权三态与 HITL 暂停/续跑。
- **边界**：agent 链配置（roles/order/relations）**修改/删除不给 AI**——属「元配置」，风险高、语义复杂，只给「执行/调用」。
- **复用**：HITL 中断复用书级边界 HITL（#456）；权限状态域可挂到 conversation 扩展。
- **后续**：工具白名单 per-agent 细粒度；授权状态持久化跨会话。
