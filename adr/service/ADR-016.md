# ADR-016: 日志方案 — loguru 结构化日志

> **状态**: ✅ 已接受
> **日期**: 2026-07-31
> **来源**: design/architecture-analysis-2026-07-30.md §五（可观测性策略）+ 实现代码 `backend/src/inkflow/core/log.py`
> **依据**: Constitution §7.3（可观测性：关键路径全链路日志）

## 背景

系统含 LLM 调用（5-30s）、Agent 管线（多阶段）、RAG 检索等多阶段关键路径，需要统一的日志出口。错误处理（ADR-012）要求基础设施异常可追踪但 API 不泄漏堆栈。

## 决策

使用 **loguru** 作为统一日志库：
- **stderr handler**: 控制台输出，级别 = `config.log_level`，带颜色
- **文件 handler**: `logs/inkflow_{date}.log`，级别 DEBUG，`rotation="1 day"` + `retention="30 days"` + `compression="gz"`
- 日志级别、路径由 `core/config.py`（ADR-008）配置

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| loguru（选定） | 零配置多 handler、rotation/retention 内置、美观格式 | 非标准库，多一个依赖 |
| 标准库 logging | 零依赖 | 样板代码多（handler/formatter/logger 三层） |
| structlog | 结构化事件日志强 | 与 AI 调用链的集成成本高 |

## 影响

- ✅ 一条 `logger.add()` 完成控制台 + 文件双出口
- ✅ rotation/retention 自动管理磁盘
- ✅ LangSmith 追踪（ADR-015）互补：loguru 记录应用层，LangSmith 记录 LLM 调用链
- ❗ 日志文件路径必须基于 `backend/` 解析（**修正记录**：v1 实现用相对路径 `logs/...` 导致落点随 cwd 漂移，见 [Issue #11](https://github.com/zhx-xi/InkFlow/issues/11)，修复后路径固定为 `backend/logs/`）
