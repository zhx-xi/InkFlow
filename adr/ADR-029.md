# ADR-029: F25 daemon 移除 — 伪需求判定 + 意图已覆盖

> **状态**: ✅ 已接受
> **日期**: 2026-08-07
> **风险等级**: 🟢 低
> **依据**: Issue #52 评审（2026-08-07 用户拍板移除）+ PRD v2.1 §2 用户故事 3（AI Agent 通过 MCP 调用）+ ADR-021（本地内核进程多客户端并发）+ ADR-023（MCP stdio 直连）+ ADR-022（skills 包）

## 背景

F25（Issue #52，0.5.0）原 spec 设计为「daemon 后台写作」：常驻进程 + 定时调度（interval/cron）+ 会话状态机联动。评审中发现两个层面的问题：

1. **spec 立项偏离初始意图**：用户初始真实想法 = **外部 AI agent（Hermes/Claude Code 等）通过 MCP/skill 调用 InkFlow 进行写作**（PRD 用户故事 3）——对应「daemon 本地跑」形态，而非 PRD 用户故事 5 的「后台挂机定时写作」
2. **定时自动写作本身是伪需求**（即使按 spec 原意实现）

## 决策

**F25 移除**。真实意图（外部 agent 调用）已被既有规划覆盖，无需新模块：

| 真实意图 | 覆盖方 | 状态 |
|---------|--------|------|
| 本地常驻内核（多客户端并发） | F19 serve（ADR-021：GUI/CLI/skills/MCP 并发访问同一内核） | ✅ 已实现 |
| 外部 agent 结构化调用 | F20 MCP Server（ADR-023：stdio + 官方 SDK + 直连领域服务） | ⏳ 1.0.0 |
| 外部 agent 轻量调用 | ADR-022 skills 包（CLI --json 封装，零常驻） | ⏳ 1.0.0 |
| 调用履历/会话 | F24 会话（Session + SessionLog） | ✅ 已实现 |

**F25 编号不再复用**（避免历史引用歧义）；PRD v2.1 P1-14「daemon 后台写作」条目为历史基线保留不动（历史记录原则），需求判定以本 ADR 为准（后续 PRD 修订时若重排 P1 需求表则同步移除）。

## 为什么定时自动写作是伪需求（评审论证）

| 维度 | 论证 |
|------|------|
| 场景 | 个人作者是「在场创作」生物——无人值守自动生成正式章节无使用场景（生成时用户不在场，上下文/风格/大纲走向无人确认） |
| 哲学冲突 | F27 Writer Agent（#160，0.7.0）已拍板「写工具 = 草稿 + 用户确认」（控制感在用户手里）；F25 自动写正式章节与之直接矛盾 |
| 行业参照 | 主流 AI 写作工具（Sudowrite/NovelAI/Jasper 等）均为交互式（2026-08-07 实测搜索），无「定时无人值守写作」先例；定时批量生成只存在于内容农场/SEO 工具 |
| 已有覆盖 | F3 即时写作 + F24 会话（暂停/恢复/履历）已覆盖全部真实能力 |
| 复杂度守恒 | 调度引擎 + croniter + 状态机联动 + 测试面，为无场景功能付复杂度的成本 |

## 备选方案

| 选项 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **移除（选定）** | 消灭伪需求；意图已覆盖；0.5.0 减负 | 已起草 spec v1.0 作废（无代码投入，仅文档） | ✅ 用户拍板 |
| serve 内 asyncio 调度器（精简版） | 让「定时」变便宜 | 需求本身仍无场景；与 F27 草稿哲学冲突 | ❌ 伪需求不因实现变便宜而变真 |
| 独立 pythonw 进程（原 spec） | 完整 daemon 形态 | 进程生命周期复杂度 + 伪需求 | ❌ 已先被用户「GUI 开着才需要定时」推翻 |
