# ADR-028: E2E 按页面域拆分 + 门禁口径（E2E 增强，0.5.0 起）

> **状态**: ✅ 已接受
> **日期**: 2026-08-06
> **来源**: 用户拍板（2026-08-06，6 项决策）——E2E 增强规划（防 SDD 功能 bug + 防回归，1.0.0 全页面覆盖）
> **依据**: 现状盘点（12 用例覆盖约 30% 交互面）+ 单 job 串行 wall time 推演（40 用例 → 38-45 min）+ #118/#119 实测教训（required check 被跳过 = merge BLOCKED）
> **替代**: 现状单 `e2e-frontend` job 串行（#104 时代 12 用例，第二批按需信息性）

## 背景

1. **覆盖缺口**：当前 `tests/e2e/` 12 用例（smoke 3 + pages 9）仅覆盖约 30% GUI 交互面——设定库全空白、模型管理仅列表渲染、设置模板管理未测、写作工具栏/AI 状态未测、窗口控制/侧边栏折叠未测；目标「1.0.0 全页面按钮可达」约需 40 用例
2. **单 job 时间线恶化**：每个用例独立 launch Electron + 内核冷启动（CI 下约 45s/用例）+ 前置成本 6-9 min（uv sync/pnpm install/build）；40 用例单 job 串行 wall time ≈ 38-45 min，不可接受
3. **回归防线定位**：E2E 是 GUI 层 SDD 回归防线（#106 实测教训：实现改动导致 CI 三连败，E2E 契约是最后防线）；用户要求增强至全页面覆盖
4. **门禁现状**：E2E 属第二批按需 job（paths-filter 触发、红不阻塞 merge）；分支保护 required checks 5 个（lint/unit ×2 + build）

## 决策

### 1. Spec 按页面域拆分（6 文件）

```
tests/e2e/
  e2e-shell.spec.ts      # 壳契约：启动闭环/崩溃拉起/退出回收（3 用例，保持精简）
  e2e-projects.spec.ts   # 项目页：创建/模板创建/删除确认/卡片 + chrome（WindowControls/AppNav 折叠）
  e2e-writing.spec.ts    # 写作页：树 CRUD/编辑器/工具栏（undo/redo/save/AI 按钮状态）/StreamArea/ContextPanel/StatusBar
  e2e-library.spec.ts    # 设定库：项目选择/tabs/列表/空态/retry
  e2e-models.spec.ts     # 模型管理：provider CRUD/模型添加/表单校验/key badge
  e2e-settings.spec.ts   # 设置：模板管理全套/Agent 链/默认模型/快捷键面板/主题
```

### 2. CI 6 job 并行 + 门禁折中（用户拍板 C）

- **e2e-shell 提前第一批恒跑 required**（6 个 required checks：lint-backend/unit-backend/lint-frontend/unit-frontend/build/e2e-shell）
  - 理由：required check 不能按需跳过——`if:` 条件不命中 = skipped = 无报告 = merge BLOCKED（#118/#119 docs-only PR 实测教训）；恒跑是 required 的必要条件
  - 代价：每 PR（含纯后端/docs）多 ~10-15 min runner 分钟（wall time 与其他第一批并行不叠加）
- **e2e-projects/writing/library/models/settings 保持第二批按需**（`frontend/ci` 变更触发，needs 第一批，红不阻塞 merge）
- 实施 E1 时 PATCH 分支保护：required contexts 5 → 6

### 3. AI 生成链路（用户拍板 A）

- 常规 E2E **只测 UI 状态**：按钮可达 → 点击后 loading/错误/空态（确定性断言）
- 真实 LLM 生成走既有 ADR-026 label 触发（`e2e-ai-backend`），不进常规 E2E
- fake LLM provider（确定性短路，可走完整生成流）**登记 1.x.x 优化项**，不进 1.0.0 范围

### 4. 1.0.0 覆盖口径（用户拍板 A）

- **主流程 + 全按钮可达**（约 40 用例）；异常态/边界态（表单校验失败/空态/网络错误）交给单测三层（前端 unit 99.11% 已覆盖）
- #55 发布验收 body 追加「E2E 全页面覆盖」验收条目，引用 E1-E5 完成状态

### 5. 实施节奏（用户拍板 Phase 1 → 0.5.0）

| Issue | 里程碑 | 内容 | 估算 |
|-------|--------|------|------|
| E1 | 0.5.0 | 6 spec 拆分 + e2e-shell 提前第一批 required + 分支保护 PATCH | 2-3 人天 |
| E2 | 0.5.0 | 设定库 + 模型管理 E2E 补全 | 2-3 人天 |
| E3 | 0.6.0 | 设置页 E2E（模板管理/Agent/快捷键） | 2-3 人天 |
| E4 | 1.0.0 前 | 写作页深度（树 CRUD + 工具栏 + AI 按钮状态） | 3-4 人天 |
| E5 | 1.0.0 前 | 项目页 + chrome（WindowControls/AppNav 折叠） | 2 人天 |

### 6. 并行度约束

- Playwright `workers=1` 保持（job 内串行）——内核 DB 落 `frontend/inkflow.db`（spawn 继承 cwd），同 worker 并行会 sqlite 锁冲突
- 跨 job 并行天然安全（不同 runner 不同工作目录）
- job 内并行（DB 路径 env 隔离改造）**登记 1.x.x 优化项**

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A: 6 job 按页面域（选定）** | 失败隔离精准（job 名=页面域）、wall time 最优（~15-18 min vs 38-45 min）、新页面=新 spec+新 job 扩展自然、与现有第二批按需模式一致 | runner 分钟 ~90/PR（现状 ~18，用户接受） |
| B: 3 job 合并（shell+projects / writing / library+models+settings） | runner 分钟约减半 | 最慢 job ~14 用例 wall time 涨到 ~20 min、失败定位粒度粗 |
| C: 矩阵 + 页面级 paths-filter | 变更只跑对应页面 job | 组件跨页面引用多（AppNav/顶栏/Toast），漏触发风险高、维护成本大 |
| D: E2E 全部 required | 全量门禁、回归零逃逸 | 每 PR runner 成本 ×2.5、外部波动（内核冷启动）卡 merge |
| E: e2e-shell 保持第二批按需 required | 无 | **不可行**：required check 被跳过 = BLOCKED（#118/#119 实测），按需 job 无法作 required |
| F: 常规 E2E 走 fake LLM 完整生成流 | 生成链路全闭环 | 内核需新增 fake provider（额外 1-2 天），登记 1.x.x |

## 影响

- ✅ wall time：单 job 38-45 min → 6 job 并行 15-18 min（P1 后最慢 job 即含前置 ~15 min）
- ✅ 失败定位：job 名 = 页面域，红哪个修哪个；e2e-shell required 兜底壳契约回归
- ✅ 1.0.0 全页面覆盖有可执行路径（E1-E5 依赖链 + 里程碑挂载）
- ❗ runner 分钟上升（全量 ~90/PR）；e2e-shell 恒跑使纯后端/docs PR 也跑 Electron 测试
- ❗ required checks 5 → 6（P1 实施时 PATCH 分支保护）
- ❗ E1 需拆现有 spec 文件（12 用例搬家），PR 需同时验证 6 job 拆分后 wall time 对比
- ❗ `AGENTS.md`/`ci.yml` 在 E1 实施后需同步（CI 结构 + 里程碑登记）
