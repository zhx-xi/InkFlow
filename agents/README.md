# 开发 Agent 文档目录

> **给谁看**：给**开发 agent**（Hermes / Codex / 其他 AI 协作会话）阅读的文档。
> **不是**用户文档 —— 用户使用说明在 `docs/`，功能设计在 `specs/`。
> **为什么入库**：模板承载「已踩过的坑」（CI 门禁细节、Windows 陷阱、验证纪律），
> 每次重写必然遗漏 → 统一模板 + 按需填充。

---

## 1 · 目录内容

| 文件 | 角色 | 何时读 |
|---|---|---|
| [`CONVENTION.md`](CONVENTION.md) | **公共约定**（授权边界 / CI 门禁事实 / 停点 / 环境陷阱） | **每个派轨会话必读** |
| [`TASK-TEMPLATE.md`](TASK-TEMPLATE.md) | **单轨任务书模板**（骨架 + 通用节） | 每次派轨前复制 |
| [`KERNEL-CONCURRENCY.md`](KERNEL-CONCURRENCY.md) | 内核并发专题（互斥/复用/实测门禁） | 内核相关轨才读 |

---

## 2 · 用法

1. 复制 [`TASK-TEMPLATE.md`](TASK-TEMPLATE.md) 到 `.hermes/plans/<波次>-<轨>.md`（**gitignored**，`<波次>` 如 `W6-A`）
2. 填充模板内 `<占位>` 处
3. **把填充后的全文贴到新会话**（或让会话读该文件）

⚠️ **所有路径必须写绝对路径**：
```
✅ D:\develop\projects\InkFlow\agents\CONVENTION.md
❌ agents/CONVENTION.md
```
相对路径会导致新会话读不到前置（实测踩过）。

---

## 3 · 分层理由

| 层 | 稳定性 | 内容 |
|---|---|---|
| `CONVENTION.md` | **跨波次稳定** | CI 门禁、授权边界、停点、环境陷阱 |
| `TASK-TEMPLATE.md` | **每轨变化** | 任务骨架（复制后填充） |
| `KERNEL-CONCURRENCY.md` | **领域专题** | 内核并发（按需读） |

混在一起会导致约定漂移（复制时漏改）—— 所以拆开。

---

## 4 · 关键纪律（模板已内建，此处重申）

1. **不写产品代码** —— 派轨会话只做「实现 + 验证 + 提交」，架构决策回主会话
2. **契约先行**（SDD+TDD）—— RED 必须先红，再实现
3. **子代理自报不可信** —— 父侧必须跑 canonical 对拍
4. **不绕过门禁** —— CI 全绿才 merge（`strict: true`）
5. **不猜** —— 遇到未覆盖情形按模板「预判裁定点」的默认决策；命中「重大问题」则停

---

## 5 · 维护

- 新增**跨波次稳定**的约定 → 加到 `CONVENTION.md`
- 新增**领域专题**（如内核/迁移/前端）→ 新建 `<领域>.md` + 在本表登记
- **不要**把具体波次的任务书放进本目录（那些是 `.hermes/plans/` 的临时产物）
