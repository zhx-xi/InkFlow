**背景**: 项目所有者最新三条产品形态决策（见 §0），本报告对其做完整展开分析，供一次性批量拍板。

## 0. 决策输入确认（三条决策的产品化解读）

| 决策 | 原文要点 | 产品化解读 |
|------|---------|-----------|
| 【决策1】单机形态 | 打包后的单机应用是 **GUI 程序**；用户可在 GUI 中使用，或通过 CLI 交互；其他 AI agent（如 Hermes）通过**随程序/源码的 skills 包**使用，后续再考虑 MCP | 单机版 = GUI（主界面）+ CLI（技术/脚本界面）+ skills 包（agent 界面）。**MCP 从「Phase 3 关键路径」降级为「远期增强」**，skills 包先行 |
| 【决策2】Web 归属 | 单机应用**不要 web 页面**；web 页面只给云用户使用 | Web UI 的定位从「本地部署界面」反转成「云端专属界面」；本地界面职责由 pywebview GUI 承接。前端 React 代码**一套两用**（云 Web 部署 + GUI 内嵌加载本地构建产物） |
| 【决策3】云定位 | 云应用 **≠ 多人协作写同一本书**（多人协作是工作室场景，后移到后期）；云应用 = **云存档 + 异地写作替代方案**；用户通过 **web 或 GUI 设置远程连接**后使用云应用；包含单机版绝大部分功能（自定义 skill 等有安全问题的需评估）；云应用 = **用户页面 + 后端管理系统**（后端 + web 管理页面） | 云 = 「单机的远程形态」，不是另一款产品；管理后台从零开始就是正式组成部分；云功能需逐项裁剪评估（§3） |

**总判断**：四形态不是四个并列产品，而是 **「一个 Python 核心引擎 + 两套部署拓扑 + 若干前端界面」**：
- 本地拓扑：GUI 窗口 + CLI + skills 包，数据在用户磁盘（SQLite）
- 云拓扑：Web 用户端 + Web 管理后台，数据在服务端（PostgreSQL），GUI/CLI 可通过远程连接模式指向云端 API

这条主线贯穿 §1-§5 的全部推荐。

## 1. 产品形态矩阵

| 维度 | ① 单机 GUI 应用 | ② CLI + skills 包 | ③ 云 Web 应用（用户端） | ④ 云管理后台 |
|------|----------------|-------------------|------------------------|--------------|
| **目标用户** | 非技术独立创作者（网文作者/同人写手/编剧） | 技术用户、脚本/自动化用户、AI Agent（Hermes/Claude Code 等） | 有多设备/异地写作需求的创作者（同一个人在不同场景） | 部署者/运营者（本项目即用户本人，单人运维） |
| **核心价值主张** | 装好即用、零配置、本地隐私、流畅桌面写作体验、离线可用 | 可脚本化、可编程、结构化 JSON、agent 可完整驱动创作流程 | 云存档不丢稿、异地浏览器即开即写、跨设备续写、单机↔云双向同步 | 用户/存储/用量可视化管理、安全审计、基础运维 |
| **使用场景** | 日常写作、断网/弱网环境、长篇创作主阵地、数据敏感不愿出本机 | 批量生成、自动化审校循环、CI/定时任务、把写作委托给 agent | 出差/办公室写书、临时设备应急、设备丢失/更换后恢复、单机↔云迁移 | 账号管理（禁用/重置密码）、存储配额、异常排查、日志查看 |
| **界面形态** | pywebview 原生窗口（内嵌 React 构建产物） | 终端命令 `inkflow <cmd> --json` | 浏览器 SPA（React 19 + Vite） | 浏览器 SPA（管理端独立路由/独立构建） |
| **数据与后端** | 本地 SQLite + 本地文件 + 免认证（LocalTrust） | 同左（同一本地后端，常驻服务或单命令执行） | 服务端 PostgreSQL + 对象存储 + JWT 认证 | 同左（同一后端，管理员角色） |
| **LLM 成本承担** | 用户自带 Key（BYOK） | 同左 | **BYOK 或平台代付（待拍板 D1，推荐 BYOK）** | 不涉及（仅计量） |
| **开发优先级** | P0（主力形态，1.0 里程碑） | P0（与 GUI 共享后端，成本≈0） | P1（云里程碑） | P1（与用户端同步交付，轻量） |
| **竞品参照** | Manuskript（桌面）+ NovelWriter | —（差异化点） | NovelCrafter / Sudowrite（SaaS） | —（差异化点） |

**形态间关系**（关键架构结论）：
1. ① 和 ② 共享同一本地后端进程，GUI 只是 pywebview 壳；skills 包只是「CLI 命令 + Markdown 指令」的封装，零新增后端。
2. ③ 和 ④ 共享同一云端后端（模块化单体复用），管理后台 = 同一 FastAPI 应用 + admin 路由 + 管理员角色。
3. ①② 与 ③ 通过 **SyncProtocol + REST API** 连接：GUI/CLI 增加「远程模式」（配置 api_base + token 后，读写云端而非本地），这是【决策3】「GUI 设置远程连接后使用云应用」的架构落点。
4. 明确推荐：**四形态全部保留，但投入比例 单机 GUI 60% > 云用户端 25% > CLI/skills 10% > 管理后台 5%**（单人开发，云 MVP 只做最小切片，见 §4）。

## 2. 用户旅程（三条关键路径）

### 旅程 A：本地作者写作旅程（单机 GUI）

```
触发：下载 InkFlow.exe → 双击启动
  → ① 首次启动引导（欢迎页 + 数据目录选择）
  → ② 新建项目（书名/题材/语言/目标字数，≤1 分钟）
  → ③ 模型配置向导（BYOK 填 API Key 或选 Ollama 本地模型，Key 加密落盘）
  → ④ 生成大纲（Agent 链：Architect → Writer）
  → ⑤ 写第一章（Writer，SSE 流式逐 token 渲染）
  → ⑥ 审校循环（Auditor → Reviser，自动修订）
  → ⑦ 本地自动存档（SQLite，无感）
  → ⑧ 关闭/续写（项目列表直接恢复）
```
- **关键体验指标**：安装到完成第一章 ≤ 30 分钟（PRD 成功判据）；首 token ≤ 2s；全程断网可用；数据不出本机。
- **设计要点**：模型配置向导是最大门槛，必须向导化；写作页默认沉浸式（隐藏不常用面板）；软删除 + 回收站兜底误删。

### 旅程 B：异地写作（云存档）旅程

```
触发：用户在办公室电脑打开浏览器 → inkflow 云站
  → ① 登录（邮箱+密码，JWT；新用户注册引导）
  → ② 项目列表（自动拉取昨晚家里写的书，增量同步）
  → ③ 打开项目 → 章节编辑器（Markdown + 字数统计）
  → ④ 续写章节（写作管道上云，SSE 流式；BYOK Key 云端加密存储）
  → ⑤ 自动云存档（每步操作增量 push，rev 递增）
  → ⑥ 回家打开 GUI → 远程模式连接 → 自动 pull 最新版本 → 本地继续写
  → ⑦ 换设备/换电脑：登录即恢复全部项目（云存档 = 不丢稿保险）
```
- **关键体验指标**：登录 ≤ 10s；保存无感（后台增量同步）；单写者场景冲突率 ≈ 0；断网时本地缓冲、恢复后自动补同步。
- **设计要点**：修订历史是云存档的信任基础（误操作可回滚）；设备标识 + 「最后写入胜出（LWW）」+ 修订历史兜底即可，**不需要 CRDT**；单机↔云首次迁移通过「项目导出/导入 zip」完成。

### 旅程 C：AI agent 辅助写作旅程（skills 包）

```
触发：用户对 Hermes 说「帮我把第 5 章写完」
  → ① Hermes 加载 InkFlow skills 包（随程序/源码分发，零安装）
  → ② agent 通过 skills 发现项目结构（project list --json）
  → ③ agent 读取大纲/角色/世界观/伏笔（结构化 JSON 输出）
  → ④ 调用 write 生成章节（CLI 命令封装，流式/整段返回）
  → ⑤ 自动触发审计（audit check --json），按需修订
  → ⑥ 结果写回项目（幂等操作 + 操作留痕，用户可撤销）
  → ⑦ 用户审阅确认（GUI 中可见 agent 写入的草稿，标记为 agent 生成）
```
- **关键体验指标**：工具发现 ≤ 10s；一章生成 ≤ 5 分钟；JSON 输出格式稳定（弱模型下自动重试 ≤ 3 次）。
- **设计要点**：skills 包 = Markdown 使用说明 + CLI 命令封装，**零常驻服务、零依赖**，比 MCP 更早落地；MCP Server 保留为远期增强（结构化工具发现、渐进式发现）；所有 agent 操作支持 `--dry-run`/撤销，避免污染用户数据。

## 3. 云功能裁剪评估（单机功能域 × 上云/不上云/需评估）

评估三维度：**安全**（数据/凭据/执行风险）、**成本**（LLM token 费/算力/存储/运维）、**体验**（云化后是否保值或增值）。裁剪总原则：**「数据类全上、逻辑类全上、凭据类加密上、执行类受限上、开发工具不上」**。

| # | 功能域 | 分类 | 理由（安全/成本/体验） |
|---|--------|------|----------------------|
| 1 | 项目/书籍管理 | ✅ 上云 | 核心数据，云存档第一诉求；无安全风险；成本低；体验增值（多端可见） |
| 2 | 卷/章节管理 + 章节编辑器 | ✅ 上云 | 核心数据；同上；编辑器用 Markdown + 字数统计即可（富文本可后补） |
| 3 | AI 写作管道（生成/续写/修改/格式校验/重试/SSE 流式） | ✅ 上云 | 云的价值核心（异地必须能写）；成本 = LLM token 费，靠 BYOK 转移给用户（D1）；体验必须与单机一致 |
| 4 | Agent 编排（Architect/Writer/Auditor/Reviser 内置链） | ✅ 上云 | 内置角色 = 纯 Prompt 编排，无执行风险；成本同上（BYOK）；体验：异地一键生成大纲/章节 |
| 5 | LLM Provider 配置 / API Key 管理 | ⚠️ 需评估 | **安全敏感**：Key 托管云端 = 平台保管责任（泄露=用户资金损失）。推荐 **BYOK + 服务端 AES 加密 + 用户可随时吊销/更换**；体验上「云端填一次、全设备生效」是增值点。结论倾向：**上云但加密+可吊销**（MVP 即做） |
| 6 | 上下文管理（Token 预算/分层注入/前文摘要） | ✅ 上云 | 纯逻辑 + 数据，无风险、低成本；体验保值 |
| 7 | 角色管理 | ✅ 上云 | 数据类；AI 提取能力随写随建 |
| 8 | 世界观管理 | ✅ 上云 | 数据类 |
| 9 | 大纲管理 | ✅ 上云 | 数据类 + AI 生成（BYOK） |
| 10 | 时间线管理 | ✅ 上云 | 数据类 + 确定性检查（无 LLM，零成本） |
| 11 | 伏笔管理 | ✅ 上云 | 数据类 |
| 12 | 统一提取服务（6 种提取） | ✅ 上云 | LLM 调用（BYOK），逻辑无风险 |
| 13 | 一致性审计（4 维度） | ✅ 上云 | LLM 调用（BYOK）；云端长书审计是高频诉求 |
| 14 | 风格检测 | ✅ 上云 | 同 13 |
| 15 | 会话管理（写作会话/恢复） | ✅ 上云 | 数据类；跨设备恢复会话是异地写作刚需 |
| 16 | daemon 后台写作 | ❌ 不上云（改形态） | **推荐改为「本地 daemon + 云端存档」**：云上常驻定时任务 = 服务端成本 + 用户困惑（谁在跑？）+ 计费失控风险；本地跑、写云端，体验等价且零新增成本 |
| 17 | 自定义 skill（自定义 Agent/Prompt 模板/工具权限） | ⚠️ 需评估 | **安全敏感**：任意 Prompt + 工具权限 = 服务端执行面（RCE/滥用风险）。推荐 **MVP 仅支持「受控模板」（YAML Prompt 模板白名单、无任意工具权限）**；完整自定义 skill 只留单机。结论倾向：**受限上云** |
| 18 | CLI | ❌ 不上云（界面） | CLI 是本地界面形态；云端等价能力由 REST API 提供。但 CLI 需支持 `--remote` 远程模式连接云端（客户端增强，不是云功能） |
| 19 | MCP Server | ❌ 不上云（MVP） | 本地 stdio 版 = 客户端功能（保留）；云端 Streamable HTTP 版 = MCP 协议改造，**P2 后评估**。MVP 阶段云端 REST API 已可满足 agent（skills 包可指向云端 API） |
| 20 | 本地向量库 RAG（Chroma + BGE） | ⚠️ 需评估 | **成本敏感**：embedding 需 GPU/托管 API，服务端持续费用；**安全**：内容送第三方 embedding 服务 = 数据出域。推荐 **MVP 不上**，用「全文搜索 + 结构化上下文注入」替代；P2 评估托管 embedding。结论倾向：**暂不上** |
| 21 | LangSmith 追踪 | ❌ 不上云 | 开发/调试工具（AGENTS 明确默认关闭）；云端用户无需求；追踪数据出域无必要。仅开发期本地启用 |
| 22 | 导出服务（EPUB/MD/TXT/DOCX） | ✅ 上云 | 纯本地逻辑、零 LLM 成本；体验增值（云端下载成品）；P1 交付 |
| 23 | 全文搜索 | ✅ 上云 | PostgreSQL 内置即可，低成本；异地写作查资料/查设定刚需 |
| 24 | 回收站/软删除/修订历史 | ✅ 上云 | 云存档的信任基础，**P0 必须**（误删/误改回滚） |
| 25 | 打包分发（PyInstaller/GUI） | ❌ 不上云 | 纯客户端概念 |

**统计**：上云 17 项 · 不上云 4 项（daemon 改形态、CLI、MCP、LangSmith、打包=5 项）· 需评估 3 项（LLM Key、自定义 skill、RAG）。
**裁剪结论**：云 = 「单机核心引擎的完整数据层 + 内置写作/Agent 管道 + BYOK 计费 + 修订历史」，自定义执行类能力（自定义 skill、RAG）受限或后移。**「云包含单机绝大部分功能」的目标成立，且不会引入失控成本**（BYOK 是成本闸门）。

## 4. MVP 建议：云应用（用户端 + 管理后台）

> MVP 定义：**云存档 + 异地写作闭环**。不追求 23 模块全上，只做「让用户换台电脑能继续写书」的最小完整闭环。裁剪原则：数据类 P0、写作用 P0、工具类 P1、执行类 P2。

### 4.1 云用户端

| 优先级 | 功能 | 说明 / 验收要点 |
|--------|------|----------------|
| **P0** | 账号体系 | 注册/登录/登出/JWT/忘记密码；邮箱验证（可用临时方案） |
| **P0** | 项目云存档 | 项目 CRUD + 章节 CRUD + 增量同步（SyncProtocol 落地：push/pull/rev）+ 修订历史（回滚） |
| **P0** | 章节编辑器 | Markdown 编辑 + 字数统计 + 自动保存（防丢稿） |
| **P0** | LLM 配置（BYOK） | 云端加密存储 API Key + 可吊销；模型选择（OpenAI/DeepSeek/Ollama 兼容/自定义） |
| **P0** | 写作管道 | 生成/续写/修改 + 格式校验重试 + SSE 流式 |
| **P0** | 创作资料 CRUD | 角色/世界观/大纲/时间线/伏笔 的查看与编辑（数据层直接复用） |
| **P0** | 单机↔云桥 | 项目导出/导入 zip；GUI/CLI 远程模式（api_base + token） |
| **P0** | 数据隔离 | 每用户独立命名空间（user_id 过滤即可，无 RBAC） |
| **P1** | 全文搜索 | 跨项目/章节/设定检索 |
| **P1** | 导出服务 | EPUB/Markdown/TXT 云端下载 |
| **P1** | 一致性审计 + 风格检测 | 一键审计报告 |
| **P1** | 统一提取服务 | AI 提取角色/世界观/大纲（增量） |
| **P1** | 会话历史 + 回收站增强 | 写作会话恢复；软删除恢复 |
| **P1** | 本地 daemon + 云端存档 | 挂机写作写入云（本地进程） |
| **P2** | 自定义 skill 受控模板 | YAML Prompt 模板白名单（评估后） |
| **P2** | 只读分享链接 | 给编辑/朋友预览（非协作） |
| **P2** | 云 MCP（Streamable HTTP） | agent 远程调用（评估后） |
| **P2** | RAG 托管评估 | embedding 服务选型 + 成本测算 |

### 4.2 云管理后台

| 优先级 | 功能 | 说明 |
|--------|------|------|
| **P0** | 管理员登录 | 与用户体系同后端、管理员角色标记（避免第二套认证） |
| **P0** | 用户管理 | 列表/搜索/禁用/启用/重置密码 |
| **P0** | 存储与用量看板 | 每用户项目数/章节数/存储体积/最近活跃 |
| **P0** | 基础运维 | 健康检查、服务日志、错误率视图 |
| **P1** | 用量配额 | 存储软上限 + 超限提示（不收费） |
| **P1** | 安全审计日志 | 登录 IP/时间/失败次数/敏感操作 |
| **P1** | 数据备份 | 自动备份策略 + 恢复演练 |
| **P1** | 公告下发 | 维护通知/版本更新 |
| **P2** | 功能开关/灰度 | 按用户比例放量 |
| **P2** | 计费预留接口 | 只留数据模型（用量明细表），不实现付费 |

### 4.3 MVP 上线标准（建议）
1. 用户 A 在电脑 1 写完一章 → 电脑 2 浏览器登录可见、可续写、可回滚。
2. 单机 GUI 远程模式连接云端：本地界面操作云端项目，体验与本地一致。
3. 异地生成一章（BYOK）首 token ≤ 2s，弱模型自动重试不中断。
4. 管理后台可完成：查用户、禁用户、看用量、看日志。
5. 全链路测试覆盖 ≥ 60%（沿用项目 CI 标准）。

## 5. 多人协作后移的影响分析（PRD 设计假设变更清单）

【决策3】将「多人协作写同一本书」从云端首期目标移除，**云端改为个人异地写作**。以下 PRD/规格中的设计假设需要同步修改：

| # | 原设计假设（出处） | 变更后 | 影响动作 |
|---|-------------------|--------|---------|
| 1 | `UserProtocol` 云端实现 = **MultiTenant 多租户**（P0-11 spec §3.4） | 云端 MVP = **多用户单租户**（每用户独立数据空间，互不可见） | 简化：去掉组织/成员/租户模型，仅 user_id 数据隔离；接口签名不变（`tenant_id` 默认即可），实现简化 |
| 2 | `SyncProtocol` 语义 = **多人共享项目同步**（P0-11 spec §3.5） | 语义改为**个人多设备存档同步**（单写者多端） | 冲突模型从「多写者并发」降为「LWW + 修订历史」，**无需 CRDT/OT**；spec 需重写 SyncResult 冲突语义说明 |
| 3 | 云端隐含 **RBAC 权限模型**（协作必然需要 读者/编辑者/所有者） | **无权限模型**，仅数据隔离 | 删除角色/权限/邀请设计；管理后台不做「团队/成员/权限」页面 |
| 4 | 数据模型隐含协作字段（如 Project.members / share 表） | 仅需 `user_id`（owner）外键 | 数据模型保持简单；将来加协作时再迁移 |
| 5 | 用户画像 B「3-10 人工作室」（PRD §3） | 工作室场景从云端第一诉求**降级为远期愿景**；云端定位改写为「异地写作 + 云存档」 | PRD §3 用户画像表需更新；竞品对比话术从「多用户协作」改为「个人创作多端同步 + agent 原生 + 本地隐私」 |
| 6 | Phase 4+「云端部署（PostgreSQL/JWT/CloudSync）+ 多用户协作」捆绑推进（PRD §6.5/P2） | **拆分为两条独立线**：① 云存档/异地写作（提前为独立里程碑）② 多人协作（更靠后，单独立项） | 里程碑/版本路线图重排；建议云端里程碑独立于本地 1.0.0 定义（如 1.1「云存档」、2.0「协作」） |
| 7 | Web UI F18 = **本地部署界面**（PRD §6.3） | Web UI 反转定位为**云端专属界面**；本地由 pywebview GUI 承接 | 前端一套代码两用（云部署 + GUI 内嵌）；「本地 serve + 浏览器」降级为开发模式 |
| 8 | MCP P1-11 = Phase 3 关键交付（PRD §6.4） | **skills 包先行，MCP 后移**（本地 stdio 保留，云端 Streamable HTTP 到 P2+） | P1-11 优先级调整；新增「skills 包」交付物（随程序/源码分发） |
| 9 | Non-goals 第 2 条「不实现云端功能」（PRD §11） | 云端成为正式产品线（云存档 MVP） | Non-goals 更新：改为「不实现多人协作/实时协作编辑（CRDT 维持 Phase 5+）」「不实现付费订阅（仅预留计量接口）」 |
| 10 | GUI/CLI 仅面向本地数据 | GUI/CLI 增加**远程模式**（api_base + token 连接云端） | 架构新增「客户端远程配置」概念；REST 客户端层统一支持本地/远程双目标 |
| 11 | 云端需承担全部 LLM 成本（隐含平台代付） | 明确 **BYOK**（用户自带 Key）为主模式 | 成本模型从「平台承担」改为「用户承担 + 平台托管 Key」；管理后台增加用量计量（为将来收费留数据） |
| 12 | daemon 后台写作 = 本地挂机（PRD 用户故事 5） | 维持本地 daemon；云端不提供常驻任务 | 明确「云端无定时任务」边界，避免云端计费失控 |

**结论**：多人协作后移不是简单砍功能，而是**释放了云端 MVP 的设计复杂度**（去 RBAC、去多写者冲突、去团队模型），使「云存档 + 异地写作」可以在单人开发约束下以最小成本交付。原有 6 个云端 Protocol 全部保留、签名不变，只调整实现语义（MultiTenant→单租户、共享同步→个人同步），**接口投资不浪费**。

## 7. 一页总结（给决策者的浓缩版）

1. **形态**：单机 GUI 是主力（60% 投入），CLI/skills 包零成本附带，云 = 单机远程形态 + 轻量管理后台；四形态共享同一 Python 核心与同一 React 前端。
2. **云的本质**：云存档 + 异地写作，不是 SaaS 全家桶，更不是协作平台。BYOK 是云端成本闸门。
3. **裁剪公式**：数据类全上、逻辑类全上、凭据类加密上、执行类受限上（自定义 skill 白名单）、开发工具不上（LangSmith）、界面不上（CLI/MCP 本地保留）。
4. **MVP 一句话**：换台电脑登录 → 书还在 → 能继续写 → 能回滚 → 管理后台看得见。
5. **协作后移**：不是砍功能，是释放设计复杂度——去 RBAC、去冲突处理、去团队模型，6 个云端 Protocol 接口全部保留、语义简化，投资不浪费。
