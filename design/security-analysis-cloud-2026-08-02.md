## 1. 自定义 Skill 云端化风险评估

### 1.1 威胁模型

InkFlow 的「自定义 skill」对应现有产品形态（F4 自定义 Agent：Prompt 模板 + 模型 + 温度 + 工具权限；Phase 2 用户自定义 DAG；YAML Prompt 模板系统），未来可能扩展为含用户代码的可执行体。云端多租户执行时的威胁清单：

| # | 威胁 | 触发路径 | 影响 | 严重度 |
|---|------|---------|------|--------|
| T1 | 远程代码执行 (RCE) | skill 含任意 Python/Shell 代码，云端进程内执行 | 服务器沦陷 → **全租户数据泄露**、横向渗透 | 🔴 严重 |
| T2 | Prompt 注入 | skill prompt 被恶意构造（「忽略系统指令」类）；小说正文夹带注入指令 | LLM 越权行为、内容外泄给第三方、诱导回显敏感信息 | 🔴 高 |
| T3 | LLM API Key 泄露 | skill 代码读取进程环境/配置文件中的 Key 并外发；注入诱导 LLM 回显 Key | 账单轰炸、账号盗用 | 🔴 高 |
| T4 | 资源滥用 | 死循环、超大输出、无限重试、并发轰炸 | 云端成本飙升、拖垮同租户其他用户（单实例部署下=全站 DoS） | 🟠 中高 |
| T5 | 跨租户数据访问 | skill 读取文件系统/DB 其他租户数据；对象存储路径穿越；越权调用内部 API | 隐私泄露、合规风险 | 🔴 严重 |
| T6 | 供应链 | skill 依赖第三方包/外部 URL 回调 | 恶意依赖、数据外发 | 🟠 中高 |

### 1.2 分级评估

| 分级 | 方案 | 优点 | 缺点 | 裁决 |
|------|------|------|------|------|
| A | 完全不上云（skill 仅本地可用） | 零工程投入、风险归零 | 云端功能缺口大、异地写作体验割裂 | ❌ **否决**（一刀切，产品价值损失不成比例） |
| B | **沙箱化后上云**（方案对比见 1.3） | 保留功能 + 风险可控 | 需工程投入；沙箱存在残余逃逸风险 | ✅ **推荐（默认）** |
| C | 仅个人独享实例上云（每用户独立 VM/容器） | 单租户物理隔离，隔离最彻底 | 每用户一份实例成本；运维复杂；与「成本敏感+个人作者」直接冲突 | ⚠️ 仅作付费增值选项，**不作默认** |

### 1.3 沙箱方案对比

| 方案 | 隔离强度 | 逃逸风险 | 工程成本 | 运维成本 | 单人团队适配性 | 评级 |
|------|---------|---------|---------|---------|---------------|------|
| 容器/Docker（gVisor/Firecracker 级） | 高（内核隔离+系统调用过滤） | 低 | 高（镜像构建链、CVE 跟踪、版本升级） | **高（单人运维噩梦）** | ❌ 差 | **不推荐** |
| 子进程隔离（独立 OS 用户 + rlimit + seccomp + 网络命名空间） | 中 | 中（共享内核） | 中 | 中 | ⚠️ 一般 | 备选，非首选 |
| **纯 Prompt 白名单**（禁止代码执行，skill=prompt+参数） | 结构上消灭 RCE 面 | 无 RCE；仍有注入 | **低** | **低** | ✅ 与产品现状（YAML 模板+Agent 配置）天然契合 | ✅ **首选** |
| **禁止任意代码 + 内置工具白名单**（langgraph 工具调用模型） | 中高 | 低（需审计内置工具实现） | 低-中 | 低 | ✅ 与 langgraph 工具调用天然契合 | ✅ **首选** |

**推荐（D1 裁决）: B 级双轨制**
1. **云上 skill = 「Prompt 模板 + 自定义 Agent 角色 + 内置工具白名单 + 参数化 DAG」，禁止上传/执行任意代码**。用产品设计消灭 T1（RCE）与 T5（跨租户）两大最严重威胁，工程成本最低。
2. **任意代码类 skill（Python 脚本）仅本地运行**，云上标记「本地专用」；同步时只同步配置元数据，**可执行体云端拒收**（SyncProtocol 层拦截，见 §3.3）。
3. Prompt 注入（T2）即使无代码执行仍需缓解：系统提示与用户内容分层注入（不可信内容置于 user 消息并加隔离标记）；结构化输出校验 + 敏感操作（导出/删除/外发）二次确认；skill prompt 静态扫描；云上 skill 运行配 token/次数/并发配额（T4）。

## 2. LLM API Key 管理

### 2.1 方案对比

| 方案 | 说明 | 安全强度 | 成本 | 运维 | 异地写作体验 | 适配度 |
|------|------|---------|------|------|-------------|--------|
| 单机本地加密（现状：AES-256-GCM + 环境变量主密钥） | Key 存本地，本地直连 LLM | 中（依赖本机安全；**存在明文模式**） | 零 | 零 | 不适用（云端写作时 Key 不在云端） | 本地基线 |
| 云端代理（云端持有 Key 代调用） | 用户 Key 上传云端，云端统一调用 | 低-中（Key 集中=单点蜜罐；泄露面=云服务器+DB+日志；信任要求高） | 中（代理流量+服务器） | 中 | 好（云端全自动） | ❌ 非首选 |
| **BYOK 客户端直连**（云端不存 Key、不经手流量） | 写作任务的 LLM 调用在本机发起，云端只存任务定义+结果；用户内容仍按云存档需求上传 | **高（云端零 Key 零泄露面）** | 零（无代理成本） | 零 | 好（异地写作=本机在线，成立） | ✅ **首选** |
| 云端 KMS/Secrets Manager | 云厂商托管密钥 | 高 | 中-高（按密钥/调用计费） | 中 | 好 | 仅当未来必须云端代理时使用 |

### 2.2 推荐（D2 裁决）

1. **云端任何情况下不存储用户 LLM API Key —— P0 红线**。云端不落盘、不进口志、不进异常上报、管理后台不可见明文（只显示「已配置 Provider」，操作仅吊销/重置）。
2. **默认方案 = BYOK 客户端直连**：写作 LLM 调用在用户本机发起，云端只做任务编排与结果存档。理由：a) 云端零 Key、零泄露面；b) 零代理服务器成本（成本敏感直接受益）；c) 顺带规避云端代调用常见的 LLM 出口 IP 封禁/地域限制问题；d) 异地写作场景本机必然在线，成立。
3. **云端代理 + KMS 作为未来付费增值选项**（当出现「纯 Web 免安装」需求时），须满足：KMS 托管 + 全量审计 + Key 脱敏 + 用户可随时吊销，并明示信任模型。**Phase 4 不做，P2 再议**。
4. **本地现状整改（上云前置，本地同样受益）**：现 `APIKeyManager` 存在「secret_key 为空→明文落盘」的开发模式——**云端化后必须废除明文模式**，桌面版默认生成随机主密钥并引导备份；Key 文件权限收紧（Windows ACL / Unix 0600）；日志层对 Key 模式统一脱敏。

## 3. 多租户隔离

### 3.1 数据隔离设计要点（D3 裁决）

| 层 | 方案 | 要点 |
|----|------|------|
| 数据库（PostgreSQL） | **共享 schema + 全局 tenant_id 列 + 仓储层强制过滤 + RLS 纵深防御** | 单人团队选共享 schema（运维最简单）；tenant_id 由 JWT 解出后**单点注入**（Repository 基类强制 `WHERE tenant_id=?`，禁止各处手写）；PostgreSQL Row-Level Security 作为第二道防线（即使 SQL 漏写也拦不住越权行）；每租户独立 schema 留作升级选项（YAGNI） |
| 对象存储（S3 兼容） | key 前缀隔离 `tenants/{tenant_id}/projects/{project_id}/…` | 路径**服务端拼接，永不信任客户端传入的完整 key**（防路径穿越）；预签名 URL 绑定 tenant+前缀+最短时效（≤15min）+最小权限策略 |
| 缓存/会话 | Redis key 前缀 + namespace | 同前缀隔离原则 |
| 备份 | 全量备份加密（对象存储 SSE-KMS 或客户端加密） | 备份含全租户数据，属高价值目标；保留期与恢复演练纳入安全运营 |

### 3.2 租户边界验证（防越权访问，多租户系统头号漏洞）

1. **强制租户上下文**：每个请求从 JWT 解出 tenant_id，服务层统一注入（AuthProtocol → 请求上下文 → 仓储层），单点强制而非逐处手写。
2. **资源 ID 全量归属校验**：`GET /projects/{id}` 等一律校验归属，**越权一律 404**（防枚举探测）。
3. **UUID v4 无顺序 ID**：项目已是 UUID（AGENTS.md 既有决策），天然防遍历，云端继续保持。
4. **预签名 URL 边界**：见 3.1；生成与校验必须服务端完成。
5. **越权测试矩阵为上线前置门槛**：专门的集成测试（租户 A token 访问租户 B 全部资源端点 → 全部 404/403），与业务测试同等 CI 强制。
6. **管理后台 token 与用户 token 完全隔离**：不同 issuer/audience，管理面与用户面不可互认。

### 3.3 SyncProtocol 安全设计要点

现有接口 `push(project_id, payload) / pull(project_id, since)`，云端实现必须补充：

| # | 要点 | 说明 |
|---|------|------|
| S1 | 归属校验 | push/pull 前强制校验 project 属于当前租户（同 3.2） |
| S2 | rev 服务端签发 | `rev` 必须服务端生成与校验，防重放/伪造版本号 |
| S3 | 增量游标防越权 | `since` 之前的记录同样执行可见性校验，防止用旧时间戳枚举历史数据 |
| S4 | payload 校验 | 内容类型白名单 + 大小上限（防超大 payload DoS）；**内嵌 skill 可执行体一律拒收**（呼应 §1.2 红线） |
| S5 | 传输 | 仅 HTTPS/WSS；同步走服务端 API，大文件经预签名 URL 直传对象存储 |
| S6 | 速率限制 | push 频率限制（防滥用写爆存储与账单） |
| S7 | 删除语义 | 云端删除=软删+回收站（与本地一致），避免同步风暴与误删不可恢复 |
| S8 | 审计 | 每次 push/pull 记录：谁、何时、哪个项目、字节量 |

## 4. 管理后台安全

### 4.1 Admin 权限模型（最小 RBAC）

| 角色 | 权限 | 说明 |
|------|------|------|
| super_admin | 全部 | 仅 1 个（用户本人）；**强制 MFA（TOTP）+ 强密码 + 登录 IP 白名单（可选）** |
| support（可选，默认不建） | 只读用户元数据（不含正文内容/Key） | 未来客服场景再说，YAGNI |
| 无中间角色 | — | 单人团队不需要 operator 层 |

要点：管理后台与用户端**不同域名/独立应用**（防 cookie/CSRF 串用）；admin 账号与开发/部署账号分离；不直接用 GitHub 账号登 admin（收窄供应链攻击面）。

### 4.2 审计日志

| 事件类别 | 必须记录 |
|----------|---------|
| 身份 | 登录/登出/失败登录/MFA 变更/密码重置 |
| 数据 | 用户数据导出、删除、恢复、封禁 |
| 管理操作 | admin 任何查看/修改/删除用户数据的操作 |
| 安全 | token 吊销、Key 吊销、设备移除、风控触发 |
| 同步 | 大额/异常同步事件 |

硬性要求：**只追加不可篡改**（独立存储 + admin 无删除权限）；与业务数据分离存储（防删数据时顺手删日志）；保留期 ≥ 90 天 + 归档（成本敏感底线）。

### 4.3 谁能在云端看到用户数据（操作安全）

1. **默认零可见**：管理后台默认只展示聚合指标（用户数、存储用量、配额、异常事件数），不含任何内容。
2. 查看用户**内容**（正文/项目数据）需：super_admin + 二次确认（填写理由）+ 全程审计留痕 + **只读模式**（禁用导出/复制按钮，防拖库）。
3. **绝不展示** LLM API Key（见 §2.2）。
4. 数据导出走留痕流程（单人团队=自己对自己负责，但痕迹必须有）。

## 5. 远程连接安全（GUI→云端）

### 5.1 连接与认证

| # | 项 | 要求 |
|---|----|------|
| C1 | 传输 | 全链路 TLS 1.2+ + HSTS；SSE/MCP 走 WSS；证书自动化（Let's Encrypt，零成本） |
| C2 | 认证 | OAuth 2.1 授权码 + **PKCE**（桌面 GUI 无 client secret 场景必选）；access token 短时效（15-30min）+ refresh token 长时效可吊销 |
| C3 | token 存储 | refresh token 存系统安全存储（Windows Credential Manager / macOS Keychain / Linux secret-tool），**不落配置文件**；服务端 refresh token **哈希存储**（DB 泄露不可直接用）；支持全端吊销（改密/风控时全部失效） |
| C4 | 设备管理 | 每设备独立凭证（device_id+指纹）；用户可在设置页查看已登录设备并远程注销；新设备登录需邮箱验证码（可选「新设备审批」）；设备上限 3-5 台（防滥用） |
| C5 | API 防护 | 速率限制（登录/同步/LLM 调用分桶）；CORS 白名单；请求体大小上限；SSRF 防护（云端不直接接受用户 URL 抓取，导出/搜索若需抓取必须白名单） |
| C6 | **GUI 本地端口防 CSRF（单机版独有新风险）** | 桌面端自带本地 API（127.0.0.1）必须：仅绑定 localhost + 随机端口 + 本地随机 token 校验 + Origin 校验（防浏览器恶意网页跨站调用本地服务）——「GUI+CLI 无 web」形态下这是新增的攻击面，须在本地版就落实 |

## 6. 单机功能上云清单 · 安全视角裁决

分级语义：**P0 = 绝对红线（现在与未来都不上云）**；**P1 = 需工程投入后才可上云**；**P2 = 上云安全但非核心（可后置）**。

### 6.1 裁决表

| 功能 | 云端形态 | 主要风险 | 裁决 | 级别 | 前置工程投入 |
|------|---------|---------|------|------|-------------|
| 项目/章节/卷 CRUD（含回收站） | 云端 DB | 低（隔离做好即可） | ✅ 上云 | P2-核心 | 多租户隔离（§3） |
| AI 写作管道（生成/续写/润色） | 云端编排，LLM 调用走 BYOK | 中（注入面） | ✅ 上云 | P2-核心 | 输入输出校验 + 配额 |
| Agent 编排（内置角色链） | 云端 | 低（内置模板可信） | ✅ 上云 | P2-核心 | 云上内置模板只读、不可被用户改写 |
| 上下文管理 / 本地 RAG | 云端向量库 | 中（创作内容即数据，隐私敏感） | ⚠️ 上云需投入 | P1 | 向量库租户隔离 + 静态加密 + 容量配额 + 隐私条款 |
| **自定义 Agent / Prompt 模板** | 云端 | 中高（注入面） | ⚠️ 白名单化后上云 | P1 | 静态扫描 + 白名单执行（§1.3） |
| **自定义 skill 任意代码** | 云端执行 | **极高（RCE/跨租户/Key 泄露）** | ❌ **绝不上云** | **P0 红线** | —（本地专属，同步拒收可执行体） |
| **LLM API Key** | 云端存储 | 高（凭据集中） | ❌ **云端不存 Key** | **P0 红线** | BYOK 客户端持有（§2） |
| 项目同步（SyncProtocol） | 云端 | 中 | ⚠️ 按 §3.3 设计后上云 | P1 | rev 服务端签发 + 限流 + 审计 |
| MCP Server（Streamable HTTP） | 云端 | 中（工具调用面） | ⚠️ 需投入 | P1 | 工具白名单 + OAuth + 审计（本地 stdio 版先沉淀规范） |
| 导出服务 | 云端生成 | 中（DOCX/EPUB 解析有 zip 炸弹/XXE 面） | ⚠️ 需投入 | P1 | 解析库加固 + 大小/嵌套限制 |
| 全文搜索 | 云端索引 | 低-中 | ✅ 上云 | P2 | 索引租户隔离 |
| daemon 后台写作 | 云端定时任务 | 中（资源消耗） | ✅ 上云 | P2 | 任务配额 + 幂等 + 失败告警 |
| 会话管理 | 云端 | 低 | ✅ 上云 | P2 | — |
| 确定性工具链（时间线/一致性审计/风格检测等无 LLM 或纯分析功能） | 云端 | 低 | ✅ 上云 | P2 | — |
| 管理后台 | 云端 | 高（特权面） | ⚠️ §4 全部落地后上云 | P1 | RBAC + 审计 + MFA + 零可见 |

### 6.2 汇总裁决（供拍板）

1. **云应用 v1 可安全上云**：项目/章节/写作管道（内置 Agent）/上下文/搜索/会话/导出/daemon/确定性工具链——前置条件为 §3 多租户隔离落地。
2. **P0 红线（永不）**：云端执行任意代码；云端存储 LLM API Key。
3. **P1（工程投入后上云）**：自定义 skill（白名单化）、RAG、同步协议安全化、MCP 云端化、导出加固、管理后台。
4. **不做**：多用户协作（已后移，且多人协作会显著放大 §1/§3 的威胁面——后移决策与安全视角一致）。

### 6.3 工程投入排序（P1 优先级）

| 序 | 投入项 | 门禁作用 |
|----|--------|---------|
| 1 | 多租户强制隔离 + 越权测试矩阵 | 云上线前置门槛（§3） |
| 2 | 管理后台 RBAC/MFA + 审计日志 | 特权面可控（§4） |
| 3 | skill 白名单执行 + prompt 静态扫描 | 自定义能力安全上云（§1） |
| 4 | SyncProtocol 安全化（rev 签发、限流、审计） | 同步安全（§3.3） |
| 5 | 导出/文件解析加固 | 消除 zip 炸弹/XXE（§6.1） |
| 6 | 本地版先行整改（废除明文 Key 模式、本地端口防 CSRF） | 本地与云端同基线（§2.2/§5） |

## 7. 附：安全视角对架构决策的补充建议

1. **部署形态**：单机部署（1 台 VM 跑 FastAPI + PostgreSQL 托管服务如 Neon/Supabase 免费层 + S3 兼容存储）即可满足「个人作者 + 成本敏感」，**不做微服务、不做 Kubernetes**（与 ADR-001 模块化单体一致）。
2. **云存档产品的备份即安全**：加密备份 + 定期恢复演练纳入上线 checklist（数据丢失=安全事故）。
3. **隐私与删除权**：个人作者的未出版小说属敏感创作数据；上线前需隐私条款 + 「注销即删」承诺（数据删除流程留痕）。
4. **本报告建议以 ADR 形式落地**（治理规则：决策变更先写 ADR 再改代码），编号建议 ADR-020 起，含 D1-D6 六条决策。
