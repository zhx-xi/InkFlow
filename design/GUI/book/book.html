第四章 · 章标题占位：审计阻断（人设漂移 severity=error），已停止后续章节
现状对照（非方案） 当前实现的三处呈现缺陷：① 章状态 needs_review（#1267 审计阻断）无映射 → 兜底显示「待处理」中性灰，与真实语义相反；② run 状态 blocked 无档位 → 中性灰 + 直接渲染英文原文；③ 失败原因块仅在 failed/degraded 渲染 → 审计阻断原因对用户不可见；④ 本页 无导航入口（AppNav 无 book 项）—— 段 2 已拍板新增「成书」项（见 §3.5-4），故 legacy 之外的形态左侧导航已出现该入口。
方案 A · 侧栏任务列表 任务列表常驻右栏（286px），主区留给运行面板与干预。收益：任务与主区操作可同时可见，与写作页「右栏面板」语言一致。代价：book 页需由单栏改双栏；窄窗口（<1100px）需折叠侧栏。
方案 B · 主区看板（三列） 待处理 / 进行中 / 已完成 三列并置。收益：一眼看到全局分布，最接近「看板」字面。代价：本页章数可达数百（长篇），三列各自滚动后总览价值消失；单卡宽度被压到 ~1/3，章名与角标易截断；需重做行内交互（展开/干预）形态。
方案 C · 单栏任务时间线（推荐） 沿用现状单栏与既有 ExecutionTraceRow 语义：章级行为主，展开看章内步骤（agentic 轨的 write/audit/revise），行内标「当前动作」。收益：改动最小、与既有折叠/密度/干预控件一脉相承，数百章可滚动/分页。代价：无列分布视图（用顶部计数与进度条补足）。
