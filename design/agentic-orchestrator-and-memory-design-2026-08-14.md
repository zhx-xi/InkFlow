## 0. 结论摘要（TL;DR）

1. **定位**：InkFlow 是「学 agent 开发 + 个人自用」项目，**不是商业产品**。上一轮按商业框架（买单/留存/遥测/成本模型/劝退/MVP 验证）给出的 7 条修正全部作废。
2. **「一句话 → 全书」是毕业设计级的 agent 学习载体**：它把 planner-executor、HITL、checkpoint、长上下文、多 agent 状态流串起来，且每个概念都落在已交付的 F26-F42 代码上做增量。
3. **记忆系统必须 AI 总结（两段式：difflib 证据收集 → LLM 语义总结）**，且分两层归属（项目级 + 用户级）。当前 F28 是纯函数（difflib 字面片段），只完成了两段式的前半截。

## 2. 「一句话 → 全书」长任务编排器

### 2.1 已锁定约束（用户拍板，8 条 + 3 拍板）

1. 访谈式 Planner：大纲/主角 = 必须对话确认；配角/细节 = 显式授权后自定（「完成度授权」）
2. 允许中途干预：主面板 = 主 agent 对话/思考/计划/调用子 agent；子 agent 详情 = 次面板/手动点开
3. 多维上限：章节 / token / 会话次数 / 子 agent 调用，**禁止全部设为无上限**（「至少一道有限护栏」不变式）
4. 失败恢复：由用户决定，或用户显式授权主 agent 决定
5. 访谈节奏：分批（题材/体裁/篇幅 → 分卷+主角 → 其余自定），全程可跳过/回改
6. 提问格式：问题可直接复制、修改后作为回复（问题即模板）
7. 「全部你决定」兜底：用户拒绝访谈时完全自主生成
8. checkpoint 默认：卷级「暂停等确认」，章级「只报告」

拍板补充：① 访谈分批（采纳）② 无大纲兜底走显式授权（采纳）③ 卷级暂停/章级只报告默认（采纳）。

### 2.2 架构

```
一句话 ──► [Planner 访谈循环]          产出 WritingPlan（Book→Volume→Chapter 树 + 进度状态机
             │                          pending/in_progress/done/failed/skipped）
             ▼
        [Orchestrator Loop]           逐章/逐卷推进 + 卷级 checkpoint + 跨运行 resume
             ▼
        [Executor]                    复用 F42 管线 + F27 writer agent
             ▼
        [护栏系统]                    多维上限 + 「至少一道有限护栏」
             ▼
        [恢复策略]                    用户决定 ｜ 授权主 agent 决定
```

**数据模型决策**：planner 产出的大纲/角色**直接写现有 `outline` / `character` 实体**（复用 P3+P4 三级结构），`WritingPlan` 只存**编排元数据**（结构树 + 进度 + 产物引用），不重复存内容——打通设定库与 RAG 检索。

### 2.3 关键设计约束（评审提炼的硬约束）

1. **「内容已写」安全阀先行**（半天）：在 `ExecutionStore.create_execution` 前检查「该章已有内容/执行已完成 → 拒绝重跑」。危险的从来不是 InMemorySaver 丢状态，是缺「这章已写」标记——一行 WHERE 拆掉「重复内容 + 双倍费用」。
2. **interrupt 只放卷边界（串行点），绝不放进 Send 并行分支内部**。卷节点内 Send 扇出章执行（无 interrupt）→ 卷节点返回 → 卷边界 interrupt 问用户 → 下一卷。这既是 LangGraph 语义约束，又恰好满足约束 8。
3. **委派形态 = LangGraph Send API 并行 fan-out**（包装现成 F27 writer-agent），**不是** deepagents `task` 工具嵌套（F26 已禁用，且是工具调用语义、无法程序化控制）。
4. **恢复策略树（约束 4 落地）**：章级失败 → 重试 N 次 → 标记 failed 继续（章级只报告）；卷级失败 → interrupt 用户决定或授权主 agent。

### 2.4 学习+实现路线（6-8 周 part-time）

| 阶段 | 目标 | 学到什么 | 工程要点 |
|---|---|---|---|
| **0**（1 天·纯认知） | 把 F42 write_auto 重新定义为「计划写死的 planner-executor」 | workflow vs agent 心智模型 | — |
| **1**（1 周）一句话→一章 | 委托的第一次 | agent 工厂复用 F27、委托契约、最小访谈 | 访谈式 planner（每轮 ≤5 问 +「全部你决定」=跑 F42） |
| **2**（1-2 周）→几章 | 计划成为一等公民 | 计划=数据（outline 三级）、顺序派发、进度状态机、多维上限 | **「内容已写」安全阀 + 章级幂等写** |
| **3**（1-2 周）→一卷 | 两级层级 + 卷级暂停 + 失败恢复 | 层级分解、replan、卷级 HITL 锚点、失败恢复策略树 | **Send map-reduce 扇出章执行 + interrupt 只放卷边界 + F29 护栏复用** |
| **4**（1-2 周）→一本书 | 长跑 + 真检查点 + 中途干预 | InMemorySaver→AsyncSqliteSaver、thread_id、跨重启续跑、后台任务 | **AsyncSqliteSaver + thread_id 落库 + 干预 API** |
| **5**（可选 1 周+） | 打磨 | 并行、token-aware 规划、记忆回写 | 苦工后补 |

### 2.5 学习投资 vs 苦工

- **值得学的复杂度（保留优先）**：checkpoint 持久化、Send map-reduce 委派、交互式规划（访谈）、HITL 状态手术、护栏缩放、预算语义、事件 schema。
- **该绕开的苦工（先能用再修）**：幂等键框架、唯一索引冲突框架、token 精确核算、双面板精致化、访谈分批状态机、三级 agent、章内断点、遥测看板。

### 2.6 自用场景三件核心

1. **观察流三层密度**（表演/仪表/无声，默认全开、可压缩）——主 agent 思考、决策、子 agent 调用轨迹全可见。
2. **检查点 + 随时改 + 效果可见**（暂停/旁路指令/回滚，干预后输出带差异标注）。
3. **回归摘要 + 结构化运行日志**（离开再回来一页说清「到哪了/接下来」，可回放复盘导出）。

## 3. 记忆系统演进（AI 总结 + 两层归属）

### 3.1 现状（F28，2026-08-11 交付，PR #242）

**纯函数（difflib 规则化），零 LLM 调用**：

| 环节 | 手段 |
|---|---|
| 提取「改了什么」 | `difflib.SequenceMatcher` 字面替换片段（pattern→value） |
| 分类 | 正则 + 字符规则（四类：addressing / structure / style_word / other） |
| 聚合 | `(project_id, category, value)` 计数 N≥2 |
| 注入 | 直接拼字面碎片 `AI 已记住：她（林晚）`（最多 10 条，count desc） |

- 两张表：`project_preferences`（绑定 project_id）+ `memory_events`（diff 快照）。
- 开关 `memory_learning`（默认 false，显式开启铁律）。
- **能力边界**：跨会话 ✅ / 跨卷 ✅（project 级天然覆盖）/ **跨项目 ❌（显式隔离，"跨项目不混算"）** / 学习内容 = 字面替换习惯，**无语义风格**。

### 3.2 需求（用户 2026-08-14 明确）

**项目级和跨项目（用户级）的记忆都必须 AI 总结**，否则出现幻觉。

**架构论断**（本轮设计核心）：
- 规则化（difflib 字面片段）**无法安全跨项目**——不理解语义，会把"她→林晚"这类项目特有设定原样搬到别的项目 = 幻觉。这是 F28 当初选择"跨项目不混算"的根因。
- **AI 总结是安全跨项目的前提**——LLM 理解语义，能分离「项目特有设定」（留在项目级）与「用户通用风格」（升到用户级）。

### 3.3 两段式架构（防幻觉双向堵）

```
difflib 证据收集（确定性，零成本）
   ↓  产出「用户反复修改的片段」作为锚点
LLM 语义总结（锚定证据，不自由发挥）
   ↓  产出「抽象偏好」（风格/习惯/称谓规则）
```

- **difflib 负责「找到用户改了哪里」**——确定性证据，防止 LLM 编造偏好（堵幻觉 B）。
- **LLM 负责「理解为什么这样改」**——语义归纳，防止字面碎片注入下游生成被错误套用（堵幻觉 A）。

> 这是原设计「规则化统计**先于** LLM 提取」的完整形态——F28 只落地了前半截（规则化），本阶段补齐后半截（LLM 提取）。

### 3.4 两层归属落地形态

| 层 | 证据来源 | LLM 总结产出 | 注入时机 |
|---|---|---|---|
| **项目级** | 该项目 difflib 片段（N≥2） | 项目风格偏好（称谓规则、结构习惯、文风） | 该项目内每次写作 |
| **用户级（跨项目）** | 多项目 difflib 片段聚合 | 用户通用风格（句长、冗余、叙述/对话比例） | 所有项目的写作 |

**关键**：LLM 总结时显式区分「项目特有设定」（项目级）和「用户通用风格」（用户级）——这个区分本身是 LLM 语义能力才能做的事。

### 3.5 演进拆分（可独立排期）

| 演进项 | 内容 | 学习价值 |
|---|---|---|
| **M1 用户级偏好层** | `user_preferences` 表（全局）+ 归属分层（用户级/项目级）+ 跨项目聚合 | 中（归属语义设计） |
| **M2 语义风格提取（AI 总结）** | difflib 筛片段（锚点）→ LLM 归纳抽象风格 → 注入为「风格指令」而非碎片 | 高（agent 记忆最核心的一课） |

**依赖**：M2 依赖 M1（先有跨项目聚合，LLM 才有跨项目证据可总结）。M2 建议接在编排器阶段 4（长跑）之后、阶段 5（打磨）之前。

## 4. 拍板结论（2026-08-14 用户已确认）

1. **两段式架构**：difflib 证据收集（锚点）+ LLM 语义总结——**保留 difflib 锚点层**（防 LLM 编造偏好，第二种幻觉）✅
2. **记忆演进排期**：M1/M2 **独立于编排器**排期，M2 接编排器阶段 4（长跑）之后——长跑产生的大量修改证据正好喂给 M2 的 difflib 锚点 ✅
3. **恢复策略「授权主 agent 决定」**（约束 4 后半句）：**保留**（区别于上一轮商业框架「恢复人控」的推翻）✅

## 5. 依赖与拆分

- **编排器**：独立里程碑（建议 0.10.0），依赖 F39-F41（Agent 实体 + 能力白名单 + skill 绑定，0.9.0 已排）。
- **记忆演进**：M1/M2 可独立于编排器排期；M2 依赖 M1；M2 与编排器阶段 4/5 有咬合（长跑产生大量修改证据 → 喂给 M2 的 difflib 锚点）。
- **技术事实（工程评审实证）**：F29 checkpointer=InMemorySaver（进程内存）；execution 表无 run 分组、无幂等键、无「内容已落库」标记；outline/character 项目内唯一索引（批量生成易撞 IntegrityError）。
